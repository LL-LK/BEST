# docs/archive/ — 历史归档

本目录放**已归档、不再逐份维护**的历史材料。归档的共同判据：材料本身已收口
（结论不会再变），但**逐条证据链必须留存** —— 下一轮审计要按条目编号回查当时的判据、
实验条件与推翻过程，只留一句结论的话，任何人重跑一遍都未必能得到同样的数字。

## ⚠ 归档实体已退役，只留清单（2026-10-08）

**所有 `*.zip` 实体包都已从版本库移除**，每份对应一份 `*.MANIFEST.md` 清单
（逐文件 sha256 + 包内相对路径 + 隐私标注）。完整登记见 [`RETIRED.md`](RETIRED.md)。

原因：门禁 `verify_archive_privacy` 实测这些包里确有本机信息（本机用户名 63 处、
真实绝对路径 4237 处、邮箱 93 处、1 个 PEM 私钥块），而入库时报告的"隐私扫描全净"
是**错的** —— 扫描判据比要抹的东西窄。用户裁定「取消 git 推送隐私内容，只推送带
占位符和注释的版本」。

**代价**：用户裁定不授权重写历史，故旧提交里的 blob 仍在 git 对象库中，已 clone
过的人仍能取到。彻底清除需 force-push + GitHub 侧删缓存。

## audit-2026-10-06-v1

2026-10-06 那轮五轮（判据审计 + 四轮补漏 + 第五轮变异补盲）产生的 **36 份报告**：
5 轮分片报告、汇总表、根代理亲验实录、已裁定待办清单，以及那份**施工坑单页**。

内容清单见 `audit-2026-10-06-v1.MANIFEST.md`（sha256 + 文件名），**入库就是为了不必解压就能核对**。

当初的打包口径与取舍：

- **只收 `temp/vfy/` 顶层的 `*.md`**。该目录下另有 12 个 `*_clone/` 实验副本，
  每个都躺着一份 277 KB 的本仓 CHANGELOG —— 全收进来体积从 0.6 MB 涨到 11.9 MB，
  而归档的意义是保住**证据链**，不是保住别人的仓库副本。
- **入库而不是仓外自存**。`temp/` 是铁律 3 的临时区（gitignored，可随时整体清理），
  而门禁看不见它（`verify_crossrefs` 的路径白名单不含 `temp`，
  `test_gate_blindspots.py::TestGitTrackingCoverage` 也只管未跟踪的新文件）——
  这正是主登记册 `AK4-001…036` 那 36 个编号在受跟踪文件里**零命中**的原因，
  即「无人回查、无人继承」的成因。仓内已有同类先例：
  `docs/architecture/yz-registry.md` 就是为解掉 30 个 `YZ-NN` 孤儿而建的。

## 怎么用这份归档

报告是** DETECTION-ONLY 产物**：结论以「实测退出码 + 逐字输出」的形式给出，
条目编号（如 `AI5-P0-B`、`AK4-006`）在原始文档之间交叉引用。按编号回查时注意：

- 报告里的**行号会漂移**。任何路径与行号先 `git show <commit>:<file>` 或实跑复核再引用
  —— 这条纪律写在归档内的 `CONSTRUCTION-TRAPS.md` §1，是那份报告自己的第一条结论。
- 报告里的**门禁数量声明已经过期**。它们写作时 `make audit` 被描述成 6/8/9 道不等；
  权威值以 `ops/audit/run_all_gates.py` 的 `HARD_GATES` 为准（当前 12 道），
  `test/unit/meta/test_gate_count_drift.py` 守着声明层与它不得漂移。
- 归档里的多数结论**已被 2026-10-07 那轮修复关闭**（负对照闸、`trust_env` 锁定、
  交叉匹配半径复核、U5 真空满分、E3 盲评死代码）。本包保留的是**当时怎么发现它的**，
  不是「现在还有哪些问题」的清单 —— 后者以 `docs/` 与门禁实跑为准。
