## 2. 章节结构与每节要点

### 摘要
- 问题 → 系统 → 评测体系 → 三条核心发现（E3 组间差异显著 / E6 真实可复现性约 0.80–0.89 / 上游材料缺陷被评测暴露）。

### 1. 引言
- 天文数据服务的 agent 化为何困难：12 张表、无服务端过滤、哨兵值、单位陷阱、无时间序列。
- 现有 agent benchmark 的缺口：多数只测"工具调用对不对"，不测"科学表述是否可追溯"。
- 本文贡献三条：(a) 一个真实系统；(b) 一套六维评测体系；(c) 一批可复用的失败教训。

### 2. 背景与相关工作
- BEST 数据服务：12 张可查表；`std`/`calib`/`other` 是分组不是表；无 `gaia_dr3` 只有 `gaia_dr3_18`；无 ZTF 表、无时间序列。
- LLM agent 工具调用评测现状。
- 与本文的差异：**被测系统、金标准、判定器三者分离 + 反证夹具自证**。

### 3. 系统设计
- 7 原子工具面：`resolve_name` / `list_catalogs` / `describe_catalog` / `cone_search` / `crossmatch_batch` / `count` / `fetch_page`（SSOT：`references/tools.schema.json`）。
- 统一信封 `data/status/cost/provenance`；站点行数据标记 `content_trust=untrusted`。
- 领域知识注入：哨兵 `-1000`/`-999`、`validate_coordinate` 硬抛越界、软 404（HTTP 200 + `{"error":"Not Found"}`）。
- 澄清 / 拒绝 / 停止报告的**四级处置决策表**（A 可确定纠正 / B 可确定拒绝 / C 必须澄清 / D 必须停止报告）。

### 4. 评测方法论（核心贡献章）
六个实验逐个交代**测什么、怎么测、怎么防自证**：
- E1 自然语言→工具调用：六维加权（toolset/param/convert/redundant/clarify/reject）。
- E2 查询结果与金标准一致性：21 场景实连站点；M1–M7 七指标；§4.3.1 七项独立核验（21/21 通过）；M7 传输抖动与真不确定性解耦（传输异常登记豁免，消除随机挂用例）；人工签字机制整链删除，以生成器指纹漂移（provenance_drift=0）披露替代阻断。
- E3 科学语义区分与幻觉抑制：S-A vs S-B 组间对照；SFA/UNGR/UCR/SLR/RQC 五指标 + 人机一致性。
- E4 鲁棒性与安全失败：Tier W（协议层程序判定）与 Tier P（话术层盲评）双层。
- E5 基线与消融：12 装配主表（B0/B1/B2b/B3 基线 + A1–A6 单组件消融含 A6 统一信封 + sham 安慰剂）+ add-back 恢复检验；题库扩展为 56 任务（24 问答 + 23 拒绝诱饵题 + 9 澄清）破除 R 电池方差为 0 地板效应；两段式独立采集流水线与采集资产入库；facts.py 动态现导与 critical 语义关键词职责分离；三通道（D/F/E）可交换性标定；D08 单件归因机制（决策层拦截 vs 工具层报错）与 F 通道 N/A 判据。
- E6 可复现性/效率/可用性：R0/R1/R3 三路；TSC/PAC/RDC/FCC 四一致率；EF1–EF7 + U1–U7。
- **抗自证机制小结**（本节的理论亮点）：反证夹具 metascore 必须 = 1.00、零宽区间标注为"任务间零离散度"、覆盖率显式披露、假设预登记冻结（防 HARKing）。

### 6. 讨论：实践教训（实践论文的重头戏）
- **有效的设计**：反证夹具（六/十/十二件套均 metascore=1.00）、预登记假设冻结、四级处置决策表。
- **无效或存疑的设计**：
