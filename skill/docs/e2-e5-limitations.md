# E2 与 E5 实验不足汇总

> 生成日期：2026-10-09
> 范围：**本地两个实验**（E2 金标准一致性、E5 基线与消融）
> 用途：论文写作前的风险清单；引用任何分数前必读
> 证据口径：全部来自仓内报告、方案文档与代码，逐条标注出处

---

## 零、一句话总览

E2 和 E5 是六个实验里**唯一的本地实跑**（E2/E5 归 `LL-LK` 本机，见 `docs/paper-outline.md` §0.1）。
两者的共同性质是：**证明"判定管线自洽"，不证明"系统能力强"**。
E2 的致命伤是**回放层退役导致逐行 P/R 失守**；E5 的致命伤是**add-back 超限导致全部消融结论降级**。

| 实验 | 报告判定 | 真实结论强度 |
|------|---------|-------------|
| E2 | 17/17 PASS | ⚠️ 只证"真实素材上的判定管线自洽"，**不含**独立人工复核、**不含**全站点取数正确 |
| E5 | PASS | ⚠️ 主表可出，但 **A1–A5 消融结论已降级为「待复核」**，统计检验全部不显著 |

---

## 一、E2 的不足

### 1. 证据强度类（最致命）

**1.1 回放层退役 → 逐行 P/R 与 M7 确定性失守**
- 原文（`evals/groundtruth/REPORT.md` L24-25）：「回放层已于 2026-10-07 整链退役，逐行 P/R 与 M7 确定性随之失守」。
- M1 在 live 下**已改判「行集不变量」**：不再比对金标准行集，只查结果集内部一致性（主键唯一 / 行数不超预算 / 计数自洽 / 截断位诚实），返回字段变为 `n_rows` / `n_keys` / `duplicate_keys` / `violations`（`docs/eval-E2-groundtruth.md` L888-892）。
- **影响**：E2 的"一致性"从「与金标准逐行对上」降级为「自己跟自己自洽」。这是全篇最大的证据强度塌陷，写作时必须如实交代。

**1.2 「金标准经独立人工复核」整链删除**
- 人工签字一族（闸门 `--require-human-review`、`gold/*.review.yaml`、指纹台账、`review/` 工具链）已于 2026-10-04 **整链取消并删除**（`REPORT.md` L11-19）。
- 删除理由：17 份金标准全是**生成器自签**，这道闸门「从未放行过任何一个 case —— 启用即整批恒 FAIL，产出『没通过』而不是证据」。
- **影响**：`pass=true` **不含**独立人工复核这一层。这不是"被跳过"，是"机制已不存在"。

**1.3 只证管线自洽，不证取数正确**
- 原文（`docs/eval-E2-groundtruth.md` L638-642）：「§6 的 M1–M7 分数、§13 的『17/17 PASS』的正确读法是：**真实素材上的判定管线自洽**，**不是**『全站点取数正确』，也**不是**『金标准经人工审核』。」

**1.4 不能证明未抓取过的组合**
- 原文（同上 L627-630）：「**仍不能证明**：Skill 对**尚未抓取过的**天区 / 星表 / 参数组合都正确 —— 31 份实抓快照覆盖的是本轮实际查询过的那批参数，不是全站点。」

### 2. 覆盖与素材类

**2.1 快照库存与消费严重不匹配**
- 库存 41 个 `snapshot.yaml` 目录 / 283 个文件，但 **17 个 case 实际只消费 15 份**（`REPORT.md` L34-37）。
- 明确存在**无消费方**的快照：`std_scr_galah_live`、`ps1_ra286.1_dec15.7_r5as` 等。
- 原文警示：「**在盘上 ≠ 被验证**，引用时须先查有没有 case 消费它。」

**2.2 仍有合成件，且带已知陷阱**
- 全 17 case 里唯一的合成件是 `missing_column` → `syn_missing`（因站点不产生"列不存在"的回包，**有意保留**）。
- 该合成件**缺真零格**（NULL-vs-ZERO 孪生陷阱），建议增补 `class_star=0.0` 行 —— **仍成立**（`REPORT.md` L78-79）。

**2.3 超大查询用例远未达文档字面规模**
- `huge_over_cap` 现取 gaia 快照（落盘 1000 行）+ `max_rows=500` 校准版。
- 文档字面的 **60000 行 / >50000 上限**版本**仍需扩快照**（`REPORT.md` L86-90）。

**2.4 密集场用例未做**
- 改造项状态表（`docs/eval-E2-groundtruth.md` L652）：星团 / M31 那类**天然多值并列**的密集场用例「⏳ 未做」。

**2.5 case 名与素材已脱钩**
- `huge_3700rows` 实际消费 **4003 行**快照（含 3 行分页续抓重复落进数据的表头行）；`single_exact` 实为 1 行；`multi_filter_mag_snr` 实为 5 行（`REPORT.md` L96-99）。
- 案名是换素材前的遗留命名，**实际消费以 `scenarios/*.yaml` 的 `snapshot_id` 为准**。

### 3. 工具与算法类

**3.1 `canonical.id_keys_unique()` 不感知记录类型**
- 它只在检测到重复时降级到 (ra,dec)；对「以对象记录为主 + 少量点源记录」的结果集仍会给 `source_id` 口径（`REPORT.md` L100-102）。属已登记的待改进项。

**3.2 ps1 主键走量化键**
- `ps1` 回包实为**对象记录与点源记录混排**（对象级列与点源级列互斥），`source_id` 在点源记录子集整列为空 → 主键走 `(ra,dec)@9` 量化键（`REPORT.md` L80-85）。

**3.3 服务端分页行序不稳**
- 需 GT 存两份：**集合**（供 M1）与**期望序列**（供 M4）（`docs/eval-E2-groundtruth.md` L1101）。

### 4. 文档与口径类

**4.1 多套数量口径并存**
- 同一实验内并存四种数：**17 个 case**（`REPORT.md` L46）、**21 个场景**（`REPORT.md` L21）、**21 份 gold**（`docs/eval-E2-groundtruth.md` L1130）、**15 条反证夹具**（L1133）。
- 引用时若不注明是哪一套，读者无法核对。

**4.2 REPORT.md 存在重复段落**
- 「已知登记」的第 5、6 条**整段重复出现两次**（`REPORT.md` L86-95 与 L103-112），编号也重复（出现两个 5、两个 6）。

### 5. 顺延与未做

**5.1 在线漂移检测顺延为 E7**（`docs/eval-E2-groundtruth.md` L1105：「E2 **只跑冻结快照**；在线漂移检测单独做 E7」）。
**5.2 live 抓取只在素材采集阶段**，跑批阶段一律回放/离线（L867-875）。

## 二、E5 的不足

### 1. 结论强度类（最致命）

**1.1 add-back 恢复检验超限 → 消融结论全部降级**
- 实测逐 attempt 极差 **0.367**，远超 0.05 容差（`evals/ablation/REPORT.md` L56）。
- 后果（L57）：「**A1–A5 的消融结论降级为『待复核』，不进主表**（采样噪声 > 消融效应时 Δ 不可归因）」。
- **影响**：E5 的核心卖点（"哪个组件贡献多少"）**当前不可用**。表 2.2 的单组件消融行只能作为"待复核"材料。

**1.2 统计检验全部不显著**
- 表 4 中 10 个系统的 McNemar p 全部 `not_reject`（p 从 0.1250 到 1.0000），Holm 判定全为 `not_reject`（`REPORT.md` L67-76）。
- **没有任何一个对照/消融与基线 B3 有统计显著差异。**

**1.3 效力不足，存在漏检风险**
- 原文（L78）：「30 题配对设计下，真实差异 0.85 vs 0.60 时 McNemar 效力约 **0.6–0.7**，存在漏检风险；出现『差异看着大但 p>0.05』时**必须扩到 60 题**再下结论，**不得直接写『两者无差异』**。」
- 而当前**未扩到 60 题**。

**1.4 系统整体表现弱**
- ESR_full 最高仅 **0.200**（B3 / A1），最低 0.000（B0/B1/B2b）（`REPORT.md` L14-24）。
- 这意味着连"完整 Skill"（B3）在 30 题上也只做对 20%。

**1.5 sham 与真消融区分度存疑**
- sham 安慰剂 ΔESR_full = **-0.044**，而真消融 A2 = **-0.033**（L55、L44）。
- sham 掉分**比真消融还多**，报告据此判"掉分来自信息"——但两者量级接近，该结论本身不够硬。

### 2. 指标口径类

**2.1 语义指标是"机器预筛代理指标"**
- 原文（L8）：「表述门与 HR_num/HR_claim 走**机器预筛**（数值可追溯性 + 禁词表 + 哨兵扫描），比 E3 的双专家盲评**弱** —— 语义类指标是**代理指标**，只用于跨系统横向比较，绝对结论以 E3 为准。」

**2.2 无人类复核、不报一致性**
- `review_mode: llm-only (no human reviewer, no kappa)`（L149）；T5 盲评由子代理产出，无 κ/AC1。

**2.3 大量失败无法归因**
- T5 类型总分布：`other×82`、`no_provenance×40`、`hard_execute×19`……（L147）。
- `other` 占 **46%**（82/177），"未归类"占大头 → 归因表对设计的反馈力被削弱。文档自陈：「这本身是有信息量的结果，不是判据失灵」（`docs/eval-E5-baseline-ablation.md` L468-469）。

**2.4 token 全部缺失**
- `tokens_in` / `tokens_out` 全为 `null`（L103-113）；API 未返回 usage，**禁止估算填数**。
- 后果：成本无法折算成金额，T6 成本-边际表只有 `http_requests` 一列可用。

**2.5 边际成本出现荒谬数字**
- `B2b` 的 `Δcost/ΔESR_full` = **-11454.5**（L106）。这是 ΔESR 接近 0 导致的除零放大，数字本身无意义，入表会误导读者。

### 3. 设计与覆盖类

**3.1 drop-two 交互检验未做**（L123：「P5 可选项，预算不足则明确写『未检验交互』」）。
**3.2 四个系统缺结果一致率**：B0/B1/B2a/B2b 的「结果一致率(行集F1)」为 `N/A`（无工具面）（L14-17）。
**3.3 确定性不一致**：报告头 L5 记「确定性（同 items+系统重复跑指纹一致）：**不一致** — 见 runs」。
**3.4 预登记核对栏全部未完成**：表 2.2 的「预登记核对」列五行全为「**待核对**（跑后只核对不改写）」（L43-47）。
**3.5 样本量小**：仅 30 任务；B2a 附录族只 1 次 Holm 校正。

### 4. 文档类

**4.1 表 3 符号写反**
- L56：「极差 **0.367 ≤ 0.05** → ⚠️ 超限」——`0.367 ≤ 0.05` 为假，正确关系是 `0.367 > 0.05`。判定结论（超限）对，但符号写错，读者会困惑。

**4.2 T4/T5 编号曾与代码对不上**
- 2026-10-08 才按代码实况重排为 T1–T7（`docs/eval-E5-baseline-ablation.md` L462-469）；此前文档写「T3 成本表 / T4 统计表 / T5 错误谱系」与实际 `report.py` 生成表不一致。

## 三、E2 与 E5 共通的不足

| # | 共通不足 | 说明 |
|---|---------|------|
| 1 | **性质是"判定管线自洽"，非能力评测** | 两者都不回答"系统在真实用户任务上有多强" |
| 2 | **无人类复核** | E2 签字链已删；E5 是 `llm-only`。两者都缺独立专家这一层 |
| 3 | **报告与数据/代码存在口径漂移** | E2 的 REPORT 落后于 `live-*.json` 与代码；E5 的 T 编号曾对不上 `report.py` |
| 4 | **样本/覆盖面窄** | E2 只 17–21 个场景、15 份快照被消费；E5 只 30 题、单站点单领域 |
| 5 | **依赖机器判定** | 判定器失效只能靠反证夹具（metascore）兜底，无第二人复核 |
| 6 | **外部效度受限** | 单站点（NADC BEST）、单领域（天文星表）、单模型（E5 为 `deepseek-flash`） |

## 四、对论文写作的影响与建议

### 4.1 结论强度必须降级表述

| 不要写 | 应该写 |
|--------|--------|
| 「E2 证明取数正确」 | 「E2 证明真实素材上的判定管线自洽；逐行 P/R 已随回放层退役」 |
| 「E2 金标准经复核」 | 「金标准为生成器自签，人工复核机制已删除，不参与 pass」 |
| 「E5 消融量化了组件贡献」 | 「E5 主表可出；A1–A5 消融因 add-back 超限降级为待复核」 |
| 「E5 各系统无差异」 | 「E5 30 题设计效力 0.6–0.7，未检出显著差异；需扩至 60 题方可下结论」 |

### 4.2 可以正面写的部分

- **E2 的诚实机制**：回放退役后如实降级口径、签字链删除时说明"从未放行过任何 case"、`provenance_drift` 独立披露——这些都是**评测方法论**层面的正面素材。
- **E5 的反证设计**：sham 安慰剂 + add-back 恢复检验 + 预登记假设冻结，这套"自己证伪自己"的设计在实践论文里是加分项，**即使结论是负的**。
- **E5 的失败谱系**：`other` 占 46% 本身说明"大量失败停在表述门层面、无单一组件可归因"，这是有信息量的发现。

### 4.3 建议的补做项（按性价比排序）

1. **E5 扩到 60 题**（文档自己要求）——若预算允许，这是唯一能把消融结论从"待复核"转正的路径。
2. **E2 补密集场用例**（星团 / M31）——已登记 ⏳ 未做。
3. **E2 补 `syn_missing` 的真零格**——消解 NULL-vs-ZERO 陷阱。
4. **E5 修表 3 符号 + 补预登记核对栏**——低成本，纯文档修正。
5. **E2 清理 REPORT.md 的重复段落**——低成本。
