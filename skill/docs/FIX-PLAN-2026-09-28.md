## 2. 修复原则（全 Phase 通用）

1. **fail-closed**: 能确定 inputs 非法时显式抛错, 不猜、不静默降级（对齐 `magnitude_column`/`quality_column` 既有口径）。
2. **单一事实源**: 端点 URL、分页参数、排序列、数据根锚定、URL 校验各只有一个实现, 两客户端共用（规律四的根治法）。
3. **改坏就红**: 每条修复配定向断言（沿用 `test/unit/audit_round/` 惯例）, 突变即红。
4. **中文注释纪律**: 新增/修改的 class/function/method 必须有中文 docstring; import 组有中文说明（`ops/audit/comment_audit.py` 零违规）。
5. **400 净行预算**: 新增逻辑优先落入既有文件; 单文件超限必须登记 `docs/architecture/file-size-budget.md` §3.2。
6. **每 Phase 门禁全绿才提交**: `pytest test -q` + `ruff check .` + `verify_tree_integrity.py` + `count_code_lines.py` + `comment_audit.py`（结构变更 Phase 加 `--write`）。
