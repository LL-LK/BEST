# E2 —— 查询结果与数据库金标准一致性实验方案

> 定位：E2 是**新增的独立实验**，与 `evals/` 既有「行为用例 (cases/) + 探针 (probes.py) +
> 内容审计 (audit/)」并行，**不并入** `evals/scoring-rubric.yaml` 的四维权重（避免权重和被打破）。
> E2 只回答一个问题：**同一个冻结的数据快照上，Skill 交出来的行和数，跟人工审核过的标准答案是不是一模一样。**
>
> 编号说明：本方案的 E2 沿用实验序列命名；本仓 `docs/architecture/` 里的 E1/E2 是**治理债务条目**，
> 与本实验无关，勿混淆。

## 0. 三句话说清 E2 在干什么

1. 把 BEST 站点的一次真实查询**整段冻成快照**（HTML 回包 + 每一页 CSV 原文 + 计数接口回包），以后永远不再联网。
2. 用一支**不许抄被测代码的独立脚本**，从这个快照里算出「标准答案」（应该有哪几行、每格是什么数、按什么顺序、翻几页）——这叫 ground truth，人工抽检签字后锁死。
3. 让 Skill 在快照上跑一遍，把它的输出和标准答案**逐行逐格用程序对账**（不靠"看起来对不对"），7 个指标各算各的分。

## 1. 实验目标与非目标

### 1.1 目标

| 目标 | 说明 |
|------|------|
| G1 行集一致 | 该有的行一行不少，不该有的行一行不多 |
| G2 字段一致 | 同一行的每个字段值完全一致（含类型、单位、精度） |
| G3 语义正确 | 空结果 / 空值 / 零值 / 报错 四种状态不被互相冒充 |
| G4 结构正确 | 排序、分页、截断标志、总数与快照事实一致 |
| G5 版本可溯 | 输出声明的数据版本 == 实际消费的快照版本 |
| G6 判定可信 | 判定器本身经反证夹具自证有效（不会"坏答案也判过"） |

### 1.2 非目标（明确划走，避免实验被稀释）

- ❌ 不测网络健壮性、断点续传（那是既有 probes 的活；注：网络健壮性一度被记为 "E1"，
  该指代已作废——现由 `evals/probes.py` 的 `background_download` / `download_resume`
  场景覆盖, 编号台账以 E6 附录 B 终版裁决为准, 2026-09-28 回改注明）。
- ❌ 不测站点当前数据是否与快照一致（那是**在线漂移检测**，编号 **E7**）。
  ——**2026-10-07 终局**：E2 只剩实跑一条臂，直连真站点，验的是「此刻站点返回的
  东西满足不变量」，仍**不**判「与某份冻结快照一致」——那条判据依旧归 E7。见 §0.0。
- ❌ 不测代码风格 / docstring（那是 `evals/audit/`）。

## 2. 被测对象（SUT）与统一规范化层

Skill 有多个输出面，E2 全部要过同一把尺子，所以先做**规范化**：把任何形态的输出压成
"标准行集"（canonical row set），再拿去对账。

| 面 | 入口 | 输出形态 | 规范化办法 |
|----|------|----------|------------|
| **A 主面：Agent 工具面** | `src.ai_tools.ToolBox(client=...)` | `ToolResult.to_dict()` 统一信封 | 取 `data` 段的行列表 → 标准行集 |
| B 客户端面 | `src.client.BestClient.cone_search / query_standard_stars` | `BestQueryResult` | `sources` 转 dict + 信封字段（total/truncated） |
| C CLI 落盘面 | `python -m src cone ... --output x.csv` | CSV 文件 | 读文件 → 标准行集；另校验表头列名 |
| D TAP 面（可选） | `src.tap` 网关 | CSV/VOTable | 复用 C 的读法；**建议独立成 E8**（TAP 面一致性, 编号台账见 E6 附录 B），本轮可跳过 |

**标准行集定义**（写死在 `evals/groundtruth/canonical.py`）：

```
一行 = { "source_id": str, "ra": float(deg), "dec": float(deg), "<其他字段>": 原值 }
主键 K = source_id；无 source_id 的星表用 (round(ra,9), round(dec,9)) 量化键；
批量匹配场景用 (input_index, source_id) 复合键。

> **2026-10-04 补：主键列的判定是"有列"，不是"列名叫 source_id"**。
> 实现按形态解析：`*_source_id`（裸名与任意星表/表单表前缀都认），
> 外加 stripe82 的 `*_calibstars_id` —— stripe82 的真实主键列是
> `stripe82_calibstars_id`（27/27 非空且唯一），而 `BestSource.from_row`
> 的 ID 别名支路早已认它。不对齐的后果是**两侧不同尺**：
> 产品代码能取到主键、oracle 取不到而退化成坐标，M1 会报出一串
> 看着像"数据对不上"的假失配。
>
> **同时明确一条反例**：`gaia_dr3_18_solution_id` 是**解算批次 ID**
> （实测 1000 行里只有 2 个不同值），字典序又排在 `*_source_id` 之前 ——
> **不得**把裸 `id` / `objid` / `obj_id` 当后缀扫全列。`from_row` 是逐键
> 精确匹配，oracle 是按后缀扫全列，风险面不同，不能照抄它的别名名单。
> 重复 id 会让两行塌成同一主键，M2 拿 A 行的期望值比 B 行的实际值。
>
> 此外主键降级还受两个**结果集层**判据约束（逐行函数看不到集合）：
> `id_keys_unique`（集合内有重复即整批走坐标键）与 `batch_line_offset`
> （服务端 `input_line` 的 1-based/0-based 基准）。

> **为什么必须有规范化层**：同一份数据从信封出来是 float，从 CSV 出来是字符串 `"19.908778"`。
> 不做规范化就会有大量"假不一致"，判定器反而失去可信度。

## 3. 固定快照（Snapshot）规格

### 3.1 快照是什么

快照**不是**"一份结果 CSV"，而是**一整套被冻结的服务端应答**。理由：E2 要测分页、排序、截断、
空结果 vs 软错误，就必须让被测代码真的走完「POST 表单 → 拿 sqlid → 分页 GET」两阶段协议；
如果直接喂结果文件，这些维度全都测不到。

一个快照目录（建议 `evals/groundtruth/snapshots/<snap_id>/`）：

```
snapshot.yaml          # 元数据：catalog / columns / row_count / data_version / 抓取时间 / endpoint / page_size / sort_key
phase1.html            # POST 提交后的 HTML 回包（内含 sqlid 链接，真实原文）
count.json             # getcount 接口回包 {"total": N} 的真实原文
pages/page_0001.csv    # 每一页的**原文**（保留 BOM、保留无表头形态、保留 -999/-1004 哨兵值）
pages/page_0002.csv
...
rows_full.csv          # 全量真值（仅供 GT 生成器读取；被测面永远不读它）
manifest.json          # 目录内所有字节的 sha256 + snapshot_id
```

### 3.2 快照两类来源

| 类 | 含义 | 用途 | 本轮建议数量 |
|----|------|------|--------------|
| **L 类 live-frozen** | 真实抓一次后冻结 | 保证"像真的"：BOM、无表头、哨兵值、列顺序都是真形态 | ≥ 2（`ps1` 一份、`std` 一份；仓内 `best_data/best_ps1_ra286.1_dec15.7_r5arcsec.csv` 可作 L 类素材） |
| **S 类 synthetic** | 按真实协议形态合成 | 覆盖真实站点抓不到的极端：边界值、缺列、超大结果、多对象批量 | 覆盖 8 类场景所需 |

S 类必须**照抄真实形态**：该有 BOM 就有 BOM、该无表头就无表头、缺值就写 `-999`/`-1004.09…` 哨兵，
否则测不出 `src.protocol.parse_csv_rows` 的表头判定与哨兵处理。

### 3.3 回放方式（关键：不联网、可复现）

E2 用**回放 transport** 顶掉 HTTP：

```python
# 人话：造一个假的"网卡"，让它不去访问网站，而是从快照目录里把当年存下来的回包原样递给被测代码。
class SnapshotTransport:
    def __init__(self, snap_dir): ...        # 记住快照目录
    def get(self, url, **kw):                # 顶替 requests.Session.get
        # 1) url 里带 getcount → 返回 count.json 的原文
        # 2) 否则按 url 里的 page=N 取 pages/page_00NN.csv 的原文
        # 3) 每次调用计数 +1（用来核对 cost.http_requests 是不是诚实上报）
        return FakeResponse(status_code=200, text=原文)
    def post(self, url, **kw): return FakeResponse(200, phase1.html原文)   # 顶替 POST 提交表单
```

接线方式（沿用 `evals/probe_support.py` 已确立的桩策略，不引入新机制）：

```python
client = BestClient(base_url="http://snapshot.local", rate_limit=0.0)  # rate_limit 归零，否则 100 页要睡 200 秒
client.session.get  = transport.get     # 把网卡换成快照
client.session.post = transport.post
tool = ToolBox(client=client)           # ToolBox 本来就接受注入 client（src/ai_tools.py:260）
```

> **坑位（实测确认）**：`BestClient.__init__` 默认 `rate_limit=2.0`，回放 100 页会真睡 200 秒；
> 且 `session.mount` 的重试适配器在假响应上不生效（无妨，但要保证 FakeResponse 有 `raise_for_status()`）。
> 回放模式下必须显式 `rate_limit=0.0`，并在报告里注明"离线回放不计礼貌延迟"。

## 4. 金标准（Ground Truth）生成：人工审核脚本

### 4.1 铁律：独立 oracle（最重要的一条）

GT 生成器**严禁 import** 被测的判定逻辑：`src/query_builder.py`、`src/client.py`、`src/protocol.py`、
`src/crossmatch.py`、`src/core/source_postprocess.py`。
锥搜角距、筛选谓词、排序、分页切片**全部自己用 `math` 写一遍**。

> 为什么：如果 GT 抄了被测代码的算法，那么被测代码的一个 bug 会被 GT 原样复制，
> 两边"完美吻合"，实验**静默失效**。这是此类一致性实验最经典的翻车点。
> 配套守卫：加一条 CI/测试断言，静态扫描 GT 脚本的 import 白名单（`math/json/csv/pathlib/hashlib`）。

### 4.2 GT 产物结构（`evals/groundtruth/gold/<case_id>.json`）

### 4.3 人工审核脚本（**整链已于 2026-10-04 裁定取消并删除，本节仅存历史记录**）

> ⚠️ **现状**：本节描述的「人工抽检签字」机制**已全部取消并从仓内删除** ——
> `--require-human-review` 闸门、签字单联（`gold/<case_id>.review.yaml`）、
> 指纹台账（`gold/manifest.json`）、汇总表与回填工具链（`evals/groundtruth/review/`）
> 连同 gold 内的 `review` 段，**都不复存在**。下方文字保留只为记录"放弃过什么"，
> 不得当作现行流程引用。

脚本全自动产出候选 GT，原设计要求**过人工抽检签字**才准进判定（fail-closed：
未签字 → 该 case 直接 FAIL，不许"默认通过"）。脚本同时吐出一张**审核清单**
（`gold/<case_id>.review.yaml`，**已删除**），把要人看的证据摆出来：

- 抽样行的计算过程：`输入坐标 → 我算的角距 d=? ″ → 半径 60″ → 判进/判出`；
- 边界前后各 3 行、末行、极值行（最亮/最暗/最大角距）必抽；
- 所有哨兵值行（`-999` / `-1004.09…`）必抽；
- 分页边界行（第 N 页最后一行与第 N+1 页第一行）必抽。

抽检比例建议（**该规则本身仍在用** —— 它同时是 M2 逐格期望值的取样口径）：

| 行数 | 抽检 |
|------|------|
| ≤ 50 | 全审 |
| 51–1000 | 20%，且必含上述必抽项 |
| > 1000 | 2%，且必含上述必抽项 |

### 4.3.1 人工填表与回填（两段式：人填表 → AI 回填）

### 4.3.1 自动化独立核验（2026-10-03 取代原「人工填表 + 回填」两段式）

> **本节替换原设计。** 原方案要求人填一张 17 行的 CSV（`items_checked` /
> `must_sample_ok` / `state_confirmed` / `verdict` / `reviewer` / `reviewed_at`），
> 再由脚本回填。**该设计已作废**，理由是核验实测给出的三条事实：
>
> 1. **它签的东西本身不值得签** —— §4.6 的双路核验查明：17 份里 **16 份是合成素材**，
>    唯一那份真实快照还掺了 1 颗人造星。给合成数据盖「人工已审」的章，
>    并不提升可信度，只是把「结论不可外推」藏进四个字。
> 2. **「A 类 3 份非人不可」是错的** —— 本轮实测 `validate_search_radius(0)` 抛
>    `ValueError: Search radius must be positive, got 0`（对照：`-1` 同抛、
>    `18000` 通过、`18001` 抛 too large）。
>    **「半径 0 该记什么」不是科学语义判断，是 `guards.py` 行为的镜像** ——
>    guards 抛什么，gold 就该记什么。这条判据完全可程序化。
> 3. **人填的是是非题，而答案就在代码里** —— 几何、行集、排序、截断、状态机
>    全部是**确定性函数**，独立重算一遍即可，不需要人称���。

**新流程（三段，全部脚本，零人工）**：

| 段 | 谁做 | 做什么 | 入口 |
|----|------|--------|------|
| **① 生成** | 脚本 | `gen_gold.py` 用独立 oracle 产 17→21 份金标准 | `python evals/groundtruth/gold/gen_gold.py` |
| **② 核验** | 脚本 | **不复用生成器的算法**，独立重算下表 7 项判据，逐份出 `PASS`/`FAIL` | `--require-independent-verify` |
| **③ 放行** | 闸门 | 7 项全过 + 零红线才 `exit 0`；任一不过即阻断并点名是哪一份哪一项 | 缺省关闭，显式打开才当放行条件 |

**七项核验判据**（每项都必须是**重算**，不是重读生成器的结论）：

| # | 判据 | 怎么算 | 挡的是什么 |
|---|------|--------|-----------|
| 1 | **几何自洽** | 自写 haversine 逐行算角距，`gold 行集 == 半径内行集` | 半径/单位算错、wrap 漏处理 |
| 2 | **排序** | 按 `ordering.key` 复核单调性 + 期望序列逐项相等 | 排序键错、`tie-break` 不确定 |
| 3 | **分页无损** | 重算 `page_hashes`，比对 `pagination.pages` | 翻页丢行/重复/漏页 |
| 4 | **截断三元组** | `total ≥ returned`、`truncated` 与二者自洽、`max_rows` 截断点正确 | S1 静默截断（最危险的一类） |
| 5 | **状态裁决** | `result_state == f(回包形态)`，非法参数**调 `guards.py` 取真实异常** | 四态混淆（空/零/无结果/报错） |
| 6 | **血缘双向** | gold 的 `snapshot_id` ↔ 快照 manifest ↔ 场景引用三者交集非空 | 拿错快照、血缘漂移 |
| 7 | **独立 oracle** | 静态扫描 GT 生成器的 import 白名单（禁 `src.*`） | GT 抄被测代码（同源漂移） |

> 第 7 项**已经实装**：`gold/guard_no_src_imports.py`，是 §10 阻断项的执行者。
> **第 1–6 项已于 2026-10-08 固化落地**（新增功能经批准）：实现为
> `evals/groundtruth/verify_independent.py`，与 `gen_gold.py` **各写一份算法**
> （haversine / 主键 / 页指纹 / 截断算术全部独立重算，刻意不 import `gold.*`），
> 入口 `python evals/groundtruth/verify_independent.py`，或跑批时加
> `--require-independent-verify`（全过才放行）。实测 **21/21 PASS**。
> 对不适用项（error 态无行集 / ordering 未声明 / 素材已退役）一律记 **N/A**，
> 不得记 PASS —— 把"没验"报成"验过"是铁律 5 禁的 fail-open。

**原工具链的去向**：`evals/groundtruth/review/`（`gen_review_sheet.py` /
`backfill_reviews.py` / `HUMAN_REVIEW_SHEET.csv`）与 `--require-human-review` 闸门
**已整体删除**（2026-10-04，见 §4.3.0）。删除理由：它们绑的是「谁来签」，
而 §4.6 已证明真正要防的东西（几何/行集/截断/状态）**与签字人是谁无关**，

### 4.4.1 为什么不再需要「第二人签字人」这个角色

> **原问题**：签字人必须是「第二人，非 `gen_gold.py` 作者」，
> 但方案从未定义「第二人」从哪来；若只有一位自然人可签字且正是作者，
> 约束在物理上无法满足 —— **唯一现在就能推进的实验反而成了唯一推不动的**。
>
> **本轮结论：该角色整体取消。** 三条依据：
>
> 1. **独立性的正确载体是「算法不复用」，不是「签字人不是作者」。**
>    §4.1 的独立 oracle 铁律（GT 严禁 import `src.*`，由 `guard_no_src_imports.py` 静态执行）
>    才是防同源漂移的真正屏障；**签字人换个人并不能防住 GT 抄被测代码** ——
>    那需要的是 import 白名单，不是第二双眼睛。
> 2. **签字能挡的东西，自动化核验全能挡，且更严。** 七项判据（§4.3.1）逐条
>    对应人工原本要确认的事：几何/行集/排序/分页/截断/状态机/血缘。
>    人工只能抽样（§4.4 原表：12 份小 case 27 行 + 2 份只看锚点），
>    自动化是**全量重算** —— 覆盖面严格更大，且可复现、可 diff、可在每次跑批时重跑。
> 3. **审计工具链已删除**：`review/` 目录与其测试、签字单联、指纹台账、
>    签字指引均于 2026-10-04 连同 `--require-human-review` 闸门一并移除。
>    需要人工审计时属**新增功能**，须重新走批准（铁律 4）。

### 4.4.2 `REJECT` 之后的返工闭环（**已随签字链作废**）

   │
   ▼
重新出表 → 重新签这一份 → --apply（其余 14 份已签的不必重签）
   │
   ▼
gen_review_sheet.py --write 会重算 gold_answer_sha256：
   修过的份指纹变了，未修的 14 份指纹不变 → 只需重签改动过的那几份
```

> **这条闭环是 §4.3 指纹机制的自然推论**：因为台账绑的是 `gold_answer_sha256`，
> 「改了哪几份」是机器能自动算出来的，所以**返工不需要重签全表**。
> 这一点原文没写，但它把「驳回一次」的代价从「重签全部」降到「重签 1 份」。
> **改造到 21 份后这条价值更大** —— 份数越多，指纹机制省下的返工成本越明显。

### 5.1 「参数漏填」为什么必须新立一类（不是 #7 的替代品）

> **2026-10-03 裁决：两者都要。** 二者测的是**不同层次**，缺一不可：

| | #7 缺失字段（数据侧） | #7b 参数漏填（新增） |
|---|---|---|
| 出错位置 | **数据回来之后**，某格是空的/是哨兵 | **数据还没发出去**，查询本身就构不完整 |
| 被测代码该做的 | 清洗：标 null、剔哨兵、不得填 0 | **拦截**：不构造非法查询、或明确要求补全 |
| 失败长什么样 | 静默错值（S1，最危险） | 报 `E_INVALID_INPUT` / 走澄清 |
| 现有覆盖 | ✅ 3 条（`syn_missing`） | ❌ **0 条** |

**用例设计与判据**：

| case_id | 漏填什么 | 期望 `result_state` | 判据 |
|---------|---------|------------------|------|
| `missing_arg_catalog` | 不传 `catalog` | `clarify` 或 `error` | 不得默认某张表就发请求；`error_code` 必为 `E_INVALID_INPUT` 或走澄清，**不得静默挑表** |
| `missing_arg_coords` | 只传 `radius` 不传 `ra`/`dec` | `error` | 不得用 (0,0) 之类的默认坐标发请求 |
| `missing_arg_radius` | 传 `ra`/`dec` 但省略 `radius_arcsec` | `clarify` 或 `error` | **不得**默默套一个默认半径——半径默认值是静默错数据的最短路径 |

> **为什么这三条不能靠 #7 顶替**：#7 的输入永远是**结构完整的合法查询**，
> 脏在数据里；#7b 的输入是**非法查询**。`src/scripts/guards.py` 的
> `validate_coordinate` / `validate_search_radius` 是这三条的执行者，
> 而它们**当前没有任何 E2 用例覆盖** —— 这是 E2 的一个真实盲区。
> 三条都归 `state_only` 审计模式（无行可抽），**属于 A 类不可替代人工签字**。

### 5.2 「超大查询」为什么不是「送星表」（硬事实 + 裁决）

> **2026-10-03 核查：`references/tools.schema.json` 的 7 个原子工具里没有 upload 工具。**
> `resolve_name` / `list_catalogs` / `describe_catalog` / `cone_search` /
> `crossmatch_batch` / `count` / `fetch_page` —— 没有任何一个接收星表**文件**。
> `starcatalog` 属 `astro-catalog-query` skill（Astropy 侧）的能力，**不在 BEST 工具面内**。
> 所以「送星表进去」若理解为上传 `.cat`/`.csv` 文件，**在 E2 的被测面上不可实现**。

**裁决（用户已定）：用 `crossmatch_batch` 送 1000+ 个坐标。**

| 用例 | 构造 | 考点 | 主判指标 |
|------|------|------|----------|
| `huge_3700rows`（**保留**） | `cone_search` r=18000″（5°）取 3700 行 | 分页 >3 页、并集无重无漏 | M4 M1 M7 |

> `src/scripts/guards.py` 的合法域是 `-90 ≤ dec ≤ 90`（**闭区间**），

## 6. 指标体系与确定性判定算法

记号：SUT 规范化结果为 `R`，金标准为 `G`，主键集合 `K(R)/K(G)`。

### M1 行集 precision / recall（权重 0.30）

> ⚠️ **live 下改判「行集不变量」（2026-10-07 起）**：下面这套 P/R 是**回放口径**，
> 已随回放臂一并退役。现行 live 口径只查结果集内部一致性（主键唯一 / 行数不超预算 /
> 计数自洽 / 截断位诚实），返回值字段为 `n_rows` / `n_keys` / `duplicate_keys` /
> `violations`。本节保留为 replay 口径的历史记录与设计依据。见 §0.0 与
> `metrics/m1_rows._live_invariants`。

```
TP = |K(R) ∩ K(G)|      FP = |K(R) \ K(G)|      FN = |K(G) \ K(R)|
precision = TP / (TP + FP)      recall = TP / (TP + FN)      F1 = 2PR/(P+R)
```
- 分母为 0 时约定值 1.0，并单独打 `degenerate` 标记（防止"GT 是空的、SUT 也是空的"被当成满分而掩盖问题——
  这类 case 必须由 M5 的 result_state 再判一次）。
- **判定阈值**：`precision == 1.0 且 recall == 1.0` 才 pass。数据查询不接受"差不多"。
  （批量匹配场景如确有服务端近似语义，可在用例里显式下调到 0.99 并写明理由，默认不降。）
- 失败明细要打印：多出来的是哪几个 key、少了哪几个 key（前 20 条）。

### M2 字段值完全一致率（权重 0.25）

只对 TP 行逐字段比，先判语义类别再比值：

```
类别不符（GT 说 null、SUT 给 0；GT 说零值、SUT 给 null） → 直接记不一致，不做数值比较
数值字段：|a - b| ≤ atol + rtol * |b|  （容差来自 GT 的 field_values，不外置硬编码）
字符串/ID：strip + 去零填充 + 大小写归一后精确相等
```
容差基准（写进 GT，不在判定器里硬编码）：

| 字段族 | atol | rtol |
|--------|------|------|
| ra / dec (deg) | 1e-9 | 0 |
| 星等 (mag) | 1e-6 | 0 |
| 角距 (arcsec) | 1e-6 | 0 |
| snr / flags / count | 1e-9（整数要求精确相等） | 0 |
| 字符串 / ID | 精确相等 | — |

```
字段一致率 = 1 − 不一致字段数 / 应比对字段数
```
报告按**字段**聚合（哪个字段错得最多，一眼看出是列错位还是单位错）。

### M3 单位与精度正确率（权重 0.10）

两道独立检查，缺一不可：

- **(a) 单位**：输出/契约声明的 `unit` 与 GT `unit_map` 逐字段一致（deg / arcsec / mag / mas / count）。
- **(b) 量纲探针**（防"声明对了但数值错了"）：
  坐标必须落在 `[0,360)` / `[-90,90]`；角距不得为负；星等落在物理合理区间；
  若某坐标被当成 arcsec 输出（×3600）会立刻越界 → 判单位错。
  半径单位混淆（arcsec 当 deg 传）则由 **M1 行集膨胀**捕获，两处交叉印证。
- **(c) 精度**：用 `decimal.Decimal` 统计有效位数，GT `precision_map` 给每字段下限
  （ra/dec ≥ 9 位有效；星等 ≥ 6；snr ≥ 4）。
  **降精度**（`19.908778205841614` 截成 `19.91`）判错；**假精度**（整数补 `.000000`）不判错但记 warn。

```
单位正确率 = 单位正确字段数 / 检查字段数
精度正确率 = 达标字段数 / 检查字段数
```

### M4 排序 / 分页 / 截断正确率（权重 0.15）

三项各自 pass/fail，汇总 `pass 数 / 3`：

- **排序**：序列按 sort key 单调（升/降）；同 key 用主键做次级比较（避免"单调但同值内乱序"）。
  SUT 若声明了不同的排序键，必须写在 provenance 里且与输出自洽，否则 FAIL。
- **分页**：各页并集 == GT 行集（无损）；页两两交集 == ∅（无重）；`page_size` 与页数符合预期；
  末页判据正确（不提前停、也不多翻）。
- **截断**：三元组 `(truncated, total_count, returned_count)` 与 GT 完全一致，任一错即该项 fail。
  其中 `total_count` 必须优先取服务端 `getcount` 值（这是 `src/client.py:462` 已修过的历史 bug，E2 要钉死）。

### M5 空值 / 零值 / 无结果区分正确率（权重 0.10）

四态混淆矩阵：`{EMPTY_RESULT, NULL_FIELD, ZERO_VALUE, ERROR}`，对角线 / 总数 = 区分正确率。

| 状态 | 正确表现 | 典型错误（要抓的） |
|------|----------|--------------------|
| EMPTY 无结果 | `success=true ∧ rows=0 ∧ error 空 ∧ total_count=0 ∧ truncated=false` | 把"服务端会话死了"报成"天上没源" |
| NULL 空值 | 显式 `null`/`None` 或按 `null_sentinel.yaml` 的哨兵，**不参与数值运算** | 把 `-999` 当真值算均值；把空值显示成 `0` |
| ZERO 零值 | 真实 `0.0` / `0` 必须原样输出 | 把真零当成缺失丢掉 |
| ERROR 报错 | `success=false + error_code`，**绝不降级为空结果** | 软错误页被当空结果（历史 bug，必须复发一次验证已修） |

> **阻断项**：任何一次 `ERROR → EMPTY` 的混淆，**整体 E2 直接 FAIL**（这不是扣分问题，是把服务故障读成科学结论）。

### M6 数据版本一致率（权重 0.05）

输出 provenance / 信封必须携带三项，逐字比对：`snapshot_id`（或 `data_version`）、`catalog`、`endpoint`。
离线回放时时间戳应**引用快照抓取时间**（而不是"现在"），否则每次跑都对不上。

```
版本一致率 = 一致子项 / 3
```
外加**跨版本污染检测**：拿 A 版本快照跑却声明 B 版本 → FAIL（阻断）。

### M7 确定性与计数诚实率（权重 0.05，附加）

> **⚠️ 2026-10-10 更正（本节前一版与实现相反, 已作废）**：2026-10-07 版写
> 「live 下『确定性』已降级为『请求可解释性』… `data_hash` 全等**不再是判据**」。
> **这与实现相反** —— `metrics/m7_determinism.py::score_m7` 一直据 `data_hash` 判确定性,
> 且正是它让实跑批**每轮随机挂一个不同的 case**。本轮把口径**对齐到实现**, 并补上缺失的域闸。

- **确定性（现行口径）**：同场景 repeat 次（默认 3）行集指纹 `data_hash` **全等 → 1.0**。
  该判据**保留**（它能抓真缺陷：跨轮丢行、重复落行、隐藏随机、集合无序）。
  实测站点在 3 轮窗口内是**稳的**：4 个代表 case（`huge_3700rows` 4000 行 /

  该轮会拿到空行集、指纹必然与其余轮不同 —— 那是**网络天气, 不是被测代码的随机性**，
  故确定性分项记 **N/A**（不进分母）, 并把轮次写进

  **站点回了 HTTP 响应再报出的契约错误不在此列**, 照旧判确定性（不许被这道闸洗掉）。
  同源先例：同在 `score_m7` 内的 `http_requests_honest` 早在 2026-10-08 就因
  "别把网络天气记在被测代码账上"加了 ERROR 态域闸, 确定性半边当时漏了。
  实测证据：两轮全量跑批分别挂在 `huge_3700rows` 与 `boundary_maxrows`（**换 case 挂**=瞬态）,

  补闸后本批 **21/21 PASS**（`n_cases=21, n_pass=21, metascore=1.0, 独立核验 21/21`）。
- `cost.http_requests` 是否等于「实际翻页数 + 计数 + 提交」的**客户端层请求数**（防虚报成本）。
  口径以 `references/tools.schema.json` 为准：该字段在 `Session.request` 出口计数，
  **不含 urllib3 适配器层重试**（429/5xx 抖动下服务端收 3 次而本字段报 1），

| M1 | M2 | M3 | M4 | M5 | M6 | M7 |
|----|----|----|----|----|----|----|
| 0.30 | 0.25 | 0.10 | 0.15 | 0.10 | 0.05 | 0.05 |

`pass_score = 0.90`，`warn_line = 0.85`（与 `evals/scoring-rubric.yaml` 现有口径对齐）。
**加权分不得覆盖阻断项**：阻断项任一命中，无论总分多少，E2 判 FAIL。

> **权重标着「建议值」，说明它与 E6 的标定问题不同，要分清**：
> - **E2 的 M1–M7 是逐指标独立可读的**（M1 召回、M2 字段全等、M5 四态区分…），
>   每个指标都有明确的物理含义与容差来源，**不依赖任何未标定的绝对阈值**。
>   所以权重没正式裁决，**不影响单指标结论**，只影响「加权总分」这一个合成数怎么读。
>   报 E2 结果时**优先报七个分指标**，加权分只作概览 —— 这样权重是否最终裁决就不重要了。
> - **E6 的 E/U 面则相反**：EF/U 指标本身就建立在未标定阈值上（E6 §8.1.1），
>   **单指标也不可信**，所以那里必须先标定才能报数。
>
> **判据**：指标本身无绝对阈值 → 权重待定无害；指标本身依赖阈值 → 权重待定是掩盖，
> 必须先标定。E2 属前者，E6 的 E/U 面属后者。

## 7. 判定分层：程序判定 vs 模型评分

| 层 | 判什么 | 怎么判 | 是否可信为硬结论 |
|----|--------|--------|------------------|
| **L0 程序判定** | M1–M7 全部数值/结构指标 | 纯 Python 计算，容差来自 GT 与外部 YAML | ✅ 是，fail-closed |
| **L1 配置规则** | 字段容差表、单位表、精度表、哨兵字典 | YAML 外置，改数值不改代码 | ✅ 是 |
| **L2 模型/专家评分** | **仅限自然语言解释**：无结果时给的解释对不对、报错提示是否可操作、有没有把错误说成"没数据" | 5 点制 rubric（正确性/可操作性/无幻觉/与 L0 结论一致性），评委 = 1 个模型 + 人工抽 20%（**E3 §8.1 档 B 的仓内先例**） | ⚠️ 否，仅供参考，占比 ≤ 10% |

**硬约束**：L2 分数**不得**用于翻转任何 L0 的失败结论。数值字段一律 L0，绝不进 L2。

## 8. 反证夹具：判定器必须自证有效

沿用本仓 `evals/` 已确立的纪律（每个审计器配 broken 坏样本）：**每个判定器都要配一个"已知坏答案"，
它必须报 FAIL；它要是报 PASS，说明判定器是摆设 → 该判定器 FAIL → E2 总评 FAIL。**

| 判定器 | 注入的坏样本 | 必须命中的指标项 |
|--------|--------------|------------------|
| M1 行集 | 删一行（recall↓）；多塞一行（precision↓） | `recall` / `precision` |
| M2 字段值 | 某字段改 1 位小数；把 `-999` 换成 `0` | `field_mismatch` / `null_semantics` |
| M3 单位精度 | 坐标 ×3600（单位错）；星等截 2 位（精度错） | `unit` / `precision` |
| M4 排序分页截断 | 交换两行（排序）；复制一页（分页重复）；`truncated` 取反 | `ordering` / `pagination` / `truncation` |
| M5 语义 | 空结果用例注入软错误 body 却仍报空 | `state_confusion(ERROR→EMPTY)` |
| M6 版本 | provenance 写错 `snapshot_id` | `version_mismatch` |

报告里单列 `metascore = 通过的反证夹具 / 全部反证夹具`，**metascore < 1.0 → E2 FAIL**。
