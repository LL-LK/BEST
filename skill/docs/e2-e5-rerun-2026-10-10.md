# E2 / E5 重跑与方案优化记录 (2026-10-10)

> 依据: `docs/e2-e5-limitations.md` 的不足清单
> 口径: **E2 仅作对照** (不追加用例、不升级证据强度); **不留人工** (凡"待人核对/待人工复核"
> 的项一律改为机器判定或明确关闭)
> 纪律: 门禁只报不改; 判定口径的每一处变更都给出"为什么旧口径在**这个臂上**不成立"的证据

---

## 一、结论速览

| 实验 | 重跑前 | 重跑后 | 性质 |
|------|--------|--------|------|
| E2 | 20/21 PASS=false | **21/21 PASS (exit 0)** | 判据域闸补全 → 恢复绿 |
| E5 | PASS (mode=live) | **FAIL** — `capture_attempts_non_exchangeable` | 原先的绿是**假绿**: 采集侧前提不成立却无人判定 |

两处都不是"把红的改成绿"或"把绿的改成红", 而是**归因修正**:

* E2 的红原本记在被测代码账上, 实际是**传输层瞬断**;
* E5 的绿原本掩盖了**采集侧轮次污染**, 该缺陷此前不可见。

## 二、E2 (仅作对照)

### 2.1 复现与定位

`make eval-e2` 连跑两轮, `n_pass` 稳定为 20/21、`metascore=1.0`、
`independent_verify` 21/21 全过, 但 `pass=false` —— **每轮挂的 case 不同**:

| 轮次 | 挂掉的 case | 阻断项 |
|------|------------|--------|
| 第 1 轮 | `huge_3700rows` | `m7_determinism:determinism_or_count_dishonest` |
| 第 2 轮 | `boundary_maxrows` | 同上 |

两轮 stderr 均见对 `ps1/q` 的 POST 被 `RemoteDisconnected` 打断
(POST 按铁律 7 (a) **不重试**, 故这是设计内的不可恢复点)。

**换 case 挂** = 瞬态, 不是固定缺陷。

### 2.2 排除"行数据漂移"

专项探针 (`temp/e2_m7_probe.py`, 4 个 case × 3 轮实跑, **全部轮次成功**):

| case | n_rows | 有序指纹 | 无序指纹 | 主键集 |
|------|--------|---------|---------|--------|
| `huge_3700rows` | 4000×3 | 全等 | 全等 | 全等 |
| `boundary_maxrows` | 174×3 | 全等 | 全等 | 全等 |
| `huge_over_cap` | 500×3 | 全等 | 全等 | 全等 |
| `multi_filter_mag_snr` | 5×3 | 全等 | 全等 | 全等 |

行数据本身**不漂**。故 M7 的指纹差异只能来自"某一轮被传输层打断后拿到空行集"。

### 2.3 修法 (域闸, 对称于既有先例)

`score_m7` 里 `http_requests_honest` 早在 2026-10-08 就因"别把网络天气记在被测代码账上"
加了 ERROR 态域闸, **确定性半边当时漏了**。本次补上:

* `run_e2._is_transport_error()`: 按**异常类名**认传输层失败 (连接/超时/读断);
  站点给了 HTTP 响应再报的契约错误**不在此列**, 照旧判确定性;
* `run_scenario` 逐轮记 `repeat_states`;
* 只要有一轮属传输层失败 → 确定性分项记 **N/A** (不进分母), 并把轮次写进
  `transport_error_repeats` / `determinism_domain` 披露。

**不是 fail-open**: 负对照测试钉住"无瞬断时指纹漂移必须照旧判红",
且传输层分类器有独立负对照 (HTTPError / E_INVALID_INPUT 不得被判成传输层)。

### 2.4 结果

修复后重跑: **21/21 PASS, exit 0, metascore=1.0, 独立核验 21/21**。

### 2.5 对照定位 (不追加投入)

按"E2 仅作对照"的裁定, `docs/e2-e5-limitations.md` §4.3 列的 E2 补做项
(补密集场用例 / 补 `syn_missing` 真零格 / 扩 `huge_over_cap` 快照)
**一律关闭为"不适用"**, 不再作为待办 —— 对照臂的职责是提供一个可比基线, 不是刷强证据。

## 三、E5

### 3.1 复现与定位

原报告的两处症状 —— 表 3 的「add-back 极差 0.367 > 0.05」与报告头的「确定性不一致」——
经逐 run 拆解后指向**同一个根因**, 且**不是**原报告写的"采样噪声过大"。

同一批采集表 (`temp/capture_live.json`), B3 三轮:

| attempt | 平均答案长度 | 已陈述 critical 占比 | 平均工具调用数 | E 门通过率 |
|---------|-------------|---------------------|---------------|-----------|
| 1 | 122.0 | 0.578 | 0.69 | 0.533 |
| 2 | 91.8 | 0.501 | 0.69 | 0.233 |
| 3 | 86.6 | 0.498 | 0.68 | 0.233 |

**决策没变 (route 230/230/229、工具调用几乎逐字相同), 只有正文变短了。**

逐系统看 attempt 1 是否**严格最高** (E 门口径):

```
A1 0.533/0.233/0.200 ✓   A2 0.433/0.233/0.233 ✓   A3 0.200/0.133/0.167 ✓
A4 0.500/0.200/0.200 ✓   A5 0.433/0.200/0.167 ✓   B3 0.533/0.233/0.233 ✓
sham 0.433/0.167/0.200 ✓
B0 0.000/0.000/0.000 ✗(全等, 无信息)   B1 同   B2b 同   B2a 0.033/0.033/0.033 ✗(同上)
```

排掉 4 个三轮**全等**的系统 (它们既不能支持也不能否证可交换性) 后,
**7 个有信息量的系统里 attempt 1 全部严格最高**, 零假设下概率 `(1/3)^7 ≈ 4.6e-4`。

**结论: 三次"重复"不是同一系统的独立样本** —— 这是**采集侧的轮次污染**。

### 3.2 为什么它废掉的比"采样噪声"更多

repeat=3 的一切重复统计都以"三次是独立样本"为前提:

* add-back「极差 > 0.05」→ 前提不成立时, 极差是**结构性的**, 任何容差都判不过;
* T4 的「逐题三次多数票」→ 非可交换重复的多数票**有偏**, 且偏向 attempt 1;
* §8 的「极差 > 0.05 标不稳定」→ 标出的是采集缺陷, 不是任务难度。

### 3.3 修法

1. **新增机器闸 `exchangeability_check`** (采集侧, 只对 live 臂):
   分母取"三轮不全等"的有信息量系统; 覆盖面 ≥80% 且 `p < 0.01` 即判
   `capture_attempts_non_exchangeable`, 并**明确标注这是采集侧缺陷、非被测系统失败**。
   替身批三轮逐字相同 → 计数为 0 → 恒判可交换, 不会误报。
2. **critical 断言加表示归一** (`metrics/assertions.py`): 裸子串命中只在"答案是渲染层
   按模板产出的原文"时成立 (替身臂成立, live 臂不成立)。现实测到的表示差异:
   「共 3 个源」被判缺 `"3 行"`、「未截断」被判缺 `"truncated=false"`、
   「不等于『非变星』」被判缺 `"不等于非变星"` (只是插入了引号)。
   归一**只动表示、不补事实**: 未给 `best://ps1/cone`、未给 `BEST_SIM_0001`、
   未提 18.20 / 17.55 / 12 次的一律**继续判缺** (负对照测试钉住)。
   语义近义 (如 `不支持` ≡ `做不了`) **不猜** —— 由断言显式声明 `{any_of: [...]}`。
   归一 / 严格**两套读数都进报告**: 两者之差即表述层脆性的量化。
3. **禁答仍走裸子串** (`forbidden` 不归一): 它测的是"说了不该说的话", 给近义开口子
   等于让话术逃逸 (既有测试 `test_gate_e_forbidden_hit` 钉住这条)。
4. **预登记核对改机器对账** (`metrics/prereg.py`): 表 2.2 的「预登记核对」栏原先五行
   恒为 `待核对 (跑后只核对不改写)` —— 那等于把**核对**留给人, 而没人执行时这一栏永远
   是"待核对", 读者会误以为假设没验。现由机器按冻结的 `prediction` 判
   命中 / 未命中 / 反向 / 不可机析, **只读 `hypotheses.yaml`, 逐字不改写** (防 HARKing)。
5. **表 3 关系符修正** (生成器层): 原实现恒印 `≤`, 于是超限那行写成
   「极差 0.367 ≤ 0.05 → ⚠️ 超限」—— 判定对而关系符是假的。现按实测方向印。

### 3.4 结果

表 2.2 的预登记栏已由机器填出: `A1=反向 A2=反向 A3=反向 A4=未命中 A5=未命中`,
四级基线 `DELTA1/2/2b=未命中, DELTA3=命中`; 表 3 关系符已正确
(`极差 0.333 > 0.05 → ⚠️ 超限`)。

放行判定由 **PASS 转为 FAIL**, 阻断项即上述采集侧缺陷 —— 这是**披露真相**,
不是回归: 原先的 PASS 建立在"三次重复可交换"这个未经验证的前提上。

## 四、遗留与边界 (如实登记)

1. **E5 消融结论仍不可用**, 但理由已从"采样噪声"更正为"采集侧轮次不可交换"。
   要转正只有一条路: **重采一份真正独立的 attempt** (子代理并行独立作答,
   不得由前一次改写而来)。本次未做 (990 run 量级, 超出本轮预算)。
2. **E5 扩到 60 题** 未做 —— 它同样依赖有效采集; 在采集前提修好之前扩题只会放大偏差。
3. **E5 T5 仍为 `llm-only`, 无 κ/AC1**: 该项**无法**机器补齐 (机器算不出人机一致性),
   故按"不留人工"记为**明确关闭 + 披露**, 不留成待办。
4. **两处门禁在 HEAD 上就是红的** (本次以 HEAD 的 git worktree 实测证实, 非本次引入):
