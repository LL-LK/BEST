## 0. 一分钟速用

```
① 你要按位置找星？        → 锥搜 (pos.type=cone)，但先查第 5 节的表陷阱
② 你要按名字找星？        → 站点不解算，**做不到**（用坐标）
③ 你有一批坐标？          → proximity 批量，回包带 inputobjs_* 回连列
④ 你要一次取很多行？      → 必须走两阶段 + 分页；先 getcount 再按 page_size 取
⑤ 你拿到数据先看什么？    → 先判状态（空/错/软 404），再判哨兵，最后才看数值
```

**三条最容易把人带沟里的**（详情见 §11）：

1. **表单页 200 ≠ 这张表有数据**。`jplus_dr3` / `landolt` 回 200 + 完整表单页，`getcount` 恒 0。
2. **`uss_dr1` 的锥搜会静默丢弃位置约束**，回一屏锥外的合法行且 `total` 是全表数。
3. **`ps1` 的回包是两种记录混排**，用错主键口径会让 M1 全量假失配。

## 1. 能力边界（先说不能做什么）

| 想做的事 | 能不能 | 说明 |
|---|---|---|
| 按坐标锥搜 / 盒式搜 | ✅ | 两阶段协议，见 §4 |
| 按坐标批量邻近匹配（proximity） | ✅ | 需登录，见 §3 |
| **按天体名查星** | ❌ | 站点**没有**名称解算端点；用户给名字要先转坐标 |
| **按 `source_id` 查星** | ❌ | 无 by-id 端点 |
| **测光变 / 求周期** | ❌ | BEST 是**单历元静态表**；g/r/i/z/y 是五个波段的五个数，不是五个时刻 |
| **判定变星** | ❌ | 不产出变星判定；空标志**不等于**「已判定为否」 |
| 下载整表 | ⚠ | 需登录，且有下载配额 |

> 用户拿一个 Gaia `source_id` 问「是不是变星」时：**先说能力边界 + 给替代路径**，
> **不得**编造 by-id 端点，**不得**给周期/振幅。

## 4. 两阶段协议：最容易踩的五件事

### 4.1 流程

```
POST /{catalog}/q   （表单含 csrf token + pos.* 字段）
   → 200 + HTML，里面藏着一个 sqlid
GET  /sqlid/{sqlid}/getcount
   → {"total": N}
GET  /sqlid/{sqlid}?output.fmt=csv&rows=1000&page=1
   → 带 BOM 的 CSV（表头 + 数据行）
```

### 4.2 五个坑

1. **`output.fmt` 有分岔**：只有 HTML 的 phase-1 回包里才藏着 sqlid；CSV 请求走的是
   另一条路径。混用会拿不到 sqlid。
2. **手搓表单会静默退化成全表查询**：表单的**几何键共 7 个**（`csrfmiddlewaretoken` /
   `output.fmt` / `pos_group` / `pos.type` / `pos.racenter` / `pos.deccenter` /
   `pos.radius`）。少发几何键，服务端**不报错**，直接回全表 —— 这是最贵的一个坑，
   因为它看起来是成功的。
3. **`sqlid` 会过期**。会话失效时报 `E_NO_SQLID`（稳定错误码，真源在 `src/protocol.py`），
   必须**重走 phase-1**，不能重试旧的 sqlid。
4. **不要重试 POST**。重试会造孤儿会话、泄漏服务端配额。
5. **必须串行 + 强制间隔**（本仓实跑纪律：≥1.5s）。对站点友好优先于吞吐。

### 4.3 分页纪律

- 先 `getcount` 拿 `total`，再按 `page_size` 分页；`rows` 上限 1000。
- **必须注入排序键**，否则 `page=N` 偏移翻页会退化成无序遍历 → 丢行。
- 排序列必须是**服务端认得的列**；注入整列为空的列 = 空操作。
  逐表登记的排序列见 §6 与 `src/protocol.py` 的 `PAGINATION_SORT_COLUMNS`。

## 5. 12 张表：怎么选 + 逐表事实

**表覆盖强非均匀，各表天区互不重叠**。用赤道附近统一坐标探测会让大半表假 0 —— 必须用下表的实测坐标。

| 表 | 实测代表坐标 (RA, Dec) | 半径 | `total` | 覆盖分档 |
|---|---|---|---|---|
| `ps1` | (180.0, 30.0) | 300″ | 5109（60″ 时 174；1800″ 时 215774） | 全天覆盖 |
| `gaia_dr3_18` | (286.1, 15.7) | 300″ | 7193 | 确认有覆盖 |
| `xpsp` | (10.68, 41.27) | 300″ | 2268 | 确认有覆盖 |
| `smss_dr4` | (0.0, -30.0) | 300″ | 106 | 确认有覆盖（南天银道面） |
| `splus_dr4` | (10.0, -70.0) | 300″ | 206 | 确认有覆盖（南天） |
| `stripe82` | (30.0, 0.0) | 300″ | 27 | 确认有覆盖（赤道精测天区） |
| `dr3xpcorr` | (180.0, 30.0) | 300″ | 1（1800″ 时 120） | **极稀疏但正常** |
| `scr_lamost` | (180.0, 30.0) | **1800″** | 137（**300″ 时 0**） | **极稀疏但正常** |
| `scr_galah` | (120.0, -20.4) | **1800″** | 1（**300″ 时 0**） | **极稀疏但正常** |
| `landolt` | (30.0, 0.0) / (120.0, -20.4) | 300″ 与 1800″ | **0** | **统计可解释的稀疏** |
| `jplus_dr3` | (10.0, -60.0) / (0.0, -60.0) | 300″ 与 1800″ | **0** | **疑似站点侧覆盖异常，待站方确认** |
| **`uss_dr1`** | (120.3, -20.4) | 5″ 与 300″ **同值** | **1039801 = 全表行数** | ⚠ **锥搜不可信，见 §7** |

### 5.1 「查不到」与「这张表没覆盖这里」是两件事

- `landolt`：全表 45712 行摊全天约 **1 行 / 3.7 deg²**，0.5° 锥的期望命中只有 **0.018 行**。
  探测 45 处全 0 属**预期**，不是故障。**要用它必须先有已知标准星坐标**（锥搜按位置找，按名字找不到）。
- `jplus_dr3`：在其公认天区（Dec −79…−45）内探测 24 处、含最大半径 5° 仍全 0，
  密度**解释不了**。报障时必须与 landolt 的「稀疏」**分开说**，否则站方无从定位。
- **三张表用 300″ 锥会得到假 0**：`scr_lamost` / `scr_galah` / `dr3xpcorr`。锥太窄是正常的。

## 6. 排序列：什么时候注入、注入哪一列

| 表 | 登记排序列 | 实测 |
|---|---|---|
| `ps1` | `ps1_ra` | 非空。~~`ps1_source_id`~~ 实测 174/174 全空 → **已退到坐标列** |
| `uss_dr1` | **`ra_u`（裸名）** | 1000/1000 非空。⚠ 带前缀的 `uss_dr1_ra_u` 在 96 列回包里**不存在** |
| 其余表 | 见 `src/protocol.py` 的 `PAGINATION_SORT_COLUMNS` | 多数非空 |

**⚠ 位置相关**：`ps1_source_id` 的空值率**随天区变** —— (180,30) 样本 0/174 非空，
而 (286.1, 15.7) 实测 **128/300 非空**。所以「这一列整列为空」是**那个天区**的性质，
不是列的属性。实测结论登记在 `contracts/measurements/sort-columns.yaml`，由门禁
`verify_measurement_registry` 核对。

**⚠ `uss_dr1` 不要显式请求 `order="desc"`**：会整页拿到 `ra_u` 为 `nan` 的行，
而坐标规范化取的正是 `ra_u`/`dec_u`，于是下游拿到整页空坐标。默认 `asc` 安全。

## 7. ⚠ `uss_dr1`：锥搜会返回锥外的行（P0）

**2026-10-07 实跑坐实。这不是稀疏，也不是覆盖问题 —— 是站点的锥形约束没生效。**

同坐标 (120.3, −20.4) 查两次，半径差 60 倍：

| 请求半径 | `total` | 1000 行中落在请求锥内 | 角距中位数 |
|---|---|---|---|
| 5″ | 1039801 | **0 / 1000**（11 波段逐段核） | 420708″ ≈ **116.9°** |
| 300″ | 1039801 | **0 / 1000** | 420708″ ≈ **116.9°** |

四条独立判据：

1. `total` **与半径无关** —— 锥搜计数必须随半径变。
2. **算术上不可能**：300″ 锥面积 0.0218 deg²，装不下百万行（全站需约 20 亿颗源）。
3. **两次回包逐行角距完全相同** —— 半径对该表零影响。
4. **回包缺 `inputobjs_input_ra/dec`** —— 其余 11 张表的锥搜回包都有这两列，
   `uss_dr1` 的 96 列里一列都没有 ⇒ 站点侧也没把它当锥搜处理。

**操作口径**：要按位置取 `uss_dr1` 的行，**不要信锥搜结果**；拿到回包后必须自己按
`ra_<band>`/`dec_<band>` 复核角距再入库。排序列用**裸名 `ra_u`**。
证据与复现见 `references/site-endpoints-and-interactions.md` §11.7。

## 8. 坐标列：12 张表实测 5 种形态，不能硬编码

| 形态 | 例 |
|---|---|
| 裸名 `ra` / `dec` | 少数表 |
| 星表前缀 `ps1_ra` / `ps1_dec` | ps1 等 |

## 9. 「无值」的编码：五种，按"等于哨兵"判空会漏判

| 编码 | 形态 | 出现在 |
|---|---|---|
| 空串 | `""` | 多数列 |
| 字面 `nan` | 文本 | uss_dr1 的误差/幅值列大量出现 |
| `-1004.09` | 数值哨兵（**带**） | ps1 |
| `-999.0` / `-1000.0` | 数值哨兵（**点**，如 `*_err` 列） | 多数表 |
| `99.0` / `99.999` | 上限饱和 | PS1（星等未检出/饱和/超极限） |
| `-32768` | int16 下界（**点**） | uss_dr1 的 12 个 `*_flag` 列 |

**判定口径**：`value <= -999.0`，且列不在豁免表里。
豁免列：`pmra` / `pmdec` / `radial_velocity` —— 带符号的真实物理量，低于阈值也是合法观测。
（`-32768 < -999`，所以现有阈值**已经覆盖**它，不需要新增规则。）

> ⚠ **豁免列按后缀匹配**：回包里既有 `pmdec` 也有 `landolt_pmdec`，而 `radial_velocity`
> 本身含下划线。只做精确相等会漏前缀形态；按第一个下划线剥离会把 `radial_velocity`
> 剥成 `velocity` 漏掉自己那条。

## 10. `ps1` 的双记录型（用列前先判型）

`ps1` 的回包**不是同一种记录的集合**，是两类结构不同的行混排：

| 判据 | A 组（对象记录） | B 组（点源记录） |
|---|---|---|
| `ps1_source_id` | 非空 | **空串** |
| 实测构成 | 431 行，占索引 0–430（前段连续） | 569 行，占 431–999（后段连续） |

- 判型判据唯一且充分：**`ps1_source_id` 是否非空**。
- **覆盖是位置相关的**：换天区就换构成（(359.5, 0.0) 是混排段、(180,30) 是纯点源段）。
  **要判型就先判型，别假设块的顺序或位置。**
- 用 `ps1_source_id` 当主键有**两个失效条件**：① 该天区整列为空 ② 组内 id 有重复。

## 11. 状态判别：空 / 错 / 软 404 必须分清

| 形态 | 判据 | 处置 |
|---|---|---|
| 正常有数据 | 200 + getcount > 0 | 正常 |
| **合法 0 行** | 200 + `{"total":0}` + 带 BOM 的表头 CSV + 0 数据行 | **是合法结果**，不是错 |
| **软 404** | 200 + 错误体（以 `{` 开头且含 `Not Found`） | 未知名/未覆盖 → 报 `E_SOFT_404` |
| 会话失效 | `E_NO_SQLID` | **重走 phase-1**，不重试旧 sqlid |
| 分页中断 | 返回 `truncated=True` | 续取，已取行不得丢 |

> **「合法 0 行」与「站点故障」在响应形态上可能无法区分** —— `jplus_dr3` 就是这种：
> 站点此刻的表现与「该锥内无源」**无法区分**。这时只能如实说「无法区分」，
> 不能替站方下结论。

## 12. 单位陷阱（本仓最高频错误）

- 半径入参 `pos.radius` 是**角秒**；参数层的度要在这一层换算掉。
- 坐标角距计算必须用**球面 haversine**，不能用平面近似（高赤纬会严重算小）。
- 坐标量化到 **9 位小数**是浮点表示的安全精度（≈0.3 mm）：再粗会并源，再细会因浮点尾数对不上。

## 14. 上手自查清单

拿到一份 BEST 回包，依次问：

- [ ] 表单页 200 —— **这不证明有数据**，还要看 `getcount`
- [ ] `total` 与请求半径**相关**吗？（`uss_dr1` 就是反例）
- [ ] 回包行**真的在请求锥内**吗？（逐行算角距，别信 `total`）
- [ ] 排序列**服务端认得**吗？（`uss_dr1` 只有裸名 `ra_u`）
- [ ] 排序列在**这个天区**有值吗？（`ps1_source_id` 位置相关）
- [ ] 坐标列名是**哪种形态**？解析**按列名**还是按列序？
- [ ] 判过状态吗：合法 0 行 / 软 404 / 会话失效，三者别混
- [ ] 判过哨兵吗：空串 / `nan` / `-1004` / `-999` / `99` / `-32768` 六种
- [ ] `ps1` 判型了吗？（`ps1_source_id` 是否非空）
- [ ] 截断三元组 `total` / `returned` / `truncated` **自洽**吗？
