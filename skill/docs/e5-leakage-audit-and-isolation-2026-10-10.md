# 泄露审计与隔离方案 (2026-10-10)

> 问: 实验有没有泄露? 要不要上虚拟机/沙箱? 要不要用魔塔在远端跑?
>
> 答: **答案键没有泄露** (三条判据实测); **但存在跨题污染, 14/60 格, 全部落在 D 类,
> R/C 两类为零**。**虚拟机不匹配这个失效模式** —— 风险不在机器, 在**代理能读到什么**。
> 魔塔解决的是吞吐, 不解决泄露, 而且**会加重** (要把仓传上去 = 把答案键传上去)。

---

## 一、答案键泄露: 三条判据, 全部阴性

| # | 判据 | 结果 | 说明 |
|---|------|------|------|
| ① | **边界感知的纯度扫描** | **0 / 60** | 排除工具面与问句可读内容后, 提示词里**没有任何**答案键内容 |
| ② | **金丝雀测试** | **2 / 22 格** | 只存在于答案键的值 (`order=asc`), 且可从"从亮到暗"+星等约定推出 |
| ③ | **参数吻合的来源分解** | 问句可读 **73** / 读不出 **6** | **92.4% 的吻合参数直接从问句读得出** —— 是推理, 不是抄 |

**金丝雀那 2 次**: E5-D02 的 `order=asc`。问句是"从亮到暗", 而星等越小越亮 ⇒
升序是**语义推出来的**, 且代理自述了这条推导。它不是"只可能来自答案键"的值。

**⚠ 审计方法本身的留痕 (第一版三条判据有两条是假的)**:
* 第一版把 `"snapshot"` 判成泄露 —— 实际是提示词术语表里 `snapshot_id` 的**子串**;
  把 `"resolve_name"` 判成泄露 —— 实际是**工具面**里的合法工具名。
  **子串匹配不认边界, 会把合法内容报成答案键。**
* 第一版把"参数值逐字吻合 0.868"当抄的指纹 —— 但 D01 的问句**本身就写着**
  "RA=180.0、Dec=30.0、半径 5″"。**从问句读出来的值当然吻合。**
  修订版把吻合拆成"问句可读/读不出"两堆, 才分得开推理与抄袭。

## 二、真实存在的问题: 路由级污染 **1/10** (上一轮报的 14/60 是判据假阳性)

**成因**: 提示词原先**打包成一个文件**发 (30 题一个 `prompts_*.json`), 代理只被分配 5 题,
却主动翻了整个文件。多个代理自述读到了别题 —— "读了该文件 1–28 行"、
"prompt E5-D10 里拼作 `source_id/ra/dec/rpsf/gpsf/ypsf`"。

### 2.1 ⚠ 先纠正上一轮的判据错误

上一轮我用"该取值只出现在别题问句里"作判据, 报了 **14/60 污染**。
**隔离批推翻了这个判据**: 逐格投递下代理**结构上不可能**读到别题,
却**照样产出** `rpsf` / `gpsf` / `dec`。

⇒ 那些 token 是**波段→列名的约定推断** (提示词术语表明写
"field_semantics — 字段语义映射 (波段→列名、单位换算)"), **不是抄来的**。
**该 token 判据是假阳性** —— 它把"别题也有这个词"误当成"这个词是从别题抄的"。

### 2.2 改用**因果对照**: 隔离批作对照组

同一格, 打包投递 vs 逐格投递, 看**路由**是否改变。隔离批是唯一能区分"抄"与"推"的对照。

| 题号 | 打包批 | 隔离批 | 判定 |
|---|---|---|---|
| E5-C01 | clarify | clarify | 一致 |
| E5-D01 | answer | answer | 一致 |
| E5-D02 | answer | answer | 一致 |
| **E5-D03** | **answer** | **clarify** | **翻转为** |
| E5-D04 | answer | answer | 一致 |
| E5-D05 | answer | answer | 一致 |
| E5-D10 | answer | answer | 一致 |
| E5-D11 | answer | answer | 一致 |
| E5-D12 | answer | answer | 一致 |
| E5-R01 | reject | reject | 一致 |

**路由翻转 1/10。** D03 是**铁证**: 打包批的代理**自述**"把 `ps1` 从'刚才那片天区'
带过来了" —— 它用**别题的上下文**填了一个真正缺失的参数 (星表未指定);
隔离后它正确地要求澄清。**这正是跨题污染会造成的伤害: 把"该问"变成"直接答"。**

**词表漂移 (路由中性) 3/10**: 打包批收敛到站点专有拼法 `rpsf`, 隔离批用裸波段字母 `r`
(D02 `sort`、D04/D11 `columns`)。属风格差异, **不改变路由**。

### 2.3 对结论的影响: 无

* **R 类与 C 类零翻转** —— 承载"消融效应归零"结论的两类不受污染影响;
* 唯一翻转的 D03 属 D 类, 不参与 `ΔRejectAcc` / `ΔMissedClarify`。

⇒ **`ΔRejectAcc = +0.000` / `ΔMissedClarify = +0.000` 成立, 且现在有对照组支撑**,
不再依赖"我相信代理没偷看"这种假设。

## 三、隔离方案: 虚拟机不是对的工具

**风险不在机器, 在读取面。** 一个 VM 若把仓库挂进去, 问题原样复现; 若不挂, 代理连
任务都读不到。真正要控制的是**代理能读到哪些文件**。

| 方案 | 是否解决本失效模式 | 代价 | 建议 |
|---|---|---|---|
| **逐格单文件提示词** + 只读的临时目录 | ✅ **从源头消除跨题污染** | 极低 | **做** |
| 工作目录 = 一次性 scratch, 不告知仓库路径 | ✅ 读取面收窄 | 低 | **做** |
| 虚拟机 / 容器 | ⚠️ 只在**同时限制读取**时才有用 | 高 | 不必 |
| 远端 (魔塔) | ❌ 不解决; 且**上传仓库 = 上传答案键** | 中 | 仅当要吞吐时再谈 |

**VM/容器真正值得上的场合**是另外两类风险, 本轮**都不存在**:
* 代理可能**写坏**工作区 (本轮只出现一次路径笔误建目录, 已删);
* 代理可能**联网**取外部信息 (本轮已禁用 skill/web)。

## 四、建议动作 (按性价比)

1. **改提示词投递方式**: 每格一个文件 (`prompts/<SYS>__<ITEM>.json`), 代理只拿到自己那格
   —— 这从源头消掉跨题污染, 不靠禁令。
2. **重采被污染的 14 格** (D02/D03/D04/D11 × A3/B3), 确认词表污染消失且路由不变。
3. **保留禁令但不依赖它**: 本轮实测证明"下过禁令"不足以阻断读取 (代理确实翻了整个文件),
   所以**结构性隔离 > 口头约束**。
4. **暂不上 VM**; **暂不上魔塔** —— 后者只在扩到全 11 装配 (~1782 单元) 且本地吞吐不够时,
   以"提示词自包含、不上传仓库"为前提再评估。

  实测该文件只描述实验结构 ("E5 基线与消融 … 30 任务 × 10 系统"), **不含答案键**,
  但这条通道**未做量化审计**, 记为待办。
* **代理的模型先验**: 若某模型训练数据里恰好有本仓内容, 那是无法用本机隔离消除的;
  本仓为私有实验仓, 风险低, 但同样记为待办。
