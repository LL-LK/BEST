## 为什么换掉原来那三份

原三份是合成数据，且各自带了一个**站点从不发布的列**：

- `ps1_5rows` / `ps1_2pages` 的 `ps1_snr` —— 真实 ps1 回包 34 列里没有它（只有 `*_err` 误差列）
- `scr_galah_teff` —— 真实 scr_galah 回包 141 列里没有它（原夹具名 `scr_galah_3rows`
  里的幽灵列之一；该列随本轮换真实回包一并消失）

数据本身也是编造的：`BEST_FIX_0001..0007` / `SCR_FIX_0001..0003`、`18.20` 这类整齐星等、`180.0001/30.0001` 这类递推坐标。

这与 E4 的 `ps1_replay.csv` 是同一种病（那份也带 `ps1_snr`）：合成数据里从来没有哨兵值、也从来没有空列，`*_corr` 四个列在真实 ps1 里**整列全空**（0/174），而 `scr_galah` 的真实回包更是零数据行 —— 这两种形态在旧夹具里都不存在。

## 两个必须记下的现实约束

**1. 站点在这个量级下不分页。** 31 份真实快照全部是 `page_size=1000` 单页回包，`total` 与 `returned_count` 全部相等（3 / 27 / 174 / 770 / 1000 / 5109 / 12750 / 50095 / 305172 …）。没有一份是"第 1 页 5 行 + 第 2 页 2 行 + total=7"的形态 —— 旧 `ps1_2pages` 描述的分页场景**站点并不产生**。

因此 `ps1_2pages` 已重命名为 `ps1_singlepage`，REPRO-08/27/28 的 `stability_class` 从 `pagination_termination` 改为 `past_last_page_boundary`：现在考的是**末页边界**（翻过末页之后服务端返 0 行，客户端不得把它读成"还有下一页"或失败），而不是"翻页翻到一半"。`ReplayTransport` 对缺失页返空 CSV 而非 404，正是复现这条语义。

**2. `scr_galah` 真的就是 0 行。** 两个天区（120.0/-20.4、286.1/15.7）实抓都是
`total=0`，没有任何数据行。原夹具名里的 "3rows" 与内容不符，已于 2026-10-04
改名为 **`scr_galah_0rows`** —— 与 `ps1_2pages → ps1_singlepage` 同一口径：
**夹具名必须与内容相符**，否则"目录名声称什么"与"里面是什么"分属两套事实，
读者先看目录名就会被误导（E2 文档 §4.6.4 判过同款问题）。
保留 141 列表头正是为了如实呈现「有列定义但无数据行」这条真实形态。
REPRO-11 因此实测的是"真实零命中"的确定性。

## 连带约束

- `count.json` 的 `total` 必须等于页内数据行数，否则 getcount 与数据页不自洽。
- 行数断言按真实行数写死（`ps1_5rows` 6 行 = 表头+5、`ps1_singlepage` 4 行 = 表头+3），
  夹具更新时会立刻红，而不是让陈旧断言一直绿着。
