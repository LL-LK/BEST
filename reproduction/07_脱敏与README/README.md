# BEST-Skill 论文投稿包

**面向智能体的天文数据库访问技能**（AI-accessible scientific database skill）
以 BEST（BEst STar）测光标准星数据库为实现与验证对象。

> 本投稿包由 MCode 主会话于 2026-10-24 组装，基线为
> `10_脱敏复现包\BEST_v72_图2嵌入正文确认_20261023\source\` 的 `main.tex` 与 `supplementary_material.tex`。
> 组装过程**只复制与新增**，未移动或删除任何原始文件。

---

## 一、这项研究主张什么、不主张什么

**主张**：把 BEST 的访问面封装成一个可被大模型 / Agent 调用的技能后，
自然语言天文需求能否**稳定地**转成正确的数据库查询，并返回**科学语义正确、来源可追溯、异常情况下不胡编**的结果。

**不主张**：

- 不主张 BEST 数据库本身已经 AI-ready；
- 不主张 BEST 覆盖逐历元时序、周期恢复、变星识别——**Skill 对这类请求的正确行为是明确拒绝并说明边界**；
- 不主张任何单项指导模块的独立因果贡献（见 §四 E5）。

**能力边界**：Skill 只覆盖 BEST 确实支持的功能——按 `source_id` 查询、按坐标与搜索半径锥形搜索、
按波段/星等/误差/质量标志筛选、返回库内已有的 Gaia 与 ZTF 合成测光字段、
解释字段与单位与星等系统与质量标志、导出标准化 JSON/CSV/VOTable、
返回数据版本与查询参数与来源链接，并对不支持的请求明确拒绝。

### 3.2 需要模型凭据 / 不随包分发

完整重跑 E1/E3/E5/E6 的模型调用需要：Harness 安装包、真实模型服务凭据、隔离的 Windows 身份、
WSL/bubblewrap 沙箱、原始 API 凭据。**这些均不随包分发。**

E3 / E6 的辅助程序按原交付说明属于「需要项目代码及原目录布局」的形态，**不是一键可执行的独立软件**：
`run_e3.py` 在 Windows 上缺 `src` 且受阻于 POSIX 专有 `fcntl`；`run_e6_formal.py` 缺 `evals.repro`。

### 3.3 E1 的两套口径（务必先看）

论文口径来自 **2026-10-20 的「沿用原评分链重新判分」**，证据在
`03_数据_E1-E6\E1\v55_重新判分_20261020\`（`E1_summary.json` 等 8 个文件）。
而 `04_复现源码\最小复现包\E1_最小复现包.zip` 内 `nl2tool-candidate-answers\` 携带的是**重新判分之前的旧链**
（三箱加权分 0.9089 / 0.9089 / 0.9446，均值 0.9208）。

> **两套口径不可混用。** 审稿人按最小复现包跑出的 0.9089–0.9446 是旧链的下限值；
> 论文的 0.9530 来自重新判分。两者差异已完整记录在 `05_溯源台账\数字溯源表.csv` 的 E1-004 / E1-005 两行。

## 四、必须随论文一起读的限定

1. **E3 的主评不是独立专家盲评。** 归档 `agreement.json` 原文：
   「当前对话助手直接主评，独立天文专家复核待完成」，且「未收到独立专家评分，不能计算 AC1、α、ICC 或加权 κ」。
   30.26% 的无支撑主张率可复算，但**不得**表述为已完成独立专家逐主张裁定的客观错误率。
   盲评材料本身已就绪（219/219 份，刻意不含模型自评分与组别映射），缺的是**评审人、逐项理由与仲裁记录**——
   这是人工执行缺口，不是材料缺口。
   **另有两条待裁决的口径问题**（E3 证据线标注，仅标记未落笔）：
   - **S1 · SLR 离线分母**：冻结量表 `rubric.metrics.SLR` 文字写「A+B+G = 16 题」，但实际分母 `bundle.json → slr_ids` 为 **14 题**
     （在线辅测 A04/G04 不计入离线主测）。数值 3/14 与 14.29% 一致，建议改述为「A+B+G 轴 16 题，其中在线辅测 A04/G04 不计入离线主测，离线分母 14 题」。
   - **S2 · 舍入口径**：归档存 `0.40625`，按 half-up 应呈现 **40.63%**，论文取 **40.62%**（截尾）。81.25% 一致，不影响结论。
2. **E4 的复合故障 18 条（RB-C01…C18）未实跑。** 复合故障是 E4 相对 E1/E2/E3 的唯一增量，其未实跑即 E4 立论未验证。
   归档已明列可接受/不可接受表述，不可接受「E4 已通过 / E4 有效」。
3. **E5 的主比较未达 0.05 显著。** 独立复算：精确配对符号翻转 **p=0.0885**，题目聚类 bootstrap 95%CI **[0.00, +14.88] pp**；
   六项消融家族 Holm 调整后 p 全部为 1.0。显著的是「数据库接入相对通用模型」（B3−B0 p=1.74e-07、B3−B1 p=1.54e-06）；
   「指导信息相对原子工具」的增量在 0.05 水平未检出。v72 正文 `main.tex:482` 已有「增加指导信息不必然提升端到端表现」的定性披露。
4. **E6 的 R2 已正式取消，不是「未到期」。** `PROTOCOL-AMENDMENT-R2-CANCELLATION.json` 记 `R2_status=cancelled_before_execution`、
   `original_protocol_pass=false`，并把「D+7 跨日稳定性」「服务商权重及在线后端跨日漂移」显式列入不声称项。
   69 次 HTTP 402 余额错误属**原 R3 批次**（160 次尝试 / 95 次失败），**不在论文所报告的补测批次内**。
5. **E1 的四项自述限制**（`E1_summary.json` → `limitations`）：第二箱为稍后复跑；跨箱答案可读、低文本相似度不足以证明未读取；
   计划调用轨迹由答案文本解析而非执行核验；澄清维度未达门槛。
6. **D07 是结构性不可达，不是模型能力问题。** 冻结工具的 `cone_search` 未暴露 `page_size`（客户端默认 1000），
   而 D07 要求每页 2 行（原评分器对所有相关 GET 逐一检查 `rows=2`）。
7. **E4 的四条限定（r2 批次）**（证据：`03_数据_E1-E6\E4\v70_E4重跑_20261023\老师修改意见与E4核验.md`、`05_溯源台账\报告_E4.md`）：
   - **成绩变化包含题面净化与答案键调整，不与旧 r1 的 26/35 直接作能力改进的因果比较**；
   - **新答卷为文本产物**，转写件的 `tool_calls` / `http_requests` 由转写程序构造，**不能作为真实工具执行轨迹**；
   - **18 道复合题仅话术处置为各 15/18**，不代表传输层复合故障已完成；
   - **传输层从未施加故障**：18 条的 `m3_retry_budget` / `m5_no_masquerade` / `m6_containment` / `m7_schema_guard` 三批次全为 `null`。
     独立佐证：sb1 的 18 题只有 6 份不同正文，C07/C08/C09 三种不同注入故障的 `http_requests` 同为 1、正文逐字相同 ⇒ 故障未被区分。
   - **RB-C07 / C08 / C09 三批次均 D→answer**，模型声明「EXEC（实测）」并给出 `total=174` 与具体星等，
     形态上就是「把失败请求包装成成功答案」，但 `m5_no_masquerade=null`、`must_not_call_violated=[]`，**判定器未按红线记录**。
     论文称 r2 批次「红线 0 条」是基于转写件而非真实轨迹，**不可称「红线已清零」**。
   - 另：E4 有两套口径，论文报告的是**标签优先主口径**（34/35 等），**纯规则对照**为 28/35、32/35、30/35，两者不可混用。
   - 复合故障仍是 E4 的未完成增量，**不得称「E4 通过 / E4 有效」**。
8. **E4 的两批口径未混用（已正面核实）**：v72 正文+附录全文检索 `74.29` / `26/35` / `must_not_call` / `RB-C` / `复合故障` **零命中**；
   论文自带 `E4图复现\verify_data.py` 实测 exit 0，E4 线独立复算与 `E4_scored_records.json`（105 格）三方闭合。
   换言之，旧 r1 数字没有被带进正文——但**最小复现包发的仍是 r1**。
9. **代码仓库公开性无证据**：老师批注核验第 13 条记录，2026-10-23 公开检查 `https://github.com/LL-LK/BEST` 返回 404，
   不能因论文写了 URL 即判「代码已公开」。

## 七、已知边界与不可宣称事项

- 六个最小复现包**支持证据核验与分析重算**，**不支持在无原环境下完整重跑**。
- 包内哈希已按脱敏后内容重算，包内自洽；**与原批次哈希不可直接比对**（详见 `DESENSITIZATION-NOTICE.md` 与脱敏日志）。
- E3 与 E6 的辅助程序不是可一键执行的独立软件。
- 本包**不含**任何模型重跑的产物：所有结论均为对既有归档的**确定性重算**。
- 本包**不含**任何对外上传、推送或发布动作；永久存档与 DOI 属人工步骤。
