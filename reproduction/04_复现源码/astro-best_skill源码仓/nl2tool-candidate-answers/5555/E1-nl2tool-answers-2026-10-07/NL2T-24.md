# NL2T-24

## 题面

> 上传我的星表做交叉匹配。

## 判定

- 类别：**先澄清再调用**（`clarify`）
- 目标工具：`crossmatch_batch`

## 期望调用

```python
crossmatch_batch(coords="[由用户星表解析出的 {ra, dec, id}]", catalog="ps1", radius_arcsec=3.0, nearest_only=true)
```

## 需要澄清的点

- 工具面没有'上传文件'这一项: crossmatch_batch 收的是坐标字典列表, 需要先把用户的星表解析成 ra/dec(度) 列表。
- 未给出匹配半径与星表时按默认 3.0″ / ps1 / 最近邻, 并显式声明假设。

## 关键要点 / 坑位

- 批量走 crossmatch_batch(单次上传、服务端 proximity), 不得逐点 cone_search——那是把一次匹配放大成 N 次请求。
- 每个元素必须含数值型 ra/dec; 缺坐标原地 E_INVALID_INPUT, 不静默当 (0,0)。
- 结果用 n_inputs 与 returned_count 对照给匹配率; 截断则 fetch_page 续拉。

## 给用户的回答口径

先要星表内容(或文件), 解析成坐标列表后单次 crossmatch_batch, 回报匹配率与未匹配项。
