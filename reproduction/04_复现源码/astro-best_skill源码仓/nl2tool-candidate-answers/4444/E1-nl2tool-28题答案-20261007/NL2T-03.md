# NL2T-03
## 用户原话
> M31 的坐标是多少？
## 判定
直接调用 —— 「M31」是唯一明确的天体名，本 skill 自带天体名→ICRS 坐标的解算工具 `resolve_name`（后端代理 CDS Sesame，`/nss/solve`），无需澄清、不越界、不拒绝。
## 期望调用
```python
from src.ai_tools import ToolBox

toolbox = ToolBox()
result = toolbox.resolve_name("M31")
# 统一信封：result.data -> {"name": "M31", "ra": <十进制度>, "dec": <十进制度>,
#                          "remark": ..., "remark_external": True}
# 坐标值由站点回包给出，此处不预填、不猜测。
# 失败分支：status.error_code == "E_NAME_UNRESOLVED"（Sesame 失败哨兵 ra=dec=-1000）
#          或 "E_INVALID_INPUT" / "E_BACKEND"。
```
## 参数与换算
- `name="M31"`：唯一入参（schema 的 `required: ["name"]`，`additionalProperties: false`），**原样传用户给的天体名**，不做大小写改写、不加空格、不换成 NGC 224 之类的别名——别名替换等于替用户改问题，且无必要（Sesame 可直接解 M31）。
- **无单位换算**：`resolve_name` 不含任何坐标/半径/单位参数，因此没有"半径→角秒""坐标→十进制度"的换算步骤。换算口径只在返回侧成立——返回的 `ra`/`dec` 是**十进制度**（ICRS），与 `cone_search(ra, dec)` 的入参单位一致，可直接喂给后续锥搜；**不得**把 ra 当"时:分:秒"再乘 15，也不得做 hms→deg 手工转换。
- 本题不涉及半径参数（skill 全局口径：半径统一角秒、上限 18000 角秒；坐标十进制度），不要凭空给半径。
- 成本口径：`resolve_name` 是**发请求**的工具（`GET /nss/solve?obj=M31`，`cost.http_requests≈1`），不是零请求工具；零请求工具只有 `list_catalogs` / `describe_catalog`（读本地注册表），它们答不了"某个天体的坐标"。

## 陷阱与错法
- **误用 `cone_search`**：锥搜必填 `ra`/`dec`，而本题恰恰是要求坐标——用锥搜是循环依赖；缺参数绝不能编造坐标（编一个中心点 + 默认 `radius_arcsec=180` 会查到毫无关系的天区）。错因：把"问坐标"错读成"查天区"。
- **误用 `list_catalogs` / `describe_catalog`**：这两个是**星表元数据**（12 张表的列清单/波段），答的是"有哪些表、有哪些列"，与"某天体的坐标"无关；且它们零请求，会给人"答得快"的错觉，但答案根本不对题。
- **误委派给 astro-catalog 或直接拒绝**：`/nss/solve` 名称解算是本 skill 自有能力（BEST 站点端点，他 skill 无 BEST 端点），不属 out_scope 的"通用星表检索"；拒绝或转派都属边界误判。
- **凭记忆直接报坐标（不调工具）**：即使记得 M31 大致坐标，也应经 `resolve_name` 取数——坐标必须有站点出处与 provenance，手工答案无 `data_hash`/`stable_uri`，且违反站点数据 `untrusted` 的标注纪律。
- **把失败哨兵当坐标**：`/nss/solve` 失败回 HTTP 200 + `ra=dec=-1000`，**不能按状态码判**；实现必须走 `is_name_resolve_failure`，否则会把 `(-1000, -1000)` 当成真实坐标返回。M31 在 Sesame 覆盖内，正常路径不会触发。
- **单位错**：把返回的 ra 十进制度误当"时"再 ×15，或把 dec 当角分——返回已是十进制度。
- **半径/坐标系口径混淆**：本题无半径参数，不要顺带塞 `radius_arcsec`；若用户后续要"M31 附近的源"，那才是 `resolve_name` → 取 ra/dec → `cone_search`（半径按角秒）的两步链，属另一意图。
## 若需澄清，问什么
无需澄清 —— 「M31」是唯一、明确、可被 Sesame 直接解算的天体名，工具与参数均无歧义。仅当用户真实意图是"M31 天区里有哪些 BEST 源"（而非"M31 的坐标"）时，才需在其后追加一步锥搜；但按原话只问坐标，直接 `resolve_name("M31")` 即可。
