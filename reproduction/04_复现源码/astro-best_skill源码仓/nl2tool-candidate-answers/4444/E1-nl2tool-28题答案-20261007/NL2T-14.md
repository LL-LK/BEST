# NL2T-14
## 用户原话
> 坐标 12h30m00s +20°00′00″ 附近有什么？

## 判定
直接调用：坐标可无损换算为十进制、半径按 skill 缺省口径（180 角秒=3 角分）取值，无需向用户追问即可发起一次 BEST 锥形检索。

## 期望调用
```python
from src.ai_tools import ToolBox

# Agent 唯一工具面（P1-9）：cone_search 走 BestClient 两阶段协议（POST 表单→sqlid→分页 GET）
toolbox = ToolBox()
result = toolbox.cone_search(
    ra=187.5,            # 12h30m00s 六十进制换算为十进制度
    dec=20.0,            # +20°00′00″
    radius_arcsec=180.0, # "附近"未给半径 → 取工具面缺省 180 角秒(=3 角分)；显式写出以示口径
    catalog="ps1",       # 工具面缺省星表
)
# 若结果 truncated=True，再凭 result.provenance["session_id"]（sqlid）调 toolbox.fetch_page 续拉
```

## 参数与换算
- `ra=187.5`（单位：度，ICRS）。六十进制 → 十进制度换算（赤经 1h = 15°）：
  - 12h × 15 = 180.0°
  - 30m = 30/60 h = 0.5h → 0.5 × 15 = 7.5°
  - 00s = 0°
  - 合计 180.0 + 7.5 + 0 = **187.5°**
  - 校验：`guards.validate_coordinate` 要求 ra ∈ [0, 360)，187.5 合法。
- `dec=20.0`（单位：度，ICRS）。+20°00′00″ = 20 + 0/60 + 0/3600 = **20.0°**；符号为正（北天）。校验：dec ∈ [-90, 90]，合法。
- `radius_arcsec=180.0`（单位：角秒）。用户只说"附近"未给半径 → 不编造，直接采用 skill 缺省口径：
  - `src/ai_tools.py:469` 的 `ToolBox.cone_search(..., radius_arcsec: float = 180.0)`；
  - `references/tools.schema.json` 中 cone_search 的 `radius_arcsec` 声明 `"default": 180.0`，注释明写"缺省 180 角秒=3 角分，与 src/ai_tools.py cone_search 的 radius_arcsec 缺省值一致"；
  - `src/client.py:418` 底层 `BestClient.cone_search` 同为 180.0。
  - 单位换算：180 角秒 = 180/3600° = 0.05° = 3 角分。校验：`guards.validate_search_radius` 要求 0 < r ≤ 18000 角秒（=5°），180 合法。
- `catalog="ps1"`：工具面缺省星表（`src/ai_tools.py:470`、`tools.schema.json` `"default": "ps1"`）。用户未指定星表，按缺省处理。
- 其余参数（`columns/sort/order/nearest_only/max_rows`）不传，全部走工具面缺省（max_rows=1000，超出置 truncated）。

## 陷阱与错法
1. **赤经换算漏乘 15（最易错）**：把 12h30m 直接当 12.5°，或把 30m 当 30°。赤经是时间单位，1h=15°、1m=0.25°，正确值是 187.5°，不是 12.5° 也不是 192.5°。
2. **半径单位当成"度"**：`radius_arcsec` 单位是**角秒**。若误传 180（当成度），会被 `validate_search_radius` 以"超过 18000 角秒"拒绝（E_INVALID_INPUT）；若误传 0.05 又只覆盖 0.05 角秒，几乎必得 0 行。缺省 180 角秒 = 3 角分才是"附近"的合理口径。
3. **半径缺省口径选错**：`src/scripts/best_cone_search.py` 脚本入口的缺省是 **60.0 角秒**，`src/models/input.py` 的 `ConeSearchInput` 也是 60.0；但 Agent 走的是工具面 `ToolBox.cone_search`，其缺省是 **180.0 角秒**。本题按工具面口径取 180。
4. **因"没给半径"而拒答或编造半径**：skill 已有明确缺省，属"有口径可按"，不该拒绝，也不该自造如 1°、5′ 等值。
5. **误用 `crossmatch_batch`**：其缺省半径是 3 角秒（`src/ai_tools.py:566`），且语义是"给定坐标批量匹配"，不是"这片天区里有什么"；"附近有什么"应走 cone_search。
6. **误路由到 astro-catalog**：BEST 数据面只有本 skill 能访问（`SKILL.md` 定位段），通用检索 skill 无 BEST 端点，不能转派。
7. **误把 ra/dec 当字符串或六十进制直接下传**：工具面只接受十进制度（float），必须先在本地完成换算。

## 若需澄清，问什么
无需澄清。坐标可精确换算为十进制（187.5°, +20.0°），"附近"由 skill 缺省半径 180 角秒（3 角分）覆盖，星表由缺省 ps1 覆盖——四项参数均有确定口径，直接调用即可；若用户后续想收窄/放大天区或换星表，可在结果返回后再按需追加约束。
