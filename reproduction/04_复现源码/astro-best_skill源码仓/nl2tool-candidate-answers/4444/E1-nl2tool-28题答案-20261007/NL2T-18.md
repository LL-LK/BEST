## 参数与换算
用户原话未提供任何可取值，逐参数只能记为"缺"，且一律不得凭空填：

- `name`（resolve_name 必填）：无值。用户没给天体名（如 M31 / NGC 532），不得替猜一个名字；resolve_name 的 `stable_uri=f"best://nss/solve?obj={name}"` 会把原文写进血缘，编名即污染溯源。
- `ra`（cone_search 必填）：无值。单位口径 **度（deg, ICRS）**；`src/scripts/guards.py:validate_coordinate` 限 `0 <= ra < 360`（左闭右开，360 与 0 同向）。
- `dec`（cone_search 必填）：无值。单位 **度（deg）**；同一守卫限 `-90 <= dec <= 90`（两端都闭，±90 是合法天极）。
- `radius_arcsec`：无值。单位口径 **角秒（arcsec）**，不是度——`validate_search_radius` 要求 `>0` 且 `<= 18000`（18000″ = 5°，换算：5° × 3600″/° = 18000″）。cone_search 缺省 180″（=3′），crossmatch_batch 缺省 3.0″。无输入即无换算过程可做。
- `catalog`：无值。合法取值是 `CATALOG_PATHS` 的 12 个裸 id（ps1 / stripe82 / gaia_dr3_18 / jplus_dr3 / smss_dr4 / landolt / uss_dr1 / splus_dr4 / scr_galah / scr_lamost / xpsp / dr3xpcorr）；cone_search/crossmatch_batch 缺省 `ps1`。注意 std / calib / other 是**导航组不是表**。
- `coords`（crossmatch_batch 必填）：无值。每项须含数值型 `ra`/`dec`（度），可选 `id`。
- `sqlid`（count / fetch_page 必填）：无值。形态 `^s?\d+$`（如 `s3898` 或 `3898`），来自上一轮两阶段查询的产物；本会话无前序调用，不存在可续会话。
- `page` / `page_size`：无值（且无 sqlid 时无意义）。page ≥1，page_size ∈ [1, 10000]（`MAX_FETCH_PAGE_SIZE`）。

结论：无任何一项可安全取值，**没有任何单位换算需要执行**；"查源"的半径/坐标口径只能等用户补齐后再按上述 arcsec/deg 口径落参。

- `src/ai_tools.py`：`TOOL_NAMES = ("resolve_name","list_catalogs","describe_catalog","cone_search","crossmatch_batch","count","fetch_page")`；`ToolBox.resolve_name(self, name)`、`cone_search(self, ra, dec, radius_arcsec=180.0, catalog="ps1", ...)`、`crossmatch_batch(self, coords, catalog="ps1", radius_arcsec=3.0, ...)`、`count(self, sqlid)`、`fetch_page(self, sqlid, ...)` —— 五个工具各有必填项，用户一个都没给。
- `src/ai_tools.py` crossmatch_batch docstring 原文：**"缺失坐标绝不能静默当作 (0,0) —— 那是一个真实天区"**，即"缺参不编造"的仓内硬依据。
- `references/tools.schema.json`：`resolve_name` required `["name"]`；`cone_search` required `["ra","dec"]`；`crossmatch_batch` required `["coords"]`；`count`/`fetch_page` required `["sqlid"]`；`additionalProperties:false`。零请求工具只有 `list_catalogs`/`describe_catalog`，二者答的是"有哪些星表/某表列元数据"，不是"那个源"。

- `src/protocol_catalog_tables.py`：`CATALOG_PATHS`（12 张可查表）/`CATALOG_GROUPS`（`std`/`calib`/`other` 为导航组，"组名绝不能当表名查询"）/`CATALOG_ALIASES={"gaia_dr3":"gaia_dr3_18"}`。
- `static/core/output-format.md`：`source_id` 是**星表原始 ID 字符串**（ps1 实测 19 位整数串，如 `2449913804508125824`），不是 `BEST001` 这类占位符——禁止编造 source_id。

## 陷阱与错法
1. **替用户猜天体名去 `resolve_name`**：原话没给名字，"那个源"不是 Sesame 可解析名。猜错会得到 E_NAME_UNRESOLVED，且血缘里落下一个用户从未说过的 `obj`（`stable_uri` 带原文），污染可复现引用。
2. **编造 ra/dec 去 `cone_search`**：最典型是把"缺"当 (0,0) 静默查赤道原点——`crossmatch_batch` docstring 明写这是真实天区，绝不能当缺省；cone_search 的 `validate_coordinate` 也只挡值域、挡不住"编造一个合法值"。
3. **编造 source_id**：工具面 7 个原子工具里**根本没有"按 source_id 查"的入口**（精准下载在下载栈 `src/download_precise.py` 的 `PreciseDownloadJob`，不在 ai_tools 工具面）；且 source_id 是 19 位原始 ID 串，凭空给一个就是伪造标识。
4. **拿 `list_catalogs`（零请求）硬答**："能用零请求工具回答的不发请求"≠"用零请求工具乱答"。list_catalogs 答的是"有哪 12 张星表"，与"查那个源"是两回事，属答非所问。
5. **把"那个源"当导航组名**（std/calib/other）去 describe_catalog/cone_search：组名不是可查询表，`/std/q` 返回 Internal Server Error、带组前缀路径返回 `{"error":"Not Found"}` 软 404（HTTP 200 门禁看不见）。
6. **把"源"理解成"数据源"（NADC BEST 站点）**：那也不是"查源"——站点连通/健康走 `python ops/astro_best_cli.py doctor`（离线自检），不是查询工具；更不能因语义模糊就转 `astro-catalog`（BEST 自身数据不委派，他 skill 无 BEST 端点）。
7. **单位误用**：即便用户随后补"半径 5"，也须按 skill 口径判为角秒（5″）还是度（5°=18000″，恰在 `validate_search_radius` 上限）；把度当角秒传会得到 360 倍半径或 0 行（tools.schema.json radius 描述原文警告）。
