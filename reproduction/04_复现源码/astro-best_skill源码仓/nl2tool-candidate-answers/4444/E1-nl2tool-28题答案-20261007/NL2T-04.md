# NL2T-04
## 用户原话
> 查 RA=10.68、Dec=41.27、半径 60″ 内的 ps1 星。
## 判定
直接调用 —— 中心坐标、半径、目标星表三项俱全且与 skill 声明的单位口径逐字一致，无缺参可编，直接走 `ToolBox.cone_search`。
## 期望调用
```python
from src.ai_tools import ToolBox

# 单锥形检索：一个中心点 + 半径，走服务端原生 pos.type=cone（非 crossmatch 批量路径）
ToolBox().cone_search(
    ra=10.68,             # 赤经，十进制度（ICRS），原话直取
    dec=41.27,            # 赤纬，十进制度（ICRS），原话直取
    radius_arcsec=60.0,   # 检索半径，角秒；原话「60″」即 60 角秒，显式覆盖缺省 180
    catalog="ps1",        # 裸星表 id（Pan-STARRS All-Sky）
)
```
## 参数与换算
- `ra=10.68`：原话已给，单位本就是十进制度（skill 声明 ra/dec 一律为度，见 `describe_catalog` 的 `units_note`：「ra/dec in degrees」）。10.68 ∈ [0, 360)（`validate_coordinate` 左闭右开），通过。**不做时角/六十进制换算**——10.68 不是 10h…，无需乘 15。
- `dec=41.27`：原话已给，十进制度。41.27 ∈ [-90, 90]（两端闭），通过。
- `radius_arcsec=60.0`：原话「半径 60″」中 ″ 是角秒（arcsecond）符号，直接取 60；skill 半径统一以角秒计（`validate_search_radius`），故**无需换算**。60 > 0 且 ≤ 18000（5° 上限），通过。必须显式传：工具缺省 `radius_arcsec=180.0`，不传就会变成 180″=3′，与用户要的 60″ 差 3 倍。
- `catalog="ps1"`：原话「ps1 星」→ 星表 id `ps1`（`CATALOG_PATHS["ps1"]="ps1/q"`，显示名 Pan-STARRS All-Sky，站点 table id 346）。`ps1` 同时挂在 `CATALOG_GROUPS["calib"]` 下，但**分组前缀不是可查询路由**，必须传裸 id。
- 其余参数走缺省：`columns=None`（用户未指定列 → 全列）、`sort=None`、`order="asc"`、`nearest_only=False`（用户未要求只取最近一颗）、`max_rows=1000`。用户未提列投影，故不传 `columns`，不凭空构造列名。

## 陷阱与错法
- **半径单位错**：把 60″ 当成 60 度传（`radius_arcsec=60` 若误以为单位是度而改写）——schema 明确警告「传度会得到 0 行或 360 倍半径」。正确做法是 60″ 直接填 `60.0`，不做任何换算。
- **漏传半径**：不传 `radius_arcsec` 会落到缺省 180″，静默放大 3 倍天区，结果集与用户要求不符。
- **选错工具**：`crossmatch_batch` 是「一次提交多坐标做批量匹配」的路径（`coords: list[dict]`，缺省半径 3″）；本题只有一个中心点，应走 `cone_search`，不是 crossmatch，也不是先 `resolve_name`（用户已给坐标，不是天体名）。
- **星表名带分组前缀**：传 `catalog="calib/ps1"` 会命中站点软 404（HTTP 200 + `{"error":"Not Found"}`，见 `CATALOG_PATHS` 上方注释），必须用裸 id `ps1`。
- **多此一举地先 describe_catalog**：schema 建议「构造列约束前先 describe」，但本题未指定任何列/约束，无需先查列清单，直接锥搜即可（describe 是零请求的，但非必需）。
- **编造参数**：用户没给列投影、排序、最近邻偏好，不得凭空补 `columns`/`sort`；这些留空由缺省处理。
- **误判为需澄清**：坐标/半径/星表齐全，无歧义，不应反问。
