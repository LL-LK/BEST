# NL2T-08
## 用户原话
> 结果被截断了，继续取下一页。
## 判定
先澄清再调用——"续下一页"对应 `fetch_page`，但其 `sqlid` 为必填且是易失会话号，本独立单轮手上没有上一轮信封（无 sqlid、也不知上一页页码），必须先向用户索取这两个值才能发调用。
## 期望调用
```python
# 澄清前不发任何调用：fetch_page 的 sqlid 为必填（无缺省），单轮内无从获得，
# 且"下一页"的页码也未知。用户补齐 sqlid 与上一页页码后，期望调用形如：
ToolBox().fetch_page(
    sqlid="<上一轮信封 provenance.session_id 的值，形如 s3898 或 3898>",  # 必填；禁止编造
    page=<上一页页码 + 1>,                                                # 下一页；禁止用缺省 1（那会重取第 1 页）
    page_size=1000,                                                       # 缺省 1000；上限 10000
    catalog="",                                                           # 留空，由协议层按 sqlid 推断
    max_rows=None,                                                        # 缺省取 page_size
)
```
## 参数与换算
- `sqlid`：**必填、不可编造**。取值只能来自上一轮 `cone_search` / `crossmatch_batch` 信封的 `provenance.session_id`（`src/ai_tools.py` 在 `cone_search`/`crossmatch_batch`/`fetch_page`/`count` 处把 sqlid 记入 `session_id`）。本单轮没有上一轮结果，故为**缺失**。形态约束 `^s?\d+$`（`references/tools.schema.json` fetch_page.sqlid），即 `s3898` 或 `3898` 皆可。
- `page`：**未知，需澄清**。语义是"页码（1 起）"，用户说"下一页"= 上一页页码 + 1；缺省 1 是**首页**，直接用会重复拉第 1 页，不是续页。
- `page_size`：默认 `1000`（工具签名与 schema 一致）。用户未指定；若要严格续接上一轮分页节奏，应取上一轮同值，故也列入可选澄清项。边界 `1 <= page_size <= MAX_FETCH_PAGE_SIZE(=10000)`，越界 → `E_INVALID_INPUT`。
- `catalog`：默认 `""`，**不猜**。签名注明"留空由协议层按 sqlid 推断"，只有少数站点行为才需按表路由，故本单轮不填、也不必问。
- `max_rows`：默认 `None` → 取 `page_size`（单次调用不跨页累积）。用户未要求跨页累积，保持缺省。
- 单位换算：**本题无单位换算**。`sqlid`/`page`/`page_size`/`max_rows` 均为无量纲计数（count）；不存在 deg↔arcsec 之类的角度换算（那是 `cone_search` 的 `radius_arcsec` 口径，与本题无关）。
## 关键依据
- `src/ai_tools.py:710` `ToolBox.fetch_page(sqlid, page=1, page_size=1000, catalog="", max_rows=None)` —— `sqlid` 为**首位必填**参数，无缺省；`page` 缺省 1。
- `src/ai_tools.py:83` `MAX_FETCH_PAGE_SIZE = 10000`（与 `references/tools.schema.json` 的 `maximum` 逐字对齐，越界在工具边界 fail-closed → `E_INVALID_INPUT`）。

- `references/tools.schema.json` envelope.provenance.session_id 描述："服务端 sqlid（**易失，仅用于续页**）"；`stable_uri` 为可复现引用但**不含 sqlid**（`best://ps1/cone?ra=..&dec=..&sr=..`），故无法从 URI 反推 sqlid。

## 陷阱与错法
1. **凭空编 sqlid**（如随手写 `s3898`）：违反"缺参数不编造"与 stance 的"不伪造 job_id"。sqlid 是服务端易失会话号，编出来的会拉到别人的会话或直接软 404。
2. **从 `stable_uri` 反推 sqlid**：错。`best://` 是内容寻址 URI（坐标/星表入 URI），`provenance.session_id` 与 `stable_uri` 是两个独立字段，前者才是续页句柄；URI 里没有 sqlid。
3. **用缺省 `page=1` 直接调**：把"下一页"退化成"重取首页"，表面成功、实则重复拉数据。必须用上一页 + 1。
4. **改去重跑 `cone_search` / `crossmatch_batch`**：错。会新建一个会话（新 sqlid），既浪费一次 POST，也不是"续页"；何况本单轮连原查询坐标/参数都没有，无从重跑。
5. **猜 `catalog`**：不必也不该。`catalog` 可空，协议层按 sqlid 推断；乱传反而可能触发按表路由的错误分支。
6. **误判为"拒绝/超能力"**：BEST 分页续取正是本 skill 的主理 in-scope（不委派 astro-catalog），能力在边界内，只是**缺参数**——正确处置是澄清，不是拒绝。
7. **误判为"可直接调用"**：若判成直接调，就会在无 sqlid 的情况下编造参数，属于 fail-open 的静默错。
8. **`page_size` 越界**：传 > 10000 会 `E_INVALID_INPUT`（`MAX_FETCH_PAGE_SIZE` 边界在此收口，协议层不校验）。

2. **上一页页码**：上一轮取到的是第几页？（下一页 = 该页码 + 1；若不知，请确认是否从第 1 页起算、下一页取第 2 页。）
