2. `cone_search`  参数: {"ra": 180.0, "dec": 30.0, "radius_arcsec": 60, "catalog": "splus_dr4", "columns": ["splus_dr4_id", "splus_dr4_ra", "splus_dr4_dec", "splus_dr4_r_pstotal", "splus_dr4_e_r_pstotal"], "max_rows": 1000}

## 二、给用户的回答

查询已发出：中心 RA = 180.0°、Dec = 30.0°（ICRS），半径 60 角秒，星表 **`splus_dr4`**，取 r 波段。

**列名先查了 `describe_catalog` 才写**——S-PLUS 的星等列不叫 `r` 也不叫 `rmag`，是 **`splus_dr4_r_pstotal`**（12 个波段的 petrosian total 星等，误差列是同名加 `e_` 前缀：`splus_dr4_e_r_pstotal`）。猜列名的话站点不报错，只会回一列空值。

**但我要先给你一个预警：这次大概率 0 行，而且不是查错了。** `splus_dr4` 是 S-PLUS DR4 的精测定标子集，**只覆盖南天 survey 天区**。你这个位置 Dec = **+30°**，是北天，落在它的 footprint 之外。天区外查不到源是**正常结果**，站点会给 HTTP 200 + 表头 + 0 数据行，形态上跟"真的没有源"无法区分——所以别把 0 行读成"这个位置没有 S-PLUS 源"，它根本不在 S-PLUS 观测范围里。同样的情况也适用于 `smss_dr4`（也只覆盖南天）。

**要 S-PLUS 的 r 波段，只有两条路：**

1. **换到南天位置查**。S-PLUS 主巡天在南天，给一个 Dec ≲ −10° 的坐标，我能查给你（留档实测 (10°, −70°) 300″ 锥有 206 行，覆盖确认）。
2. **接受"近似 r 波段"**。BEST 里北天有覆盖的是 `ps1`（g/r/i/z/y），它的 `ps1_rpsf` 是 Pan-STARRS 的 r 波段。**注意这不是 S-PLUS 的 r**：两者滤光片不同、零点不同，星等差通常在 0.01–0.05 量级，做精确颜色或定标时不能用它替代。

**另外提一句口径**：S-PLUS 的 `*_pstotal` 是 **petrosian 总星等**（不是 PSF、不是固定孔径），对延展源更合适、对点源会偏暗一点点；而且这一列有 `>= 99.0` 的缺测哨兵，做筛选时得先剔掉，否则会把"没测到"当成"极暗"。

请选一条：**给南天坐标**（我按 S-PLUS 真数据查），还是**接受 ps1 的 r 波段近似**（我立刻在原锥里给你）。
