## 二、给用户的回答

**"一份标准星清单"这种全量导出，BEST 这边不支持**，原因有三层，我说清楚，然后给你能走的路。

**不支持什么：**
1. **`std` 不是一张表**，它是导航分组，直接查会拿 Internal Server Error。标准星实际分布在 `landolt`（45712 行）、`scr_galah` / `scr_lamost`（各 137 列）、`xpsp`（287 列）里，"一张清单"这个对象在物理上不存在。
2. **无约束整表导出不可行**：站点对无约束查询会内联几百 MB 的 CSV，`getcount` 在无约束会话上会超时（>60 s）。这不是"慢"，是会直接失败。
3. **我手上 7 个工具没有导出/落盘能力**（只有 resolve / list / describe / cone / crossmatch / count / fetch_page），也没有"给我前 N 万行全表"这种接口。

**能走的替代路径：**
- **A. 按天区给（最实用）**：告诉我天区（RA/Dec + 半径）和上限（比如 5000 行），我用 `cone_search` 打 `landolt` 或 `scr_*`，分页取回给你。标准星是拿来定标的，通常你真正要的是"我观测天区附近的标准星"，这个尺度下几百到几千行足够。
- **B. 按名字/位置逐个取**：给一串标准星名或坐标，我用 `resolve_name` + 小半径锥搜逐个取定标值（`landolt_umag/bmag/vmag/rmag/imag` 与改正值）。
- **C. 整表下载走官网**：BEST 站点有 Catalog 区整表下载，需要 NADC 账号登录（`/data/best/jobs` 一侧的身份层，OAuth 是第二跳）。这条不在对话工具面里，得你在网页上操作。

**另外先确认一件事**：你要的"标准星"是哪一套？口径不同清单完全不同——
- **Landolt 经典标准星**（UBVRI 定标，`landolt`）——传统测光定标用；
- **SCR 标准星**（基于 Gaia XP 的 2 亿+ 星，`scr_galah`/`scr_lamost`/`xpsp`）——只含 4500–6500 K 矮星、Av<0.1，精度 grizy 类 0.001–0.005 mag；
- **你自己的候选源**——那其实是"批量匹配"，走 `crossmatch_batch`。

告诉我"哪一套 + 什么天区 + 上限"，我直接跑。
