## 二、P1 那条命中：复核为措辞撞车

审计器报：

```
✗ [P1 sb3] NL2T-07 clarify.options 原文出现在: answers/NL2T-07.md
```

逐字比对后，命中的最长公共片段只有这些：

| 片段 | 长度 | 能不能从可见面得到 |
|------|------|-------------------|
| `BEST 没有 ZTF 星表` | 14 字 | **能**：`skill/` 里有 12 张可查表清单，数一遍就没有 ztf |
| `ztf_g_g_xpsp` / `ztf_r_r_xpsp` / `ztf_i_i_xpsp` | 各 12 字 | **能**：`skill/src/protocol_catalog_tables.py` 里就是这几个列名 |
| `resolve_name` | 12 字 | **能**：`题卷/TOOLFACE.md` 的七个工具之一 |

实测确认：

```
sb3/skill/src/protocol_catalog_tables.py  ← ztf_g_g_xpsp / gztf / rztf / iztf 全在
sb3/skill/rag/knowledge/best_practices.yaml ← "12 张"
```

而且 sb3 的措辞与标注**并不相同**：标注写「两张标准星交叉表」「合成测光」「CDS Sesame」，
答案写「交叉匹配列」「从 Gaia Archive 查」——它走的是另一条推理路径。

**定性：撞车，不是泄漏。** 标注的 `clarify.options` 本身就是"从 skill 事实推导出的必然表述"，
任何认真读过 `protocol_catalog_tables.py` 的模型都会写出高度相似的句子。

> 审计器的探针是"含汉字 ≥8 字的原句"，没有排除"可见面本来就有的子串"。
> 真正的修法：**探针 = 标注原文 − 可见面文本**（差分探针）。否则每换一批答案都要人工复核一次。

## 三、真正值得处理的问题：跨箱 `answers/` 互相可读

三个箱的 `answers/` 对模型组都是开放读：

```
sb1\answers    Allow CodexSandboxUsers ReadAndExecute    无 Deny
sb2\answers    Allow CodexSandboxUsers ReadAndExecute    无 Deny
sb3\answers    Allow CodexSandboxUsers ReadAndExecute    无 Deny
```

**模型的三个进程同属 `CodexSandboxUsers`，ACL 无法区分"哪个箱的模型"** ——
也就是说：跑 sb2 时，它的模型进程**可以读到 `sb1/answers` 和 `sb3/answers` 的全部内容**。

这次就正好撞上风险窗口：

| 时间 | 事件 |
|------|------|
| 13:20 | sb1 / sb3 的 r4 答案落盘（**至今未归档，仍在磁盘**） |
| 14:14–14:28 | sb2 重跑（r5）—— **此时 sb1/sb3 的答案对它可读** |

**实际没有被利用**：sb2-r5 与 sb1/sb3-r4 的答案相似度只有 0.24 / 0.27，也没有任何跨题引用。
但这纯属运气——不是防线起效。

### 为什么现有目录锁没覆盖到

`_exec`、`题卷/per_task`、`净化日志.txt` 都锁了，唯独 `answers/` 不能锁：
它必须对本箱可写，而 ACL 只能按"组"授权，一旦给组开放写，同组的另两箱也一并开放。

## 四、建议

### 1. 跑批前把另两箱的 `answers` 关掉（立即可做）

```powershell
# 跑 sb2 前：把 sb1 / sb3 的答案对模型组关掉
icacls "<USER_HOME>\E1-答题沙箱-2026-10-17\sb1\answers" /deny "CodexSandboxUsers:(OI)(CI)(R)"
icacls "<USER_HOME>\E1-答题沙箱-2026-10-17\sb3\answers" /deny "CodexSandboxUsers:(OI)(CI)(R)"
```

跑完再 `/remove:d`。**代价**：每次切箱要手动改两次 ACL，容易忘。

### 2. 更稳的做法：一箱一跑，跑完立即归档（现有流程）

只要"另两箱的答案已归档清空"，风险窗口就是零。**本次风险正是因为 sb2 单独重跑、
而 sb1/sb3 的 r4 答案还留在原位。**

→ 所以规则应该是：**重跑任何一箱之前，先把另两箱的答案归档清空**（或至少 deny）。

### 3. 根本解法：`answers/` 移出沙箱

每箱只保留一个空的 `answers/`，模型写完后由执行会话搬走。但这样模型就看不到自己的
`_答题模板.md` 和 `RUN-INFO.md`，需要一并调整 `SANDBOX-RULES.md`。改动较大，不急着做。

## 五、审计器待修（1 处）

`audit_leak.py` 的 P1 探针应改为**差分探针**：把候选片段在 `skill/` + `题卷/` 里先搜一遍，
能搜到的（= 模型可正常获得的）从探针里剔除。否则每次都会报 `clarify.options` 撞车，
报告一出现红条，真正要看的东西就被淹了（这和它文档里吐槽的"第一版 2607 条噪音"是同一类问题）。

## 六、结论

- **answer key（anti_patterns / reason_code / gold 轨迹）没有泄漏** —— 81 条 P0 探针零命中。
- **模型没有越界读取** —— 84 份答案里没有一处提到 `_exec`、`_lock`、`tasks.yaml` 或标注字段。
- **三箱之间没有串题** —— 答案相似度低，无跨题引用。
- **但存在一条真实通道**：`answers/` 跨箱可读。本次未被利用，属于流程侥幸。
- **审计器有一条假阳性**，建议改差分探针。
