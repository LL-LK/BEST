# 构建器说明（给维护者，不是给被测模型）

## 一、这东西解决什么问题

上一版沙箱（2026-10-14）是**手工搭的**，没有构建脚本。后果是：

1. **无法一键重建** —— 三箱"逐字节一致"这层保证只能事后比对，歪了也查不出是哪一步歪的；
2. **净化粒度错了** —— 用整行替换处理 README.md 的仓库文件树，
   结果 1141 行里 815 行变成占位符（71%），文件反而从 1280 膨胀到 1409 行，几乎不可读；
3. **台账守卫能被绕过** —— "未填"检测只认 `（填`，占位符写成 `（待填…` 就静默通过；
4. **preflight 长期多算一份** —— 把台账 `RUN-INFO.md` 当成了答案，报 29/28；
5. **结构化文件净化后能不能解析，没人验全** —— 只抽样查了 3 个文件，
   漏了 `contracts/pipeline-stage.contract.yaml`，而它恰好会被整行替换打碎。

## 二、怎么用

```bash
# 干跑（只报计划，不落盘）
python _builder/build_sandboxes.py

# 构建三个沙箱（已存在则先解封再重建）
python _builder/build_sandboxes.py --apply --force

# 构建 + 上 ACL 硬锁（拒绝 Everyone 写入/删除）
python _builder/build_sandboxes.py --apply --force --acl

# 指定源仓库（缺省按 KNOWN_REPO_CANDIDATES 自动探测）
python _builder/build_sandboxes.py --apply --repo <仓库根>
```

构建完对每个沙箱跑：

```bash
python sbN/_lock/sandbox_lock.py seal --acl
python sbN/_lock/sandbox_lock.py verify
```

一键验收（含一致性 + 隔离 + 负向测试）：

```bash
python _builder/verify_all.py
```

## 五、净化两级

1. **区块级**：README.md 的 `## 文件树 SSOT` 整段剥离（那是仓库导航件，不是工具文档）。
2. **行级 / 片段级**：
   - `.md` `.txt` → 整行替换为 `> [已净化] …`
   - `.yaml` `.yml` `.json` `.py` `.toml` `.ini` `.cfg` → **片段级**红改（保留结构与缩进）

   被剥离的三类：题号（答案定位器）、评测目录指针、标注字段名。

   > 结构化文件为什么不能用整行替换：构建期实测 `pipeline-stage.contract.yaml`
   > 的命中行是一个**多行块标量的续行**，整行换成注释后 YAML 直接解析失败。

## 六、三道完整性防线（分工说清楚）

| 文件 | 谁生成 | 会不会被 seal 重算 | 挡什么 |
|------|--------|--------------------|--------|
| `_lock/BASELINE.sha256` | **构建器** | 否 | 任何偏离本次构建产物的状态（含"改完再封印"） |
| `_lock/MANIFEST.sha256` | `seal` | 是 | 封印之后发生的写入 |
| `_lock/ANSWERS.sha256` | `progress` | 是 | 断点续跑期间答案被改/被删 |

三者互有覆盖：单改任一个都会被另一道闸抓到；同时改需先 `unseal`，
而 `unseal` 会写进 `_lock/lock.log` 留痕。

## 七、重建纪律

**必须三箱一起重建**（构建器一次跑完三个）。只重建一箱会破坏"三次重复逐字节一致"
这层保证，那一批就不能当重复样本用了。
