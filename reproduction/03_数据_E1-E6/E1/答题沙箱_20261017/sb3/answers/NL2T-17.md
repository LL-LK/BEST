## 二、给用户的回答

这条我能做，但**缺两个维度，给了我才发查询**：

1. **天区（坐标 + 半径）**——筛"对象"必须有作用域，没有天区就是在全表上筛，那是千万行级、且 `getcount` 在无约束会话上会超时。
2. **哪张星表的 r 波段**——r 的误差列名各表不同，且系统不同、阈值含义也不同：
   - `ps1` → `ps1_rpsf` 与误差 `ps1_rpsf_err`（**推荐**，全天覆盖）
   - `splus_dr4` → `splus_dr4_r_pstotal` / `splus_dr4_e_r_pstotal`（南天）
   - `landolt` → `landolt_rmag` / `landolt_e_rmag`（标准星，稀疏）

**另外要说清一个能力边界**：我手上 7 个原子工具里，`cone_search` **没有服务端列约束参数**（没有 min/max/where 之类）。所以"r 误差 < 0.01 mag"只能在**取回列之后本地筛**，不能下推给服务端。做法是：

```
cone_search(catalog="ps1", ra=…, dec=…, radius_arcsec=…,
            columns=["ps1_ra","ps1_dec","ps1_rpsf","ps1_rpsf_err","ps1_class_star"])
```
然后本地保留 `ps1_rpsf_err < 0.01` 的行，同时**先剔除哨兵**（`ps1_rpsf` 或 `ps1_rpsf_err` 为 ≈-999/-1004 的行，那是"无测量"不是真值，否则会混进一堆假的高精度样本）。

顺带一个口径提醒：0.01 mag 这个阈值对 PS1 偏松（PS1 定标精度 1–2 mmag，多数源的 r 误差远小于 0.01），筛完可能剩下绝大多数源、区分度不高。如果你的目的是"挑高精度样本做定标"，更常用的是 0.005 或按 `ps1_rpsf` 亮度分档设阈值。

给我天区（和确认用 ps1），我直接跑并回一份"总行数 / 筛后行数 / 剔除的哨兵行数"。
