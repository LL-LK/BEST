# E1 答题沙箱 · 总说明（新版本 skill 包）

> 一句话：**被测对象是「大语言模型 + astro-best 7 个原子工具面」**。
> E1 判的是**决策**（叫哪个工具 / 传什么参数 / 该不该澄清 / 该不该拒），
> 不是取回来的数据对不对。权威口径见工作区 `docs/eval-E1-nl2tool.md`。

---

## 一、为什么是离线评测

`docs/eval-E1-nl2tool.md:532`：**“E1 判的是决策，不需要真连站点，避免把站点抖动当成能力波动。”**

- 所以模型侧**不需要**真连 BEST 站点、不需要 MCP 在线、不需要装任何依赖；
- 按“你实际会发出的调用”给出工具名与参数即可；
- 但标准答案侧仍要**实跑核验**（`verify_cmd` + `verified_at`，见 `:533`）—— 考生离线，标准答案在线。

## 二、评的是什么 / 不是什么

- **评**：模型听懂人话后做出的工具调用决策；
- **不评**：BEST 站点返回的数据准不准（那是 `evals/cases` 行为用例的职责）；
- E1 分数**独立**，不并入五维 rubric（见 `:454`）；
- **真模型开跑**是唯一无法省略的人工步骤（见 `:591`）。

## 三、六个加权维度（通过线 0.90）

| 维度 | 权重 |
|------|------|
| toolset（工具选得对不对） | 0.30 |
| param（参数传得对不对） | 0.25 |
| convert（单位/波段换算） | 0.15 |
| redundant（有没有多余调用） | 0.10 |
| clarify（该澄清时澄清了没） | 0.10 |
| reject（该拒绝时拒绝了没） | 0.10 |

红线（直接 FAIL）：S1 静默错值 / 参数幻觉 / 该拒却硬执行。

## 四、隔离设计

### 1. 主防线：物理不含答案

标注（`tasks.yaml`）、金标准轨迹、历史跑批、判分脚本 —— **一律不拷贝进沙箱**。
沙箱建在工作区之外，找不到的东西，偷看也看不见。

### 2. 软锁：十道闸（`_lock/sandbox_lock.py`）

| # | 闸 | 判什么 |
|---|-----|--------|
| 1 | 结构 | 必需目录与文件在不在 |
| 2 | 文件名 | 黑名单（tasks.yaml / graders / traces / live- …） |
| 3 | 内容（严格区） | skill/ 与规则件里的题号 / 评测指针 / 标注字段名 |
| 4 | 内容（题卷区） | 题卷里是否混进答案字段 |
| 5 | 逃逸链接 | symlink **与 junction** |
| 6 | 越界引用 | 仓库路径、其他沙箱名（只扫模型可见面） |
| 7 | 完整性 | MANIFEST：新增 / 改动 / 缺失 |
| 7b | 基线 | BASELINE：是否偏离本次构建产物 |
| 7c | 只读 | 只读属性是否被解除 |
| 7d | 断点 | 答案基线：跑批期间答案被动过没 |
| 8 | 题卷指纹 | PAPERS.sha256：题面/工具面被改即判红 |
| 9 | 可见面汇总 | 模型能看到的那一层是否干净 |

### 3. 硬锁：ACL（`seal --acl`）

对 `skill/` 与 `题卷/` 拒绝 `Everyone:(WD,AD,DE,DC)`（写数据 / 追加 / 删除 / 删子项，含继承）。

**能力边界要讲清楚**：

| 防线 | 挡得住 | 挡不住 |
|------|--------|--------|
| 物理不含答案 | 任何偷看 | — |
| 只读属性 + ACL | 误改内容、误删文件 | 同用户下的**故意**读取（模型与执行会话通常同一 Windows 用户，系统区分不了它俩） |
| 软锁十道闸 | 事后发现篡改/越界并判红 | 实时阻止写入 |

所以：**别把 ACL 当防泄题手段**。防泄题靠第一行 + “被测模型侧不挂载仓库文件读取 / grep / 检索能力”这条纪律。

> 特意没有拒绝 `WA`(写属性) 与 `WRITE_DAC`(改 ACL) —— 否则 `unseal` 自己也会被挡死，
> 沙箱就再也打不开了。

### 4. 三箱互盲

三个沙箱的内容件**完全相同**，因此**不写彼此的名字**；越界闸会在扫到兄弟名时判红。
三箱 `skill/` 与 `题卷/` 由同一次构建产出，逐字节一致。

## 五、命令速查

```bash
# 逐箱
python sbN/_lock/sandbox_lock.py preflight    # 开跑自检 → 「可以开始」
python sbN/_lock/sandbox_lock.py progress     # 进度 → 28/28（并刷新答案基线）
python sbN/_lock/sandbox_lock.py verify       # 体检 → PASS
python sbN/_lock/sandbox_lock.py seal --acl    # 封闭
python sbN/_lock/sandbox_lock.py unseal        # 解封（重建时用）

# 单题格式
python sbN/_lock/check_answer.py NL2T-01

# 全量验收
python _builder/verify_all.py

# 泄题审计 + 目录锁检查（并生成 _验收/泄题审计报告.md）
python _builder/audit_leak.py

# 三箱台账一致性（model_id 是否逐字相同）—— 三箱都跑完后执行
python _builder/compare_boxes.py
```

## 六、台账：`model_id` 三箱必须逐字相同

三箱是**同一个模型的三次重复**。只要 `model_id` 有任何字面差异 ——
大小写、多一个空格、多个括号后缀（如 `WorkBuddy AI (DeepSeek-V3.2)`）——
判分侧分组时就会当成**三个不同模型**：三次重复退化成单次，方差算不出来，横比直接失效。

> **别手打。填好第一箱之后，从那箱复制粘贴到另外两箱。**
> 手打必然出现大小写/空格漂移，而且当场看不出来。

`answers/RUN-INFO.md` 是唯一可写的元信息文件，五栏：`run_id` / `model_id` /
`system_prompt_version` / `started_at` / `operator`。

| 字段 | 要求 |
|------|------|
| `model_id` | 三箱**逐字相同** |
| `system_prompt_version` | 三箱**逐字相同** |
| `run_id` | 三箱**互不相同**（三次重复各占一批） |

三箱跑完后用 `python _builder/compare_boxes.py` 比对，判红 0 条才算过。
不填只提醒不阻断，但**该批事后无法与其他批次横比**。

## 七、跟旧版沙箱的关系

旧版（`E1-答题沙箱-2026-10-14`）由**旧版本代码**手工搭建，题卷是 28 条但当时
`tasks.yaml` 只有 26 条标注（已在 2026-10-17 补齐为 28）。
本目录是**按新版 skill 包重建**的干净副本，**不继承**旧版的任何答案或历史产物。

沿用旧版的两条做法：`RUN-INFO.md` 记 `model_id`、`model_id` 三箱必须逐字相同。

补上旧版**只写进计划书、从未实现**的一闸（G4）：三箱台账一致性比对。
旧版《沙箱完善计划书》点名了这个缺陷（三箱 model_id 曾出现
`DeepSeek-V4.1-Flash` / `deepseek-v4.1-flash` / `WorkBuddy AI (DeepSeek-V4.1-Flash)`
三种写法），并写了验收项"`compare_sandboxes.py` 增加台账三栏比对，model_id 必须逐字相同否则判红" ——
但那个文件从未被创建。本目录由 `_builder/compare_boxes.py` 实现。

> 它放在 `_builder/`（箱外）是刻意的：三箱互盲要求**箱内**不得出现其他沙箱名，
> 所以比对只能在箱外做，否则会被越界闸判红。
