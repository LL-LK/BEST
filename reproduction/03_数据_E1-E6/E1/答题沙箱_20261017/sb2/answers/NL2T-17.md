# NL2T-17

## 一、调用轨迹

无（本题不调用任何工具，理由见下）

## 二、给用户的回答

**这件事本工具面做不到服务端筛选，得说清楚原因，否则你会以为我漏了个参数。**

这 7 个工具里，能查数据的是 `cone_search` 和 `crossmatch_batch`。它们的入参只有：位置（RA/Dec/半径）、星表、列投影（`columns`）、排序（`sort`/`order`）、每锥是否只留最近邻、行数上限。**没有"列约束"入口**——也就是说没有 `where r_err < 0.01` 这种写法，我无法把筛选条件推给服务端。`count` 和 `fetch_page` 更只是计数与翻页。所以"筛误差小于 0.01"只能在**结果取回之后本地过滤**。

**还缺一个维度：你没有给天区。** 不知道在哪儿筛。请补：**坐标（RA/Dec，度，ICRS）+ 半径（角秒）**，或者给天体名（我用 `resolve_name` 解算）。

**还缺第二个维度：你没说哪张表的 r 波段。** 不同星表的 r 波段不是一回事：

| 星表 | r 波段误差列 | 口径 |
|---|---|---|
| `ps1` | `ps1_rpsf_err` | PSF 星等误差 |
| `splus_dr4` | `splus_dr4_e_r_pstotal` | petrosian 总星等误差（仅南天） |
| `stripe82` | 同 `ps1` 形态 | 仅赤道精测天区 |

**最要紧的一个坑，你必须知道**：`ps1_rpsf_err` 的缺测哨兵是 **`-999.0`**。而 `-999.0 < 0.01` 是成立的——**如果你直接按"误差 < 0.01"筛，会把所有没测光的源全部筛进来**，而且它们看起来"误差极小、质量极好"，是最坏的一种错。正确做法是两步：先剔掉 `err <= -900` 的哨兵，再判 `< 0.01`。同理，星等列 `ps1_rpsf` 的缺测是 `nan` 或约 −1000 的哨兵带，也要先剔。

另外提醒一句量级：`err < 0.01 mag` 是很严的条件，只对应**亮端**的源（ps1 里大约 r ≲ 16–17 才到这个精度），在一般天区的 60″ 锥里通常只有个位数到几十个源。如果你其实想要的是"质量好一点的源"，`err < 0.05` 更现实。

给我**坐标 + 半径 + 星表**这三项，我立刻按"锥搜 → 剔哨兵 → 按 err < 0.01 过滤"的流程跑完，把结果连同被剔掉的哨兵行数一起报给你。
