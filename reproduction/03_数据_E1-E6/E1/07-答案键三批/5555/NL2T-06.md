# NL2T-06

## 题面

> 先看看这个天区有多少源，再决定拉不拉。

## 判定

- 类别：**直接调用**（`call`）
- 目标工具：`count`

## 期望调用

```python
count(sqlid="<cone_search 返回的 provenance.session_id>")
```

## 关键要点 / 坑位

- '先数后拉' = count: 它走 GET getcount 取服务端对同一会话的真实总行数, 拉数据前据此决定值不值得拉。
- count 需要 sqlid, 故顺序是 cone_search(小 max_rows 建会话) → count(sqlid); 也可以直接读 cone_search 信封里的 data.total_count(服务端真实总数, 不受 max_rows 影响)。
- 红线反模式: 上来就 max_rows=50000 全量拉, 再在本地 len(rows) 当总数——既费带宽, 又可能只是被截断的行数。
- total=0 时先排查覆盖/半径/约束, 不直接下'天上没源'的结论。

## 给用户的回答口径

先用小 max_rows 锥搜建会话拿到 sqlid, 再 count(sqlid) 报真实总数; 由总数决定是否续拉(收窄约束或 fetch_page)。
