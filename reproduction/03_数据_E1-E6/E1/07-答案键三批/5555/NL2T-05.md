# NL2T-05

## 题面

> 我这有 1000 个坐标要匹配，帮我一次性做完。

## 判定

- 类别：**直接调用**（`call`）
- 目标工具：`crossmatch_batch`

## 期望调用

```python
crossmatch_batch(coords="[{ra, dec, id} × 1000 —— 待用户提供]", catalog="ps1", radius_arcsec=3.0, nearest_only=true)
```

## 需要澄清的点

- 1000 个坐标的具体数值(ra/dec 度)尚未给出; 未给出标准星表/匹配半径时按默认 ps1 + 3.0″ + 最近邻, 并显式声明该假设。

## 关键要点 / 坑位

- '一次性做完'的正确落点是 crossmatch_batch: 单次上传坐标表走服务端 proximity, 把 N 次线网请求压成 1 次。
- 红线反模式: 循环 1000 次 cone_search——同样的结果, 1000 倍请求数与限流风险。
- 每个元素必须含数值型 ra/dec, 缺键/非数值原地抛 E_INVALID_INPUT(缺失坐标绝不静默当 (0,0), 那是真实天区); id 缺省用输入下标兜底, 不静默造 'None' 前缀。
- 结果用 n_inputs 对照 returned_count 读匹配率; 截断则 fetch_page 续拉。

## 给用户的回答口径

先要坐标列表(或含 ra/dec 的文件解析结果), 再单次调用 crossmatch_batch; 说明本工具吃的是坐标字典列表而非文件上传, 并回报匹配率。
