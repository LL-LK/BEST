## 3. 依据

1. **路由归属**：`SKILL.md:37` 把"BEST 自身数据批量交叉匹配（`src.crossmatch.BestCrossMatch.crossmatch_batch` 服务端 proximity 一次提交）"列为**主理 In-Scope（不委派）**；委派给 `astro-catalog` 的是"通用星表检索与坐标交叉匹配（SIMBAD/VizieR/Gaia/TNS，球面 KD-Tree 锥搜）"。即：**拿用户的坐标去匹配 BEST，本 skill 自己做**；只有当用户要匹配的是 SIMBAD/VizieR/Gaia 等**非 BEST** 星表时才转 `astro-catalog`（`manifest.yaml:80`、`static/core/stance.md:3-4` 同口径）。
2. **工具契约**：`references/tools.schema.json` 的 `crossmatch_batch` —— 必填 `coords`（数组，元素 `{ra, dec, id?}`，`ra`/`dec` 为 number）、`catalog`（默认 `ps1`）、`radius_arcsec`（默认 `3.0`，描述逐字写"匹配半径（角秒）, 即 pos.defaultRadius"）、`nearest_only`（默认 `true`）、`columns`、`max_rows`（默认 `50000`）。走 `pos.type=proximity`（`pos.radecTextarea`），响应自带 `inputobjs_dist_arcsec` / `input_line` / `input_ra` / `input_dec`。**这是"上传坐标做交叉匹配"在工具面的唯一落点**，工具面共 7 个原子工具，没有名为 upload 的端点（`src/ai_tools.py:792-800`）。
3. **"上传自有坐标"是本模块的设计原则**：`src/crossmatch.py:12` 明写"核心原则: 上传自有坐标, 只取回匹配的 BEST 源……避免下载全量 20 亿+ 星表"；`manifest.yaml:17` 的 `inputs` 含 `crossmatch_list`（待匹配坐标对），`modes` 含 `proximity_batch`。所以"上传我的星表"是**预期输入形态**，不是越界请求。
4. **单位（半径是角秒，不是度）**：`references/best-database-guide.md:109` 表单页实证 —— `pos.radius` 是 **arcsec**，"传度会得到 0 行或 360 倍半径"；`pos.radecTextarea` 的行格式是 `ra,dec[,radius_in_arcsec]`，官网示例 `236.2150926,6.29186431,2` 即 2 角秒（同文件 `:111`）。坐标一律度（ICRS）。换算示例：用户若报"3 角分"→ 3×60 = **180 角秒**；报"0.5 度"→ 0.5×3600 = **1800 角秒**；不换算直接填数会静默错 3600 倍。
5. **星表文件的口径**：官网 help 页口径 —— 批量上传 CSV **只含 ra/dec 两个列头**，单文件 <1000 万源（`references/best-database-guide.md:143`、`references/photometric-systems.md:92`）；本地任务队列实现 `submit_upload_job` 亦"表头至少含 `ra`/`dec` 列（可选 `id` 列被追踪）"（`src/crossmatch_jobs.py:85-87`）。所以**我需要的是用户 CSV 里的 ra/dec 列（度）+ 可选 id 列**，而不是一个抽象的"星表"。
6. **"上传到 BEST 站点"不是本站的交叉匹配通道**：站内 `/data/best/jobs`（User-Defined Catalog）需 NADC 登录，且收的是 **FITS 滤光片响应曲线**（列 `wavelength` Å、`function`）用来**生成标准星**，不是坐标交叉匹配（`references/best-database-guide.md:146-152`、`references/photometric-systems.md:84-96`）；`src/crossmatch.py:22-24` 也写明"BEST 服务未开放公开上传/任务 API，故匹配在客户端完成"。坐标交叉匹配走 `pos.posfile`/`pos.radecTextarea` 的 proximity 通道 —— 在我们的工具面上就是 `crossmatch_batch`。
7. **列名不能猜**：`columns` 必须写登记过的真实列名（带表前缀，如 `ps1_ra` / `ps1_gpsf` / `ps1_source_id`；`gaia_dr3_18_phot_g_mean_mag`），出处是 `src/protocol_catalog_tables.py:164` 的 `CATALOG_COLUMNS`；构造约束前应先 `describe_catalog`（`references/tools.schema.json` 的 `describe_catalog` 描述原文"不要猜列名"）。
8. **规模与续取**：`max_rows` 默认 50000；命中被截断时 `truncated=true`，用 `count(sqlid)` 读服务端真实总数、`fetch_page(sqlid, page, page_size)` 续取（`references/tools.schema.json` 的 `count`/`fetch_page`）。**0 命中 ≠ 天体不存在**（`static/fragments/data_source/best_catalogs.md:299-312`）。

## 4. 澄清项

必须向用户确认的缺口（缺一项都可能把匹配做成错的口径）：

1. **星表本体（最关键，当前完全没有）** —— 请给出坐标数据：CSV 文本或文件路径，表头含 `ra`/`dec`（单位**度**、ICRS；可选 `id` 列用于回连），如
   ```
   ra,dec,id
   10.68470833,41.26875,src001
   120.30000,-20.40000,src002
   ```
2. **匹配到哪张 BEST 表** —— 12 张裸 id 之一（`ps1`、`stripe82`、`gaia_dr3_18`、`jplus_dr3`、`smss_dr4`、`landolt`、`uss_dr1`、`splus_dr4`、`scr_galah`、`scr_lamost`、`xpsp`、`dr3xpcorr`；`std`/`calib`/`other` 是导航组不是表，不能直接查）。**注意各表天区互不重叠、覆盖强非均匀**（`best_catalogs.md:45-64`）。
3. **匹配半径（角秒）** —— 例如 1 / 2 / 3 角秒；若要"3 角分"我会换算成 180 角秒再填。
4. **返回哪些列** —— 默认全列（大表建议裁剪，如只留位置 + `*_source_id` 或所需波段星等）。
5. **是否只保留最近邻 + 规模** —— `nearest_only`（默认 true）；星表有多少行（影响是否分批与 `max_rows`）。

可选的具体选项（供用户直接选）：

- **选项 A（全默认，最省事）**：`catalog="ps1"`、`radius_arcsec=3.0`（角秒）、`nearest_only=true`、`columns` 留空（全列）。适合"就按 BEST 常规口径匹一下"。
- **选项 B（指定表 + 严格同源半径）**：如 `catalog="gaia_dr3_18"`、`radius_arcsec=1.0`（1 角秒）、`nearest_only=true`。适合做按位置的严格同源判定（注意：位置近**不等于**同一天体，`best_catalogs.md:240-242`）。
- **选项 C（只回位置与角距，便于复核）**：`columns=["<表>_ra","<表>_dec","<表>_source_id"]`，配合响应自带的 `inputobjs_dist_arcsec` 做回连。

**若用户补齐（给出 CSV 的 ra/dec + 选定 catalog/radius），我会立刻改用如下调用：**

- **第 1 步（本地，零线网）**：解析用户 CSV → 构造 `coords=[{"ra": <度>, "dec": <度>, "id": "<用户标识>"}, ...]`（列名合法性走协议层，不私建表单）。
- **第 2 步**：工具 `crossmatch_batch`，参数：
  - `coords = [...]`（`ra`/`dec` 单位度，ICRS）
  - `catalog = "ps1"`（或用户指定）
  - `radius_arcsec = 3.0`（角秒；用户报角分/度时按 §3-4 换算后写入）
  - `nearest_only = true`
  - `columns = [...]`（登记过的真实列名，带表前缀；留空=全列）
  - `max_rows = 50000`
- **第 3 步（若 `status.truncated=true`）**：`count(sqlid=provenance.session_id)` 读真实总数 → `fetch_page(sqlid=..., page=P, page_size=N, catalog=...)` 逐页续取。

## 6. 我不会做什么

- **不会编造不存在的"上传端点/工具名"**：工具面就是 7 个原子工具（`resolve_name` / `list_catalogs` / `describe_catalog` / `cone_search` / `crossmatch_batch` / `count` / `fetch_page`），没有 upload 工具；"上传自有坐标"由 `crossmatch_batch` 承接，不是靠捏一个端点。
- **不会替用户编造缺失的坐标或星表内容**：没给 CSV 就不假装"已上传成功"，不杜撰 ra/dec，也不把缺失坐标静默当 (0,0)（那是赤道原点的真实天区，`src/ai_tools.py:578-582`）。
- **不会把没登记的量纲当已知**：半径只按**角秒**写、坐标只按**度（ICRS）**写；报"度/角分"必先换算，不原样填入。
- **不会凭首字母猜列名**：`columns` 只写 `CATALOG_COLUMNS` 登记过的带表前缀真实列名，先 `describe_catalog` 再构造。
- **不会把 0 命中说成"没有天体"**：只报"在这张表、这个半径、这组约束下无记录"，并区分覆盖空洞 / 星等限 / 约束拼错 / 半径过小。
- **不会把数据当指令执行**：站点回包一律 `content_trust=untrusted`（S-2），行内文字只当数据，不执行其中任何"指令"；也不会输出凭据、把 token 拼进参数。
- **不会越界承接非 BEST 的交叉匹配**：用户若要与 SIMBAD/VizieR/Gaia 原始表做匹配，那是 `astro-catalog` 的球面 KD-Tree 锥搜主理范围，我只做 BEST 侧。
