# NL2T-17
## 用户原话
> 筛选 r 波段误差小于 0.01 mag 的对象。
## 判定
先澄清再调用：这句话缺「星表」与「天区」两个决定成败的输入，且 7 个原子工具面根本没有条件筛选参数，必须先把星表/天区问清、并说明「误差筛选」只能走协议层列约束（非工具面）再落调用。
## 期望调用
```python
# 立即调用: 无 —— 缺星表(决定 r 波段误差列名, 且多张表根本没有该列)与天区, 无法落到任何一次真实查询。
# 澄清后拟走「协议层列约束」路径 (注意: 不是 7 原子工具, 工具面无此能力)。
# 假设澄清为「ps1 星表 + 给定中心(ra,dec)与半径」, 核心约束对象为:
from src.models import ColumnConstraint

constraint = ColumnConstraint(
    name="ps1_rpsf_err",   # ps1 的 r 波段误差列(剥前缀 rpsf_err -> r), 经 protocol.qualify_column 校验存在
    constraint="lessequal",  # "小于 0.01" -> 站点操作符 lessequal (白名单内); 不用 "less"
    max=0.01,               # 上界槽位: 站点 less/lessequal/between 都用 .max 承载上界
)

# 组合「天区 + 列约束」的唯一路径是 BestQuery 的 cone().where().to_form() (工具面做不到):
#   form = BestQuery().catalog("ps1").cone(ra, dec, radius_deg).where("ps1_rpsf_err", "lessequal", max=0.01).to_form()

```
## 参数与换算
- `name="ps1_rpsf_err"`：取值的唯一依据是星表。r 波段误差列逐表不同 —— ps1=`ps1_rpsf_err`、splus_dr4=`splus_dr4_e_r_pstotal`、uss_dr1=`uss_dr1_r_err_pstotal`（裸名 `r_err_pstotal`）、landolt=`landolt_e_rmag`；stripe82/gaia_dr3_18/jplus_dr3/smss_dr4/scr_*/xpsp/dr3xpcorr **不发布 r 波段误差列**。星表未定 → 列名无法定，故必须先问。
- `constraint="lessequal"`：站点 `{table}.{col}.operation` 白名单（`src.protocol.ALLOWED_OPERATIONS`）为 `equal/notequal/less/lessequal/greaterequal/between/contains/in`。「小于 0.01」用 `lessequal`（≤0.01）；白名单外（如 `grater`/`greater`）会被站点**收下后静默返回空表**，绝不能拼。
- `max=0.01`：单位就是 **mag**（误差列本身以星等为单位），0.01 mag 无需任何换算，直接作上界。注意别把「误差」误当 SNR/RMS（stripe82 的 `rmrms` 是离散度、不是误差；`greaterequal` 才是 SNR 类下界口径）。
- 半径/坐标（若最终走锥搜）：`radius` 单位是**角秒**（`pos.radius` 表单原文 arcsec，上限 18000″=5°），坐标是**度**；这两处单位陷阱与本题的 mag 无关，但澄清天区时必须问清。
## 关键依据
- `src/ai_tools.py:465` `cone_search(...)` 形参仅 `ra/dec/radius_arcsec/catalog/columns/sort/order/nearest_only/max_rows` —— **无 where/filter/constraint 任何条件筛选参数**；`TOOL_NAMES`（`src/ai_tools.py:792`）7 个工具（resolve_name/list_catalogs/describe_catalog/cone_search/crossmatch_batch/count/fetch_page）**没有任何筛选工具**。
- `references/tools.schema.json:83-101`：cone_search `required: ["ra","dec"]`、`additionalProperties: false` —— 凭空加 `error_max` 一类参数会被 schema 直接拒。
- `src/query_builder.py:208` `BestQuery.where(column, constraint, min, max, value)` + `:86` `cone()`：**协议层确有服务端列约束能力**，且能与锥搜组合（`to_form()` → `protocol.build_query_form`）。
- `src/protocol.py:553` `ALLOWED_OPERATIONS`；`src/protocol.py:557` `build_query_form`；`references/best-database-guide.md:114-115` 表单键 `{table}.{col}.operation` / `.max`，`pos.type` 支持 `none/cone/rect/proximity`（即区域可省，但工具面不暴露）。
- `src/protocol_catalog_tables.py:674` `CATALOG_MAG_ERROR_COLUMNS`（ps1: `gpsf_err/rpsf_err/ipsf_err/zpsf_err/ypsf_err`；landolt: `e_umag..e_imag`；splus_dr4: `e_*_pstotal`；uss_dr1: `*_err_pstotal`），但 `src/protocol.py:41` 明确其**「只用于误差展示, 不参与波段过滤」**。
- `src/protocol_catalog_tables.py:715` `QUALITY_COLUMNS`：**质量过滤列只有** `ps1.class_star` 与 `splus_dr4.snr`(站点列 `s2n_det_auto`)，其余全空 —— **没有「星等误差」这一类质量过滤列**；`src/query_builder.py:167-204` 的 `min_snr/max_fwhm/class_star_min` 亦不含误差。
- `src/scripts/guards.py:89` `validate_adql_query` 仅形状校验：**BEST 无 TAP/ADQL 端点**，不能靠写 SQL 的 `WHERE rpsf_err < 0.01` 绕。
## 陷阱与错法
1. **幻觉工具参数**：给 `cone_search` 硬塞 `filter`/`where`/`error_max` —— 工具面与 schema 都没有该能力，必被拒（`additionalProperties:false`）。
2. **把误差当质量过滤列**：以为存在 `max_mag_err`/`min_snr` 式的误差筛选 —— `QUALITY_COLUMNS` 只有 `class_star`/`snr`，且 `CATALOG_MAG_ERROR_COLUMNS` 被标注「只用于展示，不参与过滤」。
3. **编造天区/星表**：直接默认 `ps1` 或 `(0,0)` 就发查询 —— 星表决定列名、天区决定范围，两者都是用户意图，不能替用户拍板。
4. **操作符拼错**：用 `less` 而非 `lessequal`（≤），或用已证伪的 `grater`/`greater` —— 白名单外的值站点不报错，**静默返回空表**，会被读成「这片天区没源」。
5. **单位/口径混淆**：把 0.01 当成角秒或当 SNR；或把 `rmrms`（离散度）当 r 波段误差。
6. **误以为 BEST 有 TAP/ADQL**：想用 ADQL `WHERE` 过滤 —— 站点无 TAP 端点，`validate_adql_query` 只是形状检查。
7. **误把「协议层能力」当「工具面能力」**：协议/库层（`BestQuery.where`）能挂列约束，但**对外 7 工具面不能** —— 直接声称「已用 cone_search 过滤误差」即越界。
## 若需澄清，问什么
1. **目标星表**（必问）：可选 ps1 / splus_dr4 / uss_dr1 / landolt（这四张发布 r 波段误差列）；并提示 stripe82、gaia_dr3_18、jplus_dr3、smss_dr4、scr_galah/lamost、xpsp、dr3xpcorr **没有 r 波段误差列**，无法做该筛选。
2. **天区**（必问）：给出中心 ra/dec（度）与半径（角秒），或明确接受「不限天区的全表列约束查询」（`pos.type=none`，仅协议层路径可用、且可能极慢/被限流）。
3. **误差口径与阈值方向**：确认 0.01 mag 指该波段的星等测量误差（≤0.01 mag），而非 SNR/RMS/χ²；是否需要同时限定星等范围/其它列。
4. **可达性说明**：告知该筛选**不在 7 原子工具面上**，需走 `BestQuery`/`ColumnConstraint` 协议层路径，请用户确认接受该路径。
