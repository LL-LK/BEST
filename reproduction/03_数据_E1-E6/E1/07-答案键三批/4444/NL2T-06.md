# NL2T-06

## 用户原话
> 先看看这个天区有多少源，再决定拉不拉。

## 判定
先澄清再调用：意图是「对某个天区做计数」属本 skill 正办（BEST 锥搜/计数），但「这个天区」在本会话没有任何指代物——既无坐标也无天体名，且目标星表未定，绝不能凭空编造坐标去发请求，必须先向用户澄清天区（坐标或可解析的天体名）、半径与星表后再调用。

## 期望调用
```python
# 当前无调用：天区未定义（无坐标、无天体名、无星表），不得编造 → 先澄清。
# 澄清拿到 <坐标或天体名> / <半径> / <星表> 后，按此序执行（先看数、再决定拉不拉）：
#   cone_search(ra=<澄清值>, dec=<澄清值>, radius_arcsec=<澄清值>,
#               catalog=<澄清值>, max_rows=1)      # max_rows 压到最小，只为拿总数不拉数据
#   → 读信封 data.total_count（服务端真实总数，与 max_rows 无关）
#   → 如需对同一会话二次确认：count(sqlid=<上一步 provenance.session_id>)
#   → 据此决定是否 fetch_page 续拉
```

## 参数与换算
- **天区（ra / dec）**：缺失，不可编造。取值为澄清所得；单位必须是十进制度（ICRS）。校验口径 `validate_coordinate`：ra ∈ [0, 360)、dec ∈ [-90, 90]。若用户给的是天体名（如「M31」），先走 `resolve_name(name)` 换 ICRS 坐标，不自行换算。
- **radius_arcsec**：缺失，取澄清值；**单位一律角秒**（角分/度必须换算：1′ = 60″，1° = 3600″）。校验口径 `validate_search_radius`：`0 < r ≤ 18000` 角秒（=5°，超限即拒）。工具缺省 180″（=3′），但缺省不代表用户意图，仍需确认。
- **catalog**：缺失，取澄清值。可查表只有 12 张（`CATALOG_PATHS`：ps1 / stripe82 / gaia_dr3_18 / jplus_dr3 / smss_dr4 / landolt / uss_dr1 / splus_dr4 / scr_galah / scr_lamost / xpsp / dr3xpcorr）；`std` / `calib` / `other` 只是导航分组、不是可查表。工具缺省 `ps1`，但需用户确认。
- **max_rows**：建议显式给 1（或极小值）。`cone_search` 的 `data.total_count` 是服务端真实总数、不受 `max_rows` 影响，故用小 `max_rows` 即可「只看数、不拉数」，正合「先看看有多少源，再决定拉不拉」。
- **sqlid（若走 count）**：不可编造；只能取上一步 `cone_search` 信封里的 `provenance.session_id`。形态 `^s?\d+$`。

## 关键依据
- `src/ai_tools.py` — 工具面唯一出口 `ToolBox`，`TOOL_NAMES` 七个原子工具；`cone_search` 返回 `data.total_count`（服务端真实总数）与 `provenance.session_id`（sqlid）；`count(self, sqlid)` 契约明确写着「输入 cone_search/crossmatch 返回的 sqlid … 用于在拉数据前判断『值不值得拉』」——即本题意图的官方对应工具，但它**只吃 sqlid、不吃天区**，无法独立建会话。
- `src/scripts/guards.py` — `validate_coordinate`（ra [0,360)、dec [-90,90]）、`validate_search_radius`（`0 < r ≤ 18000` 角秒）。
- `src/protocol_catalog_tables.py` — `CATALOG_PATHS`（12 张可查表）、`CATALOG_GROUPS`（`std`/`calib`/`other` 是分组非表）。
- `references/tools.schema.json` — `cone_search.radius_arcsec` 明确「单位是角秒」、默认 180、上限 18000；`count.inputSchema.required = ["sqlid"]`、pattern `^s?\d+$`。
- `references/ALGORITHM-SPEC.md` §7 — 七工具 + 统一信封；sqlid 易失、用 `best://` URI 做可复现引用。
- `SKILL.md` — BEST 无 TAP/ADQL 端点，锥搜/计数走两阶段异步协议（POST 表单→sqlid→分页 GET）。

## 陷阱与错法
- **直接调 `count`**：最典型的错。`count` 需要 `sqlid`，而 sqlid 只能由 `cone_search`/`crossmatch_batch` 的 POST 阶段产生；「这个天区有多少源」这一步还没有会话号，`count` 无从下手。
- **编造坐标 / 天体名 / sqlid**：会话里没有「这个天区」的指代物，凭空给 ra/dec 或 `s3898` 式 sqlid 就是伪造输入——既违纪律又可能查到真实但不相关的天区（缺失坐标绝不能静默当 (0,0)，那是一个真实天区）。
- **把「多少源」误当 `fetch_page`**：`fetch_page` 是截断后的续拉，不是计数；先拉再数违反「先看数再决定拉不拉」。
- **半径单位搞错**：把度当角秒传（或反之），会得到 0 行或 360 倍半径；`radius_arcsec` 必须角秒，上限 18000″。
- **拿分组名当星表**：传 `catalog="calib"`/`"std"` 会被协议层拒绝（分组不是可查表，直接查返回软错误/内部错误）。
- **以为 `count` 会回行**：`count` 只回 `{"sqlid","total"}`，无站点行数据，故不标 `untrusted`；要行得走 `fetch_page`。

## 若需澄清，问什么
1. **「这个天区」具体指哪里？** 请给中心坐标（ra/dec，十进制度、ICRS），或给一个可解析的天体名（我用 `resolve_name` 换算）。—— 必答项，否则无法定位。
2. **检索半径多少？** 单位请给角秒（或告诉我度/角分，我换算；上限 18000″ = 5°）。可选项示例：180″(=3′，默认)、60″、3600″(=1°)。
3. **查哪张星表？** 12 张之一（默认 `ps1`）：ps1 / stripe82 / gaia_dr3_18 / jplus_dr3 / smss_dr4 / landolt / uss_dr1 / splus_dr4 / scr_galah / scr_lamost / xpsp / dr3xpcorr。
4. **只要计数，还是同时要把行也拉回来？** 若只要数，我按最小 `max_rows` 取 `total_count`；若要行，告诉我行数预算以便判断是否分页续拉。
