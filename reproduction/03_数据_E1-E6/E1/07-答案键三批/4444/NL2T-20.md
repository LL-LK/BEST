# NL2T-20
## 用户原话
> 这个字段代表逐历元星等吗？
## 判定
先澄清再调用 —— 句中没有"这个字段"的指代（无前文、未给列名、未给星表），不能假设它是某个字段就下结论；必须先问清是哪张表的哪一列，澄清后再用零请求的 `describe_catalog` 核对列名/波段，并按 BEST「单历元静态定标、全库无逐历元星等」的能力边界作答。
## 期望调用
```python
# 澄清前: 无调用。缺"这个字段"的指代 (列名) 与所属星表 id, 任何调用都是对指代的猜测。
（无）

# 澄清后 (用户给出字段名 + 所属星表, 例: stripe82 的 rmmed): 零请求核对列清单/波段/单位
from src.ai_tools import ToolBox

result = ToolBox().describe_catalog(catalog="stripe82")   # 裸 id; cost.http_requests == 0
# result.data.columns           -> 该表真实发布的列 (确认字段是否存在, 不在即非本表字段)
# result.data.magnitude_bands   -> 列名 -> 波段标签映射 (判断它是不是"星等列")
# result.data.units_note        -> "ra/dec in degrees; magnitudes in mag; radius in arcsec"
# 若字段名不在 CATALOG_COLUMNS[resolved] 内 -> 该字段非 BEST 发布字段, 明确拒绝, 不编造语义
```
## 参数与换算
- `catalog`（`describe_catalog` 唯一参数）：**必须由澄清确定**，取裸星表 id（`ps1`/`stripe82`/`gaia_dr3_18`/`jplus_dr3`/`smss_dr4`/`landolt`/`uss_dr1`/`splus_dr4`/`scr_galah`/`scr_lamost`/`xpsp`/`dr3xpcorr` 之一）。**无默认值可套** —— 未澄清前不得擅自填 `"ps1"` 之类默认，那是对"这个字段"所属表的臆测。注意：`describe_catalog` 只接受裸 id，带分组前缀（如 `calib/`）会被 `resolve_catalog` 拒绝并按 `E_INVALID_INPUT` 出函；旧拼写 `gaia_dr3` 经 `CATALOG_ALIASES` 归一为 `gaia_dr3_18`。
- 无坐标/半径/行数参数：本工具零线网、零请求（`cost.http_requests=0`、`cost.rows_returned=len(columns)`），因此**不涉及** deg / arcsec / 行预算的任何换算。
- 单位口径（不换算，仅判读）：星等列为 `mag`（对数单位，无量纲），`units_note` 已把该口径写进信封；若字段实为计数列（如 `stripe82_rnobs` = 该波段合成量背后的观测次数，单位 count）或标志列（如 `gaia_dr3_18_has_epoch_photometry` 布尔），则**根本不是星等**，无 mag 换算可言。
- 关键量级判断（供作答，不做数值换算）：BEST 全库无 MJD/观测时刻列，故不存在"逐历元"这一维度；`gaia_dr3_18_ref_epoch` 是 Gaia 天体测量**参考历元**（不是观测时刻，也不是星等）。
## 关键依据
- `src/multiband_photometry.py:3`（模块头）："BEST 是均一定标星表 (一行 = 一个源的一套定标后测光值, 全库无 MJD/观测时刻列), 本容器**不是时间序列**; points 中每个点是同一次锥搜返回的一个源 (BestSource)"；`:93-97` 类 docstring 再次点名"拿它当光变曲线用是科学误用（E3 语义轴 A 的典型错误）"，并指出全库唯一含 epoch 的 `gaia_dr3_18_ref_epoch` 是**天体测量参考历元、不是观测时刻**。
- `src/lightcurve.py:1-7`：`lightcurve` 已废弃为转发 shim，改名原因即"'lightcurve' 一名主动误导科学结论——把静态多波段测光讲成时序是 E3 语义轴 A 的头号陷阱，E1 的 NL2T-22 也以误用本类为红线反模式"。
- `static/fragments/data_source/best_catalogs.md:184-215`：能力边界段——"BEST 发布的是**单历元静态归算星表**……它**没有时间序列**：一行里的 g/r/i/z/y 是**五个波段的五个数**，不是同一颗星的五个时刻，拿它画光变曲线、估周期或算振幅是**范畴错误**"；`stripe82` 段——"**只发布合成统计量，不发布逐历元序列**"，`rnobs` 是观测次数、`rmmed` 是**中值合成星等**（"不是某一次曝光的测量值"）；要逐历元序列须转 SDSS Stripe82 原始影像/时序库，本表取不到。

- `src/ai_tools.py:417-463`（`ToolBox.describe_catalog`）：唯一能"零请求"回答"某表有没有某列/某列属哪个波段/单位是什么"的工具面入口；`:385-415`（`list_catalogs`）同样零请求。`references/ALGORITHM-SPEC.md §7`：工具面 7 原子工具（`resolve_name/list_catalogs/describe_catalog/cone_search/crossmatch_batch/count/fetch_page`）+ 统一信封 data/status/cost/provenance，站点数据标 `content_trust: untrusted`。

## 陷阱与错法
- **替用户脑补"这个字段"的指代**：无前文、无列名、无星表，若直接当成"某个星等列"或"某个 epoch 列"作答，就是在编造输入（本题纪律红线）。
- **把同一行的多波段星等当成多个时刻**：BEST 一行 g/r/i/z/y = 五波段五数，不是同一颗星五个时刻——这是**范畴错误**，不是"精度不够"（`best_catalogs.md:187`）。
- **把 `stripe82` 的 `rmmed`/`ummed` 当逐历元星等**：它是 `rnobs` 次观测的**中值合成**，不是单次曝光值；`rmrms` 是离散度（含测量误差+定标残差+可能的固有变异，不可分解），`rmchi2` 是诊断量不是分类量（`best_catalogs.md:202-215`）。
- **把 `gaia_dr3_18_ref_epoch` 当观测时刻/逐历元星等**：它是 Gaia **天体测量参考历元**，且本身不是星等。
- **把 `has_epoch_photometry` 布尔标志当成"本表有逐历元星等"**：它只是 Gaia 侧标志位，BEST 本表并不发布逐历元序列；且"未标记 ≠ 已判定为否"（空标志/`False` 只说明没有可用判定）。
- **走 `src.lightcurve.BestLightCurve`**：已废弃 shim（P0 命名整改，登记二期删除），按类名语义误用即踩 E1 NL2T-22 红线反模式。
- **在缺指代时发网络请求**：`cone_search`/`crossmatch_batch`/`count`/`fetch_page` 都触网且有成本，无字段指代时发这些请求纯属浪费；判定字段语义只需零请求的 `describe_catalog`（或本地 `slots`/`rag`）。
- **声称 BEST 能给时序/变星判定**：超出能力边界，须明确"本仓给不出"，并给出替代巡天（ZTF/ASAS-SN/Gaia 历元测光）路径，不得编造 by-id 端点或周期/振幅。
## 若需澄清，问什么
必须先问清两件事，缺一不可：
1. **"这个字段"是哪张星表的哪一列？** 请给列名原文或来源表。可选项（裸 id）：`ps1` / `stripe82` / `gaia_dr3_18` / `jplus_dr3` / `smss_dr4` / `landolt` / `uss_dr1` / `splus_dr4` / `scr_galah` / `scr_lamost` / `xpsp` / `dr3xpcorr`。
2. **该列的数据形态**：同一源、同一波段是只出现一行，还是多行（多时刻）？以及你打算用它做什么（画光变曲线/算周期/估振幅，还是做 SED/多波段定标）？
   - 若答"多时刻/画光变曲线/算周期/估振幅" → 直接告知**超出能力边界**：BEST 是单历元静态归算星表、不发布逐历元序列，须改用 ZTF / ASAS-SN / Gaia 历元测光等时序巡天（拒绝给周期/振幅）。
   - 若给出具体列名 + 星表 → 用 `describe_catalog(catalog=...)`（零请求）确认该列存在及其波段/单位，再据 `CATALOG_MAG_COLUMNS` 判定它是否星等列，并明确回答："BEST 全库无逐历元星等，该字段（若为星等）是单历元静态定标测光值。"
