# NL2T-02
## 用户原话
> ps1 表有哪些列和波段？
## 判定
直接调用 —— 「ps1 表有哪些列和波段」正是 `describe_catalog` 的职责（列清单 + 波段映射 + 单位说明），且 `ps1` 是注册表内的裸表 id、语义唯一，零请求即可作答，无需澄清、无需发线网请求。

## 期望调用
```python
from src.ai_tools import ToolBox

toolbox = ToolBox()
result = toolbox.describe_catalog(catalog="ps1")
# 读 result.data["columns"]（30 列）与 result.data["magnitude_bands"]（5 波段）
# result.cost["http_requests"] == 0；result.status["ok"] is True
```

## 参数与换算
- `catalog="ps1"`：**唯一必填参数**（`references/tools.schema.json` 的 `describe_catalog.inputSchema.required=["catalog"]`，`additionalProperties:false`）。
  - 取值理由：`ps1` 是 `CATALOG_PATHS` 的键、`CATALOG_DISPLAY` 的键，也是 `CATALOG_COLUMNS` / `CATALOG_MAG_COLUMNS` 的键，即「ps1 表」在权威注册表里的裸 id。
  - 必须传**裸 id**：`calib/ps1`（导航组前缀）会被 `resolve_catalog` 拒绝并映射为 `E_INVALID_INPUT`；`calib` 本身是导航组不是表（`CATALOG_GROUPS`），不可作 `catalog` 值。
- 无其它参数：本工具不接受坐标/半径/列投影，故**不涉及单位换算**（无 RA/Dec 十进制度、无角秒半径）。
  - 需要说明的是：本工具返回的 `data.units_note` 会声明口径 `"ra/dec in degrees; magnitudes in mag; radius in arcsec"` —— 这是**输出**里带出的单位约定，供后续 `cone_search` 用，不是本次入参要换算的量。
- 零请求：`describe_catalog` 从编译期常量 `CATALOG_COLUMNS` / `CATALOG_MAG_COLUMNS` 就地组装，`http_requests=0`，**不发任何 HTTP 请求**。

## 陷阱与错法
1. **误用 `list_catalogs`**：它只回 12 张表 id + 导航分组，**不含任何列/波段**，答不了本题。
2. **误用 `cone_search` 取元数据**：cone_search 需要 `ra`/`dec`（本题未给，不能编造坐标），且它是取行数据的重请求；用查询取「表有哪些列」既缺参数又浪费线网配额。
3. **把导航组当表名**：传 `catalog="calib"` 或 `"calib/ps1"` 会 fail-closed（`E_INVALID_INPUT`，见 `CATALOG_GROUPS` 与 `resolve_catalog`），`ps1` 虽是 `calib` 组成员，也必须传裸 id。
4. **波段数答错**：ps1 的**星等波段只有 5 个**（g/r/i/z/y，键为 `gpsf/rpsf/ipsf/zpsf/ypsf`）。`CATALOG_MAG_COLUMNS` 刻意不收 flag/改正/rms 列，故 `gpsf_corr`、`gflags`、`gpsf_err` **不是**波段。把 30 列里的带 g/r/i/z/y 字样的列都当成波段是典型错法。
5. **画蛇添足去澄清**：「ps1」在注册表里唯一确定，不需要问用户是哪张表/哪个波段口径；此时发澄清属于过度澄清，降低效率。
6. **凭空编造列名**：不得凭印象给列清单，必须以 `describe_catalog` 返回的 `data.columns` 为准（列名带表前缀，如 `ps1_ra`）。
7. **单位混淆**：本题入参无坐标/半径，无需换算；不要误把 `units_note` 当成「要先把半径换成角秒」的换算指令而多此一举。

## 若需澄清，问什么
无需澄清。（`ps1` 是权威注册表中唯一的裸表 id；列清单与波段映射均由 `describe_catalog` 零请求给出，不存在需要用户补充的自由参数。）
