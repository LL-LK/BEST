# NL2T-12

## 用户原话
> 把范围扩大到半径 0.5 度，看看有多少。

## 判定
先澄清再调用 —— 「扩大到」指向一个本会话并不存在的先前查询，中心坐标 (ra/dec) 与目标星表都缺，且这两项是 cone_search 的必填项，缺参不得编造；澄清后应调 `cone_search` 并用信封里的 `total_count`（而非 count 工具）回答「有多少」。

## 期望调用
```python
# 澄清前：不得发任何请求（ra/dec/catalog 缺失，禁止默认成 (0,0)）。
# 澄清拿到中心坐标与星表后，目标调用为：
box = ToolBox()  # 已加载 skill 的 agent 唯一工具面
box.cone_search(
    ra=<待澄清: 中心赤经, 度, ICRS>,
    dec=<待澄清: 中心赤纬, 度, ICRS>,
    radius_arcsec=1800.0,   # 0.5 度 × 3600 = 1800 角秒（关键换算）
    catalog=<待澄清: 星表裸 id, 如 "ps1">,
    max_rows=1,             # 只要数量：total_count 是服务端 getcount 真实总数，不受 max_rows 影响
)
# 回答取 data.total_count（服务端真实命中总数）；returned_count 只是本次实返，别当答案。
# 不调 count：count 只吃 sqlid，本题尚无会话号，且 cone_search 信封已带 total_count，无需二次请求。
```

## 参数与换算
- `ra`（度，ICRS）：**缺失** → 待澄清。用户只说了半径，未给中心；不得默认 0。
- `dec`（度，ICRS）：**缺失** → 待澄清。同上。
- `radius_arcsec`：**0.5 度 = 0.5 × 3600 = 1800.0 角秒**。换算依据 1° = 60′ = 3600″。工具/schema 的半径单位一律是角秒（`cone_search.radius_arcsec`，默认 180.0 角秒）。范围校验：`1800 > 0` 且 `1800 ≤ 18000`（5 度上限），**合法通过**。
- `catalog`：**缺失** → 待澄清。可选项为 12 张裸 id（`ps1`/`stripe82`/`gaia_dr3_18`/`jplus_dr3`/`smss_dr4`/`landolt`/`uss_dr1`/`splus_dr4`/`scr_galah`/`scr_lamost`/`xpsp`/`dr3xpcorr`）；若沿用上次则需用户确认，不能替用户选。
- `max_rows`：默认 1000。本题只问「有多少」，可设 `1` 以减少取回行数——`data.total_count` 来自服务端 getcount，与 `max_rows` 无关，不受此值影响（`truncated` 会变 True，属预期）。

## 陷阱与错法
1. **度当角秒直传** `radius_arcsec=0.5`：语义错 3600 倍，实际只搜 0.5 角秒邻域，结果严重偏少。schema 已显式警告「传度会得到 0 行或 360 倍半径」。必须先 ×3600 换成 1800.0。
2. **用 count 工具回答「有多少」**：count 只接受 sqlid，本题没有会话号，直接调必然 `E_INVALID_INPUT`/失败；而且 cone_search 信封已自带 `total_count`，再发一次 count 是多余线网请求（违反「能少发就不多发」）。
3. **读 `returned_count` 当总数**：它只是本次实返（受 `max_rows`，默认 1000 截断），不是真实命中数；真数是 `total_count`。
4. **编造/默认中心坐标**：把 ra/dec 补成 (0,0) 会静默查到赤道原点这个真实天区，结果看似正常实则全错——skill 明确禁止静默补默认坐标。
5. **判成「拒绝」**：BEST 锥形检索正是本 skill in-scope（`SKILL.md` 主理边界、且 BEST 无 TAP/ADQL 端点，不得转 astro-catalog），只是缺参需澄清，不构成越界拒绝。
6. **误转 astro-catalog**：通用星表检索可委派，但 BEST 自身数据查询「不委派」（`SKILL.md` 委派边界 + `static/core/stance.md`），此处必须由本 skill 承接。
