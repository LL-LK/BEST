# NL2T-01
## 用户原话
> BEST 能查哪些星表？
## 判定
直接调用：这是对「可查询星表清单」的元数据问询，恰好命中 `ToolBox.list_catalogs()`（唯一零参数、零 HTTP 请求的离线工具），直接调用即可作答，无需澄清、不构成拒绝。
## 期望调用

from src.ai_tools import ToolBox

toolbox = ToolBox()          # 无参构造：list_catalogs 不建会话、不触网

# result.data["catalogs"] -> 12 张 [{id, display, query_path}]
# result.data["groups"]   -> {"std":[...], "calib":[...], "other":[...]}（导航组，不是表）

## 参数与换算
- `list_catalogs()`：**无参数**。schema 声明 `inputSchema.properties` 为空且 `additionalProperties: false`（references/tools.schema.json:57-60），传任何参数都属越界。
- 单位换算：**本题不涉及**。半径统一角秒、坐标十进制度这套口径只对 `cone_search`/`crossmatch_batch` 生效（`src/ai_tools.py:454` 的 `units_note`：`ra/dec in degrees; magnitudes in mag; radius in arcsec`；`src/scripts/guards.py:66-86` 半径上限 18000″）。本工具不接收坐标/半径/星表 id，故无任何换算步骤，也不得凭空补坐标。
- 成本：`cost.http_requests == 0`（`src/ai_tools.py:411` 硬编码 0，读编译期常量不算请求）；`provenance.stable_uri == "best://catalogs"`。

## 陷阱与错法
1. **误用 `CATALOG_COLUMNS` 数出 13 张**：该表多一个 `"std"` 键（`src/protocol_catalog_tables.py:581`），但注释明写它是「虚拟表: 线上无对应 /q 路由」，仅供 `parse_csv_rows()` 旧式短表头修复；`list_catalogs` 取的是 `CATALOG_DISPLAY`（12 项），故正确答案是 12，不是 13。
2. **把导航组当表**：`std`/`calib`/`other` 是分组；`/std/q`、`/calib/{id}/q` 会返回 `{"error":"Not Found"}` 或 `Internal Server Error`（`src/protocol_catalog_tables.py:26-28,53-54`）。回答时必须区分「分组」与「成员表」，`std` 的真实成员是 `scr_galah`/`scr_lamost`/`xpsp`。
3. **把旧拼写 `gaia_dr3` 当第 13 张表**：它只是 `CATALOG_ALIASES` 的别名，归一后就是 `gaia_dr3_18`（`src/protocol_catalog_tables.py:72`），清单里不另列。
4. **凭空发请求 / 逐个 describe**：本题不需要任何线网请求。对 12 张表各调一次 `describe_catalog` 是多余成本（虽然同为 0 请求），而 `cone_search`/`crossmatch_batch`/`count`/`fetch_page` 更是跑偏——那是「查数据」不是「问能力」，且缺坐标/半径/sqlid 时属编造参数。
5. **把文档当权威**：`best_catalogs.md` 记有 SkyMapper DR4 出现在 catalog 文档页，但 `/skymapper_dr4/f` 软 404 —— 文档存在 ≠ 可查询，一律以注册表 `/f` 实测口径为准（`static/fragments/data_source/best_catalogs.md:20-21`）。
6. **误答"表有没有数据"**：`list_catalogs` 只回路由活性的清单；`jplus_dr3`/`landolt` 路由活但 `getcount` 恒 0，属另一维度，不能在此题里混谈。
