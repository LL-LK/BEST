# NL2T-24
## 用户原话
> 上传我的星表做交叉匹配。
## 判定
先澄清再调用 —— BEST 自身的批量交叉匹配确属本 skill 主理，且现行实现是**服务端 proximity 一次提交**（`ToolBox.crossmatch_batch` → `BestCrossMatch.crossmatch_batch`，`pos.type=proximity` + `ra,dec,radius` 多行 textarea），不是逐点锥搜；但用户这一句既没给坐标表内容/格式，也没给目标星表、匹配半径、最近邻与列投影，缺参数不编造，故先把这几项问清再发那一次 POST（澄清前零请求）。
## 期望调用

# 澄清补齐入参前不发起任何请求；下面是补齐后应走的唯一批量路径（服务端 proximity 一次提交）。
from src.ai_tools import ToolBox

box = ToolBox()                      # 缺省构造 BestClient（限流 2.0 s/req、urllib3 重试 3、超时 120 s）
res = box.crossmatch_batch(

    ],
    catalog="<BEST 星表 id>",        # 12 张之一，缺省 "ps1"；用户未指定→待澄清

    columns=[...],                   # 强烈建议显式给：不提交 showcol 时响应只有 4 个元数据列、无任何星表列（V-1）
    # max_rows=50000,                # 缺省行数预算；page_size 内层缺省 1000

# 返回统一信封：data.rows / data.n_inputs / data.mode(=proximity)；失败自动降级为逐点并标 mode=per_coordinate_fallback。

## 参数与换算
- **coords（坐标表，必填）**：`list[dict]`，每项 `{"ra": 数值, "dec": 数值, "id": 可选}`。ra/dec 单位**度（ICRS）**。用户"上传的星表"需先解析成该形态：若为 CSV，表头至少含 `ra`/`dec` 列（可选 `id` 列），口径见 `crossmatch_from_csv`（ra_col="ra", dec_col="dec"）与 `submit_upload_job` 的 DictReader 解析；`id` 缺省回落为输入下标字符串。
  - 单位换算：RA 时角 h m s → 度 = `15×(h + m/60 + s/3600)`；Dec d m s → 度 = `±(d + m/60 + s/3600)`。角度换算：`1° = 3600″`、`1′ = 60″`。
  - 值域校验（入口即拒，E_INVALID_INPUT）：`0.0 ≤ ra < 360.0`、`-90.0 ≤ dec ≤ 90.0`；越界坐标会被服务端静默归一成别的天区，故必须先校验。RA/Dec 长度不等 → `RA/Dec list length mismatch`；空表 → `Empty coordinate list`。
- **catalog（目标星表）**：裸 id，取 12 张之一 —— `ps1`（缺省）/`stripe82`/`gaia_dr3_18`/`jplus_dr3`/`smss_dr4`/`landolt`/`uss_dr1`/`splus_dr4`/`scr_galah`/`scr_lamost`/`xpsp`/`dr3xpcorr`（`CATALOG_PATHS`）。**`std`/`calib`/`other` 是导航分组不是可查询表**（带组前缀的 `/q` 路由返回 HTTP 200 + `{"error":"Not Found"}` 软 404）。用户未指定 → 待澄清。
- **radius_arcsec（匹配半径）**：单位**角秒**，即 `pos.defaultRadius`，逐输入坐标共用，缺省 `3.0″`。换算示例：用户说"1 角分"→ `60.0`；"0.001 度"→ `3.6`；"5 角秒"→ `5.0`。用户未指定 → 待澄清（可直接沿用缺省 3.0″ 但需用户确认）。
- **nearest_only**：缺省 `True`（每个输入只保留最近邻，`proximity_nearestonly`）；若要锥内全部匹配需显式 `False`。
- **columns（列投影/showcol）**：缺省 `None`。注意 §5 的 V-1 结论——**不提交 `showcol` 时响应只回 4 个无前缀元数据列（`input_line`/`input_ra`/`input_dec`/`dist_arcsec`），一个星表列都没有**；要拿匹配源的测光/位置列必须显式给 `columns`。
- **max_rows**：缺省 `50000`（单次拉取行上限）；分页内层 `page_size` 缺省 `1000`；被截断时 `status.truncated=True`，用 `fetch_page` 续拉。
- 输入上限/并发：批量路径一次 POST 替代 N 次锥搜（实机 8 坐标：16 请求/25.9 s → 2 请求/7.0 s）；逐点兜底路径 `MAX_WORKERS=4`。

## 陷阱与错法
- **误判成"逐点锥搜"**：现行批量匹配是**服务端 proximity 一次提交**（1 次 POST + 分页 GET）；`crossmatch_coords` 逐点并发（`MAX_WORKERS=4`）只是回归基线与批量失败后的 fallback（结果里 `mode="per_coordinate_fallback"`）。CLI `python -m src crossmatch` 走的也是逐点路径（`crossmatch_from_csv`/`crossmatch_coords`），不是 proximity 面。
- **以为存在"把星表上传到 BEST 服务端"的接口**：BEST **未开放公开上传/任务 API**；`submit_upload_job` 是**本地磁盘任务队列**（`best_crossmatch_jobs/<job_id>/`，逐点执行，策略 C），不是服务端上传；站点 `/data/best/jobs` 自建星表区需 NADC 登录。"上传"在本 skill 语境里 = 把用户坐标表解析成 `coords` 后走 proximity 提交。
- **不传 `columns`**：响应只剩 4 个无前缀元数据列，拿不到任何星表列（V-1），会被误读成"没匹配到/没有测光"。
- **半径单位搞错**：`radius_arcsec` 传"度"值会得到 0 行或 3600 倍半径（cone_search 侧同款注释已警示）。
- **缺参数硬编**：用户没给坐标表内容、目标星表、半径，凭空填 `ps1`+`3.0″`+假坐标即违规——坐标是真实天球位置，编造会静默查错天区。
- **组名当表名**：`std`/`calib`/`other` 是导航组，当 `catalog` 传会拿到软 404/内部错误；`gaia_dr3` 是旧拼写别名，会被 `CATALOG_ALIASES` 归一为 `gaia_dr3_18`。
- **越界坐标静默归一**：`ra`/`dec` 越界必须先抛错，不能默认填 `(0,0)`。
- **越界委派**：若用户真实意图是拿**外部** Gaia/SIMBAD/VizieR 做交叉匹配，那是 `astro-catalog`（球面 KD-Tree 锥搜）的活，本 skill 只对 **BEST 自身数据面**负责；仅当目标是 BEST 发布的 `gaia_dr3_18` 等表时仍归本 skill。
## 若需澄清，问什么
1. **坐标表在哪、什么格式？** 请直接粘贴坐标，或给出/上传文件（CSV 表头需含 `ra`、`dec` 列，可带 `id` 列）；并确认这两列是**十进制度**还是 h m s / d m s（若是后者我按 15×… 换算）。
2. **目标星表是哪张 BEST 表？** 可选：`ps1`（缺省）/`stripe82`/`gaia_dr3_18`/`jplus_dr3`/`smss_dr4`/`landolt`/`uss_dr1`/`splus_dr4`/`scr_galah`/`scr_lamost`/`xpsp`/`dr3xpcorr`；不确定就用缺省 `ps1`。（若你要匹配的是**外部** Gaia/SIMBAD/VizieR，而不是 BEST 发布的表，我会转 `astro-catalog`。）
3. **匹配半径取多少？** 可选：`3 角秒`（缺省）/`1 角秒`/`1 角分(=60″)`/其它（请带单位；我按 1°=3600″、1′=60″ 换算）。
4. **每个坐标只要最近邻，还是要锥内全部匹配？**（缺省：只要最近邻）
5. **要返回哪些列？**（缺省：不裁剪；不指定 `columns` 时响应不含星表列，只回元数据列）
