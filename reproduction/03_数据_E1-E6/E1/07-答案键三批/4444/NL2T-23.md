# NL2T-23
## 用户原话
> 把整张 ps1 导出成 FITS。
## 判定
拒绝（不给调用）：BEST 没有"整表导出/全量 dump"的取数方式（取数必须带天区或列约束，全表约 20 亿星远超行数上限），且 FITS 在本 skill 里只是**本地转换**格式、**不在 agent 工具面**，服务端本身也不产出 FITS。
## 期望调用
```python
# 无 —— 拒绝调用（请求同时踩中"整表导出"与"FITS 工具面"两条能力边界，无任何工具/参数组合可实现）
```
## 参数与换算
无调用，故无参数。逐项说明为何无法凑出参数：

- **"整张 ps1"**：无可承载的入参。7 个原子工具里没有"整表/dump"入口：
  - `cone_search(ra, dec, radius_arcsec, catalog="ps1", ...)` —— ra/dec（度）、radius（角秒）**必填**，本质是"某天区里有什么"，覆盖不了全天；
  - `crossmatch_batch(coords, catalog="ps1", ...)` —— coords 坐标表**必填**，仍是"给定坐标邻域"，不是整表；
  - `count(sqlid)` / `fetch_page(sqlid, ...)` —— 都要求**先有 sqlid**，而 sqlid 只能由一次带约束/天区的查询产生，不能凭空建全表会话；
  - `resolve_name` / `list_catalogs` / `describe_catalog` 与取数无关。
- **规模换算（为何即使"无约束"也不成立）**：官网口径 ps1 属"up to 2 billion stars"量级；skill 单次取回上限 `max_rows` 缺省 **50000**（`ALGORITHM-SPEC.md` §3）。20 亿 ÷ 5 万 ≈ **4 万次**分页上限仍不够，且 `getcount` 在无约束会话上 >60 s 超时（`best-database-guide.md` §使用约束）。"整张"在能力上不可达。
- **"FITS"**：FITS 不参与任何单位换算，它只是落盘格式；且它是 `serialization.LOCAL_EXPORT_FORMATS` 里的**本地转换**项，**不是** `protocol.SUPPORTED_OUTPUT_FORMATS` 的线上格式。想落 FITS 只能走 `BestDownloader` 落盘层（`_save_result` 的 fits 分支 → `write_fits`），**前提是先有带天区/约束的查询结果**，而这一步已被上一条否决。

**降级路径（若用户接受缩小范围）**：给定天区后可用
```python
# 示意：不是本题期望调用，仅作降级替代；需 astropy 已安装
BestDownloader(client).download_region(
    ra_center=<度>, dec_center=<度>, radius_arcsec=<角秒>,
    catalog="ps1", output_format="fits", output_file="ps1_region.fits",
)
```
单位口径：ra/dec 为**度**，radius 为**角秒**（表单 `pos.radius` 单位是角秒，传度会得 0 行或 360 倍半径）。
## 关键依据
- **无整表导出**：`src/downloader.py:11` 模块原则"核心原则: 绝不整表下拉 20 亿级全量星表 — 只按约束/天区取回真正需要的文件片段"；`references/best-database-guide.md`《使用约束》"查询务必带天区/星等约束。无约束的"Save all"等价于全量拉表……更大数据集走 Catalog 区整表下载（需登录）"（该整表下载在 skill 能力之外）；`static/fragments/data_source/best_catalogs.md`"严禁全量拉取"；`rag/knowledge/best_practices.yaml`"禁止全量下载 20 亿行星表"。
- **取数入口必带天区/约束**：`src/download_region.py:25` 入口签名强制 `ra_center/dec_center/radius_arcsec`；`src/ai_tools.py` 的 `cone_search`（ra/dec/radius 必填）与 `crossmatch_batch`（coords 必填）。
- **工具面无整表/FITS 入口**：`src/ai_tools.py:792` `TOOL_NAMES` 仅 7 个（resolve_name/list_catalogs/describe_catalog/cone_search/crossmatch_batch/count/fetch_page）；`references/ALGORITHM-SPEC.md` §7 工具面同清单。
- **FITS 是本地转换、服务端不返回**：`src/serialization.py:58` `LOCAL_EXPORT_FORMATS = tuple(SUPPORTED_OUTPUT_FORMATS) + ("fits",)`；`src/serialization.py:336` `write_fits` docstring"服务端不返回 FITS（请求 fits 拿到的是结果页 HTML）"；`src/protocol.py:114` `SUPPORTED_OUTPUT_FORMATS = ("csv","txt","json","votable")`（**不含 fits**）；`src/protocol.py:117` `PHASE1_HANDOFF_FORMAT = "html"`。
- **FITS 只在落盘层**：`src/downloader.py:528` `_save_result` 的 `elif fmt == "fits":` 分支（依赖 astropy，缺失抛 `RuntimeError`）。
- **行数上限**：`ALGORITHM-SPEC.md` §3 `max_rows 50000`、`page_size 1000`。
- **格式说明**：`references/data-formats.md` §1（`fits` 站点不支持，纯本地转换）、§3（"线上只取 CSV，其余本地转"）。
## 陷阱与错法
- **用大半径锥搜冒充"整表导出"**：如 `cone_search(ra=0, dec=0, radius_arcsec=18000, max_rows=10000)` 再落 FITS，然后声称"已把整张 ps1 导出成 FITS，文件是 ps1_full.fits"。这只覆盖极小一块天区且被 `max_rows` 截断，文件与"整表"无关 —— 是典型幻觉交付（编造文件名 + 把截断当全量）。
- **以为能给服务端传 `output.fmt=fits`**：站点不支持 fits，请求它拿到的是**结果页 HTML**，不是 FITS（`data-formats.md` §1、`best-database-guide.md` §输出格式）。本 skill 阶段一恒用 `html`、阶段二恒用 `csv`。
- **以为 FITS 在 agent 工具面**：7 个原子工具里没有任何导出/落盘入口；FITS 只在 `BestDownloader` 落盘层，且要 astropy。
- **以为可以不带天区/约束直接拉**：无约束等于全量拉表（内联 CSV 可达数百 MB 量级，`getcount` >60 s 超时），违反模块核心原则，且 20 亿行远超 `max_rows=50000`。
- **把"ps1 表很大"当成"可以分批拉全"**：分页只对已建会话续取，会话仍由一次带约束查询产生；本 skill 无"全天无约束会话"这一入口。
