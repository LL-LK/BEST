# NL2T-11

## 用户原话
> 查找 RA=120.3°、Dec=−20.4°、半径 5″ 内的标准星。

## 判定
直接调用：几何量（ra/dec/半径）齐备，唯一待定的 catalog 参数可由注册表就地确定——「标准星」即 BEST 的 Standard Stars 导航组 `std`（成员 `scr_galah`/`scr_lamost`/`xpsp`），而 `ToolBox.cone_search` 的 `catalog` 参数**显式支持** `"std"` 分组展开合并，故一次 `cone_search` 即可覆盖全部标准星表，无需澄清、不拒绝。

## 期望调用
```python
from src.ai_tools import ToolBox

ToolBox().cone_search(
    ra=120.3,            # 度, ICRS; 值域 [0, 360)
    dec=-20.4,           # 度, ICRS; 值域 [-90, 90]
    radius_arcsec=5.0,   # 5″ = 5 角秒, 工具口径就是角秒, 原值传入
    catalog="std",       # Standard Stars 导航组 → 展开 scr_galah/scr_lamost/xpsp 三成员并合并
)
# 其余参数保持缺省: max_rows=1000 / sort=None / order="asc" / nearest_only=False
```

## 参数与换算
- `ra=120.3`：用户给 120.3°；工具 `cone_search(ra=...)` 的单位即**度**（ICRS），信封 `units_note` 亦写 "ra/dec in degrees"。原值直传，不做换算。合法（`guards.validate_coordinate`：`0 <= ra < 360`）。
- `dec=-20.4`：同上，单位度；合法（`-90 <= dec <= 90`，两端闭）。原值直传。
- `radius_arcsec=5.0`：用户给 5″ = 5 角秒（arcsecond）；工具参数名与单位就是 `radius_arcsec`（角秒），故 `5.0` 直传，**无需任何换算**。合法（`validate_search_radius`：`0 < r <= 18000` 角秒 = 5°）。
- `catalog="std"`：这是本题唯一需要查证再定的参数。
  - 「标准星」= BEST 站点上的 **Standard Stars** 导航组：`CATALOG_GROUPS["std"] = ("scr_galah", "scr_lamost", "xpsp")`；显示名也逐条对得上（`CATALOG_DISPLAY`：`scr_galah`→"Standard Stars (SCR GALAH)"、`scr_lamost`→"Standard Stars (SCR LAMOST)"、`xpsp`→"Standard Stars (Gaia DR3 XP&SP)"）。所以「标准星」对应的是**三张可查表** `scr_galah`/`scr_lamost`/`xpsp`（三张都在 `CATALOG_PATHS` 里，各有可用 `/q` 路由）。
  - `std` **不能当「表名」查**：`describe_catalog` 的 enum 只列 12 张裸 id（不含 `std`）；`resolve_catalog("std")` 会抛 `ValueError`（"it is the navigation group holding ..."）；`CATALOG_COLUMNS["std"]` 是仅供旧式表头修复的**虚拟表**（注释："线上无对应 /q 路由"）；站点 `/std/q` 本身返回软错误。
  - 但 `std` **可以当 `cone_search` 的 `catalog` 分组名**：`client_query.cone_search` 有显式分支 `if catalog == "std":`，把组展开为三张成员表逐个锥搜后合并（Q-22，且注明"不得静默改写成单一表"）；`references/client-api-reference.md` 亦写明 `catalog="std"` 展开三成员合并；`tools.schema.json` 的 `list_catalogs` 描述同样宣告 `std` 展开为三成员。
  - 结论：传 `"std"`（覆盖标准星全集），**不传** `"std"` 当表名给 `describe_catalog`，**不传** 工具默认的 `"ps1"`（那是 Pan-STARRS 一般测光，不是标准星），也**不传** `"landolt"`（属 `calib` 组，不是 Standard Stars 组成员）。
- `max_rows`：缺省 1000。5″ 小锥（≈ 1.9e-5 deg²）远不会触顶，无需显式给；给了也无害。

## 陷阱与错法
1. **把 `std` 当表名**：调 `describe_catalog(catalog="std")` 或 `resolve_catalog("std")` → 被协议层拒（enum 无 `std`；分组名抛 `ValueError` → 信封 `E_INVALID_INPUT`）；直接拼 `/std/q` 则拿到 HTTP 200 + `Internal Server Error` 的软 404，状态码门禁看不见。正确做法是只在 `cone_search` 的 `catalog` 上传 `"std"`（走分组展开），或退一步逐张传三个成员 id。
2. **反向踩坑：以为 `std` 完全不能查，于是硬编码单张成员表**（如只查 `scr_lamost`）。`client_query` 明确禁止这种"静默改写成单一表"的做法——那会让用户以为拿到的是标准星全集，实际只覆盖一张表。本题要的是全组，就传 `"std"`。
3. **用工具默认 `catalog="ps1"`**：不传 `catalog` 会静默查 Pan-STARRS All-Sky（一般测光交叉匹配表），与「标准星」无关；查得到数据但答错了问题。
4. **把 `landolt` 当标准星**：`landolt` 在 `calib` 组（显示名 "Well-Calibrated Landolt"），**不是** `std` 组成员；且它极稀疏（全表 45712 行 ≈ 1 行 / 3.7 deg²，0.5° 锥期望命中仅 0.018 行），锥搜按位置找、按名字找不到，5″ 下必然 0 行。只有用户点名 Landolt 或已给已知 Landolt 坐标时才用它。
5. **半径单位错**：5″ 就是 **5 角秒**，`radius_arcsec=5.0`，不换算。若误当成 5°（放大 3600×）或 5′（放大 60×）就换了天区；反过来若"忘了传半径"，工具缺省是 **180.0 角秒**，不是 5″，同样是静默换条件。
6. **把 0 行当故障**：本坐标 (120.3, −20.4) 是 `uss_dr1` 的实测代表天区；`std` 三成员本身极稀疏（`scr_galah` 在 (120, −20.4) 300″ 下就是 0 行、1800″ 才 1 行），5″ 锥下三表很可能全 0。这属统计正常稀疏，**不是** std 组查询失效、也不是表没了——报告时必须带"表 + 半径 + 约束"限定，并区分"库内无记录"与"天体不存在"。
7. **越界半径/坐标**：半径 > 18000 角秒（5°）或 ra/dec 越界会在入口 `validate_search_radius`/`validate_coordinate` 抛 `ValueError` → `E_INVALID_INPUT`；本题 5″ 与 (120.3, −20.4) 均在界内，不会触发。
8. **门禁幻觉**：不要声称 `http_status`/`checksum_match` 两条 blocking 门禁"已判过"——SKILL.md 与 `agents/openai.yaml` 已声明它们在 `src/` 内无生产填充点（`BestResultSet` 零生产构造点），应按 `honesty_stance` 记 `not_computable`，不得凭空声称。

## 若需澄清，问什么
无需澄清。用户已给全 ra/dec/半径三项几何量，且「标准星」在 BEST 里唯一对应 Standard Stars 导航组 `std`（成员 `scr_galah`/`scr_lamost`/`xpsp`），`cone_search(catalog="std")` 一次即覆盖全集，不存在必须由用户补的缺失参数。
