# NL2T-07
## 用户原话
> 查询 Gaia DR3 1234567890123456789 在 BEST 中的 ZTF g/r/i 星等。
## 判定
先澄清再调用：BEST 只支持按位置（ra/dec 锥搜或坐标交叉匹配）取数，7 个原子工具无一接受 Gaia source_id，本 skill 也没有「Gaia DR3 source_id → 坐标」的解析能力（属 astro-catalog 边界），坐标缺失且绝不可编造；同时 BEST 无独立 ZTF 星表、ZTF g/r/i 只是 xpsp/scr_* 的交叉测光列，故必须先向用户取坐标并确认目标表，再调用。

## 参数与换算
- **source_id（"Gaia DR3 1234567890123456789"）**：19 位十进制 Gaia DR3 source_id。**不能作为任何工具入参**——ToolBox 的 7 个工具没有任何接受 catalog ID 的参数；BEST 是位置型服务（锥搜/批量坐标交叉匹配），无「按 Gaia source_id 查询」入口。也**不得**把它塞进 `resolve_name`（那是 CDS Sesame 天体名解析，如 M31/NGC 532，裸数字 ID 不是可解析天体名），更不得由它臆造坐标。
- **ra / dec（缺失，必需）**：ICRS 十进制度。值域由 `src/scripts/guards.py:validate_coordinate` 强制：ra ∈ [0, 360)、dec ∈ [-90, 90]（`cone_search` / `crossmatch_batch` 必填）。需用户提供，或先由 astro-catalog / Gaia 侧解算；本 skill 不产出坐标。
- **radius_arcsec（待定，澄清项）**：单位**角秒**。缺省值：`crossmatch_batch` 3.0″、`cone_search` 180″；上限 18000″（=5°，`validate_search_radius`）。换算：1′×60、1°×3600；若用户按角分/度给，须换算成角秒后传入。
- **catalog（待定，澄清项）**：`crossmatch_batch` 缺省 `ps1`，但本题要 ZTF，需显式指定。BEST 12 张可查表**没有 ZTF 表**，ZTF g/r/i 只作交叉测光列存在：`xpsp` 的 `ztf_g_g_xpsp / ztf_r_r_xpsp / ztf_i_i_xpsp`（XP 光谱拟合测光），或 `scr_galah / scr_lamost` 的 `gztf / rztf / iztf`（交叉匹配测光）——两者口径不同，须确认。
- **columns（showcol 投影，必须显式给）**：`crossmatch_batch` 不提交 showcol 时只回 4 个 `inputobjs_*` 元数据列，一个星表列都没有（ALGORITHM-SPEC §5 V-1）；xpsp 的响应列前缀是表单表名 `gaiaxp_photinfo_replenish_*`，ZTF 列名见上。
- **nearest_only**：`crossmatch_batch` 缺省 True（单源取最近邻合适）；若用 `cone_search` 则缺省 False，需按需显式开。
## 关键依据
- `src/ai_tools.py`：`TOOL_NAMES` 7 原子工具；`cone_search(self, ra, dec, ...)` 与 `crossmatch_batch(self, coords=[{ra,dec}], ...)` 均以坐标定位，无 source_id 入参；`resolve_name(name)` 是名称解算。
- `references/tools.schema.json`：`cone_search.required=["ra","dec"]`、`crossmatch_batch.required=["coords"]`、`resolve_name` 描述为「把天体名（M31、NGC 532…）解析为 ICRS 坐标。后端代理 CDS Sesame」；`cone_search` 声明半径单位为角秒、上限 18000。
- `src/scripts/guards.py`：`validate_coordinate`（RA [0,360)、Dec [-90,90]）、`validate_search_radius`（>0 且 ≤18000″）。
- `src/protocol_catalog_tables.py`：`CATALOG_PATHS` 12 张可查表无任何 ZTF 表；`CATALOG_COLUMNS["xpsp"]` 含 `ztf_g_g_xpsp / ztf_i_i_xpsp / ztf_r_r_xpsp`；`CATALOG_COLUMNS["scr_galah"] / ["scr_lamost"]` 含 `gztf / rztf / iztf`；`CATALOG_MAG_COLUMNS["xpsp"]` 只有 g/bp/rp，`scr_galah/scr_lamost` 只收 `rztf→r`，且注释明确 ZTF 交叉测光列「只进 raw_data，不并入 BestSource.magnitudes」。
- `references/photometric-systems.md:43`（ZTF = g, r, i，属 19 个「测光系统」）+ `references/best-database-guide.md:83`（「测光系统」与「可查询表」是两个维度）。
- `references/best-database-guide.md:92`：标准星表「锥搜按位置找，按名字找不到」——BEST 取数一律以位置为入口。
- `SKILL.md` 委派边界：Gaia/通用星表检索与坐标交叉匹配 → `astro-catalog`（BEST 无 TAP/ADQL，也无 Gaia ID 查询）；`references/ALGORITHM-SPEC.md §7`（工具面锚点）。
## 陷阱与错法
1. **拿 19 位 source_id 硬塞工具**：`resolve_name` 是 Sesame 名解析，裸数字 ID 不是天体名，只会拿 `E_NAME_UNRESOLVED`；当 ra/dec 传则触发 `E_INVALID_INPUT`。**凭空造坐标**更糟——会静默查到错误天区（`crossmatch_batch` 明言缺失坐标绝不静默当 (0,0)）。
2. **以为 BEST 有 "ztf" 表**：12 张可查表里没有；查不存在的表会得到 HTTP 200 + `{"error":"Not Found"}` 的软 404（`is_soft_error/Soft404Error`），不是「无数据」。
3. **以为拿到行就有 g/r/i 星等**：ZTF 交叉列只落 `raw_data`，不进 `BestSource.magnitudes`（同波段多调查会键碰撞），须按原始列名读，不能从 `magnitudes` 取。
4. **单位错**：radius 是**角秒**不是度（传度得 0 行或 360 倍半径）；ra/dec 是**十进制度**，不是时分秒/度分秒。
5. **漏 showcol**：`crossmatch_batch` 不提交 showcol 只回 `inputobjs_*` 元数据，一个星表列都没有——看起来「成功」实则无测光。
6. **把 "1234567890123456789" 当真值直接查**：该串形似顺序占位（1234567890…），须先与用户核实。
7. **误判为「拒绝」**：请求本质在 BEST 能力内（有坐标即可查 xpsp 交叉测光），不该整题拒绝；但也不能直接调——缺的是必需坐标。
## 若需澄清，问什么
1. **坐标（必需）**：该 Gaia DR3 源的 ICRS 赤经/赤纬（十进制度）是多少？可选路径：
   - (A) 直接给出 `ra, dec`（度）；
   - (B) 给出可被 Sesame 解析的天体名（本 skill `resolve_name` 可解，如 "M31"、"NGC 532"）；
   - (C) 只有 Gaia DR3 source_id —— **该解析不在本 skill 能力边界内**（BEST 无 Gaia ID 查询入口），需先由 `astro-catalog` / Gaia 侧解算成坐标后再回到本 skill。
2. **目标表（必需确认）**：BEST 无独立 ZTF 星表，ZTF g/r/i 只有交叉测光列。要查哪张？
   - (A) `xpsp`（XP 光谱拟合 ZTF 测光：`ztf_g_g_xpsp / ztf_r_r_xpsp / ztf_i_i_xpsp`）；
   - (B) `scr_galah` / `scr_lamost`（交叉匹配 ZTF 测光：`gztf / rztf / iztf`，且 `magnitudes` 只认 `rztf`）。
3. **匹配半径**：以角秒计（默认 3″，`crossmatch_batch`）；若用锥搜默认 180″。
4. **确认 source_id 真伪**：`1234567890123456789` 是否为真实 Gaia DR3 source_id（形似占位串）。
