# NL2T-05
## 用户原话
> 我这有 1000 个坐标要匹配，帮我一次性做完。
## 判定
先澄清再调用：意图正确且能力支持（应走 `crossmatch_batch` 服务端 proximity 一次提交），但**用户尚未给出那 1000 个坐标本身**，目标星表/半径/投影也未指定，缺参不得编造，必须先补齐坐标与关键参数再调用。
## 期望调用
```python
# 形态确定，但 coords 必须来自用户（以下 <...> 为待用户提供的占位，禁止凭空生成坐标/天体名/id）
from src.ai_tools import ToolBox

tb = ToolBox()
res = tb.crossmatch_batch(
    coords=[{"ra": <用户提供_十进制度>, "dec": <用户提供_十进制度>, "id": <用户提供的标识,可缺>}
            for _ in range(1000)],      # 1000 条，一次性整表提交
    catalog=<用户确认的星表 id>,          # 12 张之一，未确认前不默认
    radius_arcsec=<用户确认的角秒值>,     # 缺省 3.0
    nearest_only=True,                    # 批量匹配常规诉求
    columns=None,                         # 默认整表列
    max_rows=50000,
)
# 若 res.status["truncated"] 为 True，凭 res.provenance["session_id"](sqlid) 续取：
# tb.count(sqlid=res.provenance["session_id"])  ->  tb.fetch_page(sqlid=..., page=2, page_size=10000)
```
## 参数与换算
- `coords`（必填，缺失即无法调用）：每项需数值型 `ra`/`dec`，单位为**十进制度（ICRS）**，值域 `ra∈[0,360)`、`dec∈[-90,90]`。用户只说了"1000 个坐标"却没给数据 → 必须索取（粘贴或文件路径），**不得编造**。`id` 可选，缺失时工具按下标兜底并 warn，建议一并提供以便结果回连。
- `catalog`（默认 `ps1`）：目标只能是 12 张可查表之一 `ps1/stripe82/gaia_dr3_18/jplus_dr3/smss_dr4/landolt/uss_dr1/splus_dr4/scr_galah/scr_lamost/xpsp/dr3xpcorr`。用户未点名 → 需确认，不静默取默认。
- `radius_arcsec`（默认 3.0）：**单位为角秒**。若用户给角分/度须换算：1′ = 60″、1° = 3600″（例：10″ 直接传 10；0.5′ → 30；0.01° → 36）。skill 全局检索半径上限为 18000″(=5°)，超限被 `guards.validate_search_radius` 拒（`E_INVALID_INPUT`）。
- `nearest_only`（默认 True）：每个输入只留最近邻；需要全部候选时显式置 False。
- `columns`（默认 None=整表列）：可选 `showcol` 投影，列名须带表前缀（如 `ps1_ra`），裁剪可省带宽。
- `max_rows`（默认 50000）：1000 输入 + 最近邻时命中 ≤1000，远低于上限，不会截断；置 False 求全匹配时留意 `truncated`。

## 陷阱与错法
1. **凭空造坐标/天体名/sqlid**：用户没给数据，编造即违规，且工具对缺失键显式抛 `E_INVALID_INPUT`（不会当 (0,0)），脏输入会白跑一次线网。
2. **拆成 1000 次 `cone_search`**：逐点锥搜会把 1 次提交放大成约 2000 次请求，正是 `crossmatch_batch` 要消除的错法（§5 实绩 8 坐标 16 请求→2 请求）。
3. **单位错**：把半径当"度"传（如传 3 想表达 3″，实为 3°＝10800″）结果全错；坐标若传弧度/时分秒会值域越界或落到错天区。
4. **越界**：误转 `astro-catalog`（本 skill 才有 BEST 端点，转出去反而做不成）；反之把"匹配外部星表（非 BEST 12 表）"硬留本 skill 也越界。
5. **静默默认**：不问就取 `catalog=ps1`、`radius=3″`，可能答非所问；`id` 全缺虽能跑但结果只按下标回连、可追溯性差。
6. **忽略截断**：默认参数下不会截断，但改 `nearest_only=False` 时命中可能超 `max_rows`，须看 `status.truncated` 并用 `count`/`fetch_page` 续取，勿以为"就这么多"。
## 若需澄清，问什么
1.（必问）**坐标数据本身**：请把 1000 条坐标以 `ra,dec` 十进制度提供——直接粘贴，或给出文件路径与格式（CSV 两列？是否含 `id` 列？）。缺此无法发起任何调用。
2.（必问）**匹配目标星表**：要匹配哪一张？可选项 `ps1 / stripe82 / gaia_dr3_18 / jplus_dr3 / smss_dr4 / landolt / uss_dr1 / splus_dr4 / scr_galah / scr_lamost / xpsp / dr3xpcorr`（默认 `ps1`）。
3. **匹配半径**：多少角秒？默认 3″（常见选项 1″ / 3″ / 5″ / 10″；若用角分/度请说明，我按 1′=60″、1°=3600″ 换算）。
4. **是否只要最近邻**：默认"每输入只留最近一个匹配"（`nearest_only=True`），需要保留全部候选请说明。
5. **列投影与落盘**：是否只要部分列（如位置+若干波段星等）？结果要 csv / json / votable / fits 哪种、落到哪个目录？
