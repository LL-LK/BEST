## 「无值」编码**逐表不同**，跨表套用必错

同一站点对"这一格没有值"用了几种编码，**逐表不同**，判空前先在该表上实测取值分布：

| 编码 | 形态 | 出现在 |
|---|---|---|
| 空串 `""` | 点 | `gaia_dr3_18` 的 49,420 个空单元格**全是空串，零 `nan`** |
| `nan`（**字面字符串**） | token，`float()` 能转成功、后续 `==`/`<` 恒假 | `uss_dr1` 38.6% 单元格；`xpsp` 2.8%；`smss_dr4` 20% |
| `-999.0` | **点** | `ps1` 的 `*_err` 列；`xpsp` 216 次；`dr3xpcorr` 4 次 |
| `-1004.*` 一族 | **带**（3062 个互不相同的浮点） | `ps1` 测光列 |
| **`-32768`** | **点**（12 个 `*_flag` 列，9046 次，int16 下界） | **`uss_dr1`** —— 此前未登记 |

本仓判定阈值 `evals/_data/null_sentinel.yaml` 的 `threshold: -999.0`，
判定约定是 **`value <= threshold`（不是 `==` 某一个具体值）**，因此上面五种全部落在
阈值内（含 `-32768`）——**判空逻辑不需要因新形态而改，只需要把实测形态登记进去**。
`ps1` 哨兵带的完整判据见本文件「`ps1` 回包是两种记录混排」段与
`references/data-formats.md` §5c。

> **SSOT 归属**：形态清单与阈值以 `evals/_data/null_sentinel.yaml`（判分口径，
> E2/E3/E4 共用同一份字典）与 `references/data-formats.md` §5c.3 为准；本表是
> **逐表分布的引用切片**，新增形态先改那两处，本表只跟登记。

## `xpsp` / `scr_lamost` 的 `source_id` 重复是**扇出**，不是分层

- `xpsp` 的 `gaiaxp_photinfo_replenish_source_id`：1000 行只有 **38 个不同 id**，
  **一个 id 最多 27 行**；组内只有 `hipparcos_tycho_b`/`hp`/`v` 三组（每组 mag+err），
  每组 3 个取值 → 3×3×3=27 种组合**各出现一次**，27 行整行互不相同
  → **交叉匹配值的组合展开**。
- `scr_lamost_source_id`：137 行只有 **46 个 id**，一个 id 最多 **16 行**，
  组内连 `ra` 都差 1e-5 量级（`180.078518` vs `180.078541`）
  → **多条光谱解算记录**。

→ 这两张表用 `source_id` 当主键会撞车，须配行号或 `(ra, dec)` 量化键。
**这两种是"一颗星多行"的扇出，不是 `ps1` 那种两种记录类型首尾相接。**
⚠ 至于"别的表有没有 ps1 式分层"：**本轮 9 张有数据的表在各自代表天区、本轮样本量下
均未检出，但这只是未取得、不是已否证**（`ps1` 已证天区相关），不得当结论 ——
分寸见 `references/site-endpoints-and-interactions.md` §11.6。

`smss_dr4`（8 列）与 `uss_dr1`（96 列）实测**一行 `*_id` 列都没有**，
想按源标识取值只能靠 `(ra, dec)` 量化键。`gaia_dr3_18_solution_id` 是**恒定值**
（1000 行全同 `1636148068921376768`，是解的批次 id 不是源 id）—— 不能当标识列。

## `ps1` 回包是**两种记录混排**，用列前先判型（2026-10-05 实站实测）

**判型一行判据**：`ps1_source_id` 非空 ⇔ **对象记录**；为空 ⇔ **点源记录**。
两类行的**对象级列与点源级列互斥**，且**比例随天区变**：

| 列族 | 对象记录 | 点源记录 |
|---|---|---|
| `ps1_source_id` / `class_star` / `ruwe` / `parallax` | 有值（id 恒 19 位） | **整列空串** |
| `ps1_gpsf` / `rpsf` / `zpsf` / `ipsf` / `ypsf` | 有值但**混着 `nan`** | 有值，含 `-100x` 哨兵 |

同半径 600″ / 300 行三天区实测：`source_id` 非空行数 = (286.1, 15.7) **128**、
(180.0, 30.0) **0**、(10.68, 41.27) **0**。**换天区就换一种记录**，所以
"ps1 某列有没有值"这种话不加天区一律不成立。

- **主键会失效的两个条件**：① 点源记录整列为空 → 整列塌成一个值；② 对象记录内部
  也不保证唯一（快照 `live_ps1_ra359.5_dec0.0_r1800.0as` 的 431 个非空 id 去重后 430 个）。
  兜底：改用 `(ra, dec)` 量化键（`evals/groundtruth/canonical.py::id_keys_unique()`，
  E2 有 8 份 case 在用）。
- **「无值」编码的判空判据是阈值不是等值**：本仓阈值 `-999.0`，判定
  `value <= threshold`（**不是 `==` 某一个具体值** —— 上表五种形态全部落在阈值内，
  含空串/字面 `nan` 需显式单列判）。ps1 测光哨兵是**带**（`-1001.9`~`-1004.1`，
  3062 个互不相同的浮点），等值匹配一个都命中不了。本节「无值」有**五种**编码：
  空串 `""`、字面字符串 `nan`、数值哨兵**带**（`-1004.*`）与 `-999.0` 点、
  `-32768` 点（`uss_dr1`）—— 完整逐表分布见上表与
  `references/data-formats.md` §5c.3。
- **「该行存在」不等于「该行有测光」**：一行五波段全落在 -1001.9 ~ -1004.1 时，
  **只有位置列有效**，测光分析不可用 —— 换表或换波段，而不是把哨兵带进任何数值
  计算、平均或 SED。
- **哨兵是「带」不是「定点」**（2026-10-05 实测，ps1 @180,30 60″ 整页 174 行）：
  `ps1_gpsf` 148/174 行哨兵在 2 位小数上就分裂成 `-1004.07`(103) + `-1004.08`(45)，
  完整浮点散布 `-1004.0787842744421`~`-1004.0726439746845` ——
  **浮点精确相等只命中 1/174**，写死一个值会低估两个数量级。各波段带心还不同
  （g≈-1004.07 / r≈-1003.88 / i≈-1003.54 / z≈-1002.88 / y≈-1001.94），
  只能**按带**判（本仓阈值 -999.0，上沿 -1001.94 与最近合法值 16.20 之间）。
  ⚠ **服务端按 PSF 列比较时哨兵照样参与**：`less 16` 在 300″ 锥里回 3554 行 =
  真实值 + 约 3545 行哨兵，所以"暗于某极限"这类筛选会把"没测光"的源算进去。
- precise（`in` 约束）下载在 ps1 上恒 0 行（走 proximity 坐标上传），知识条目
  `L-precise-ps1-source-id-empty`；但**那条讲的是下载路径，不是这一列的全局属性**。
- 逐列形态与五种编码的完整证据：`references/data-formats.md` §5c / §5
  （**SSOT 在 references/**；本节只留「怎么判型、怎么判空」两条操作结论，
  数值与快照计数以 references 与 `evals/_data/null_sentinel.yaml` 为准）。

> **表单页 200 ≠ 查询有命中。** `GET /data/best/jplus_dr3/f` 与 `.../landolt/f`
> 均返回 HTTP 200 且有真实内容（jplus 34672 B、landolt 120062 B）—— 路由是活的、
> 表单页可取；这只证明**路由活**，**不证明该表在该天区有源**。判覆盖看 `getcount`
> 的 `total`，不看 `/f` 的状态码。

## 能力边界：BEST 是单历元静态表，不给时序也不给变星判定

- **BEST 发布的是单历元静态归算星表**（毫mag 级均一定标，约 2e9 星，200+ 波段）。
  它**没有时间序列**：一行里的 g/r/i/z/y 是**五个波段的五个数**，不是同一颗星的
  五个时刻，拿它画光变曲线、估周期或算振幅是**范畴错误**（不是"精度不够"）。
  要时序 → ZTF / ASAS-SN / Gaia 历元测光等时序巡天；本仓给不出，只能给该位置的
  静态多波段测光（带列名与误差）。
- **BEST 不产出变星判定，也无按 `source_id` 查的端点**（`/q` 走位置锥搜或
  proximity 批量坐标）。用户甩一个 Gaia `source_id` 问"是不是变星"时：先说能力
  边界 + 给判定路径，**不得**编一个 by-id 端点，**不得**给周期/振幅。
- **规模口径 ≠ 能力口径**："20 亿颗星"是**全集**口径，标准星子集口径是 2 亿+
  （`references/best-database-guide.md` 概述段），引用时必须带口径；拿规模数字
  推能力（"那能不能做全天长期光变监测"）是两个维度混用。
- **「未标记」永远不等于「已判定为否」**：变星标志为空/`NOT_AVAILABLE`、
  `has_epoch_photometry=False`、合成量 rms/chi2 看着正常，都只说明**没有可用的
  判定**，推不出"该星恒定"。恒定性的主张需要时序观测 + 明确的检视设计，静态表
  结构上给不了。**筛"恒定星清单"不能用空标志反选。**

## `stripe82` 的合成统计量：mmed 是中值，不是单次曝光

- **只发布合成统计量，不发布逐历元序列**。`rnobs` 是该波段合成量背后的观测次数，
  `rmmed` 是那 `rnobs` 次的**中值**合成星等 —— **不是某一次曝光的测量值**。要逐
  历元序列（各次星等 + 时刻）→ SDSS Stripe82 原始影像 / 时序库，本表取不到。
  同族三件套：`rmrms`（离散度）、`rmchi2`（合成拟合优度）、`rmsig`（离散度的不确定
  度）；u 波段另有自己的 `unobs/ummed/umrms/umchi2/umsig`，**按波段各自成立**。
- **`rmrms` 是"离散"，不是"误差"也不是"变化量"**：它同时含测量误差、定标残差与
  （可能的）固有变异，**不可分解**。观测次数相当时区分稳定性看**离散度**而不是
  次数 —— 次数不少而 rms 大一个量级的波段，单次异常对中值的影响仍显著（给更大
  误差或降权）。
- **`umchi2` / `rmchi2` 是诊断量不是分类量**：chi2 偏高可能来自定标残差、误差低估、
  背景混合等系统因素，**不能单凭 chi2 判变星**；chi2 低也不证明恒定。判变星仍需
  逐历元数据（见能力边界段）。
- **`*_h22` 与合成量是两个不同产物，不可互换**：`r_h22`/`u_h22` 是 **H22 视宁度改正
  星等**，`rmmed`/`ummed` 是中值合成星等。两者数值可以**极接近**（同源两列实测可差
  0.003 mag），但**接近是巧合不是同源** —— SED 拟合等场合必须同一口径，不得混用、
  取平均或同时塞进一条 SED。`_h22` 释义见本仓列登记（`CATALOG_MAG_COLUMNS`）。
  注意 **H22 视宁度改正 ≠ 消光改正 ≠ 零点改正**，三者别混谈。

## `gaia_dr3_18` 的列来源与身份边界：天体测量 / GSP-Phot / BEST 重定标

该表是"Gaia DR3 精测定标"表：**身份与天体测量量来自 Gaia，恒星参数来自 Gaia 的
恒星处理流水线，只有测光经 BEST 重定标**。说任何一列都要带上这层来源，不得笼统
写"BEST 测得"。

- **Gaia 天体测量层**（不是 BEST 的测量）：`parallax`/`parallax_error`、`ruwe`、
  `ipd_frac_multi_peak`、`astrometric_chi2_al`、`duplicated_source`。给距离**必须
  同时声明相对误差**（`parallax_error/parallax`；本仓留档快照里单源可到 0.26 量级）**
  与未做零点/选择效应改正；`ruwe` 与 `ipd_frac_multi_peak` 是**解质量诊断量**，数值正常
  只说明**没提示解异常**，不等于可以直接给高精度距离。
- **Gaia 恒星参数层**（不是 BEST 的测量）：`teff_gspphot` 来自 Gaia GSP-Phot，引用
  写"Gaia DR3 GSP-Phot（经 BEST 表发布）"。该列**只有部分行有值**，**覆盖范围不
  得凭空给区间**。
- **变星相关两列只表示"有没有可用判定"，不表示判定结果**：`phot_variable_flag` 是
  Gaia DR3 的**特定变星类型分类结果**，缺失时回 `NOT_AVAILABLE` —— 那是"未判定"
  不是"判定为非变星"；`has_epoch_photometry=False` 只说 Gaia 归档**未发布**该源的
  历元测光，不等于该源光度恒定。两列都不是 BEST 的结论。
- **身份匹配只到"候选"**：位置近（角距几角秒）**不等同于同一天体**。同一性要结合
  自行、分辨、`duplicated_source`、`ruwe` 与邻近源密度给**带限定的匹配置信**表述，
  不得直接断言"确认为同一颗星"。

## 量纲与零点：flux 不是 mag，本表不发布零点

- **流量与星等是两种量纲，不可直接相减或相除**。`phot_g_mean_flux`（Gaia 平均
  流量）与 `ps1_gpsf`（星等）相减**得不到颜色**：先要 flux→mag，而颜色还要求同一
  测光系统与同一零点 —— Gaia G 与 PS1 g 是两个系统。
- **BEST 的表不发布零点列**（列清单里没有 zeropoint / zero_point / mzp 这类列），
  因此**不得声称"BEST 给了零点"**。`mag = -2.5·log10(flux) + ZP` 里的 ZP **必须引
  官方发布值并注明版本/出处**；无出处**不给数值**。给不出就明说缺什么。
- `phot_g_mean_flux_over_error` 是**平均流量与其误差的比值**（`flux/flux_error`），
  由 Gaia 的平均量算出，**不等同于单次曝光的经典 SNR**；引用必须带限定（写
  "flux/flux_error 比值"而不是裸写"信噪比 = …"）。
- **跨表星等不能直接相减当时间变化**：两个值来自不同星表、不同归算与零点、不同
  孔径/PSF 口径。数值**极接近也不等于同源同时刻**（同源跨表吻合到 0.006 mag 量级
  是常态），更不等于可以当时间序列。跨表比较前先统一系统与零点
  （`references/photometric-systems.md` §2/§3），差异须逐项交代：定标零点、
  孔径/PSF 口径、天区处理，以及**本来就存在的归算噪声**。

## 列定义未登记时不得凭量级猜：标注待核并指路

- **列名没有登记定义就是"不知道"，而"不知道"是合法答案**：
  - `gaia_dr3_18_phot_g_mean_mag_y21` / `..._bp_mean_mag_y21`：`_y21` 后缀在本仓
    **无释义**。正确处置是标注"列定义待核"并指路（列元数据页 `/t/{table}` 或官方
    文档），**不得**猜它是某篇论文的重定标结果；核实前两列都**不当作"BEST 定标
    结果"**使用，也不得挑一个当答案。
  - `xpsp` 的 `jpas_j0430_j0430_xpsp` 等分波段列：仓内只登记了**列名与所属表单表**
    （xpsp 横跨 139 张表），**未声明量纲**。取值落在星等量级（18.09±0.41）**不足
    以断定它就是星等** —— 判定要有定义出处，不能靠量级猜。
- **通用判据**：回答任何列的**语义、量纲、覆盖范围**之前，先确认"本仓或官方是否
  登记了它的定义"。没登记 → 标注待核 + 指路 + **拒绝给值**；**更不得为不存在的列
  编覆盖范围**（例如给一张纯测光表编 Teff/logg 区间）。

## `class_star` 是按波段各自的形态分类，恒星 SED 别直接用 PSF 星等

- `*_class_star` 是**形态分类量**（源在图像上的 PSF / 扩展程度），不是星等也不是
  质量分。**接近 0 表示形态更像星系（扩展源）**；拿这种源的 PSF 星等做**恒星**
  SED 拟合不合适 —— 改用该波段的 total / 扩展源口径星等，或换源。
- **按波段各自测量**：同一行里 `u_class_star` 与 `j0378_class_star` 可以差一个量级，
  **不能拿一个波段的形态分类套到同一源的其他波段**。
- **`ps1` 密集天区的 `class_star` 整列为空**（点源记录按定义没有对象级列）——
  判形态前先确认该列在本天区**有没有值**；拿不到值不等于形态"正常"。

## `ps1` 成对列与 flags 位掩码：用有值的那一列，flag 含义查元数据页

- **成对出现的 `X` 与 `X_corr` 列用有值的那一列**：本数据里 `ps1_rpsf` 有值，而
  `ps1_rpsf_corr`（与 g/i/z 同族）**整列为空**。整列为空**不是"另一个口径的星等"，
  是没填** —— 不能因此否掉有值的 `rpsf`，也不能把空列当成可用的改正后星等。
- **给数必须带列名**（表 + 列 + 误差）：同一张表里 `rpsf` 与 `rpsf_corr` 是两个列，
  只报一个不带列名的数，读者无从分辨是哪个口径。
- **`_corr` 到底改正了什么须核实列定义后再声明** —— 不得臆断是消光改正 / 零点改正
  / 视宁度改正。
- **`*_flags` 是位掩码，不是可读的量**：`ps1_gflags/rflags/iflags/zflags/yflags` 各
  波段的位掩码**含义不同，且逐波段不一致是常态**（实测同一行 y 与 g/r/i/z 不同）。
  **各位含义必须查列元数据页 `/t/346`，不得臆断**；核实前标注"质量标志待核"并谨慎
  使用或降权 —— 既**不得**断言"数据损坏"，也**不得**断言"数据正常"。

## 「无记录」不等于「不存在」：0 行的成因与换查路径

- **0 行只证明一件事**：在这**张表、这个半径、这组约束**下没有记录。它**不证明**
  该位置没有天体，也不证明该星在某张表里不存在。成因至少四类，报数时逐类排查：
  ① **覆盖空洞 / 天区不重叠**（各表天区互不重叠，见上节代表坐标）；② **星等限**；
  ③ **列约束或 operation 拼错**（白名单外的值站点收下后返回空表，后果是"看起来
  天上没源"而不是"不过滤"）；④ **半径过小**（`landolt` 摊全天约 1 行 / 3.7 deg²，
  0.5° 锥期望命中仅 0.018 行，0 属统计正常）。
- **换查路径**（代价从低到高）：放宽半径 → 去掉列约束 → 换天区 → 换表 → 查其他
  巡天原始数据。**先换天区再判故障**：用赤道附近统一坐标探测会让大半表假 0。
- **结论必须带限定**（表 + 半径 + 约束），并区分"库内无记录"与"天体不存在"。站点
  异常与"该锥内真无源"在返回形态上**可能无法区分**时，如实说无法区分，不替站点
  下结论。跨表同理：**A 表查得到、B 表查不到，推不出 B 表没有这颗星**（覆盖、匹配
  半径、约束、表版本都可能不同），需换半径/换标识或直接查 B 表才能判断。
