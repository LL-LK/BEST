## 三、五条隔离保证

| # | 保证 | 机制 | 现状 |
|---|---|---|---|
| 1 | 盒内物理不含答案 | 只按白名单拷贝被测对象本体 + 自建题卷；标注/判分器/轨迹/历史跑批/注入剧本一律不拷 | 171 文件，审计 0 命中 |
| 2 | 历史跑批答案不进盒 | 指纹含 r1 答卷 `answer_text` 前 40 字（35 条）+ 标注答案 131 条 | 166 条指纹，0 命中 |
| 3 | 三箱互相隔离 | 每箱独立答案目录；盒内不出现箱号、沙箱根路径、`_answers` 字样 | 跨箱扫描 0 命中 |
| 4 | 答案面只有模型产出物 | `_answers/sbN/` 构建态强制清空；批次卡移到 `_batch/`，剥离源路径与来源分类 | 构建态 0 文件，负向反证有效 |
| 5 | **答案文件在跑批期不可读** | 对根下 8 项操作者资产 + 评测仓 3 处 + 2 份文档加 `deny Everyone (RD,X)` | 13 项全部实测拒读，反证通过 |

### 第 5 条的锁怎么用

锁**不搬文件**，就在原位加 ACL。工具在沙箱根之外（否则锁上自己就运行不了）：

```bash
cd "<USER_HOME>\E4-锁工具"
python plane_lock.py status      # 看锁态（实测读，不解析 icacls 文本）
python plane_lock.py unlock      # 跑批前：先解锁去构建/判分
python plane_lock.py lock        # 开跑前：上锁
python plane_lock.py verify      # 实证 + 写 LOCK-STATUS.md
```

为什么 deny 的是 `Everyone` 而不是某个"模型账号"：本机的 `CodexSandboxOffline/Online`
（组 SID 尾号 `-1004`）在 `<USER_HOME>` 与沙箱根上**没有任何授权**，连目录都进不去 ——
说明模型实际不是用这两个账号跑的。只 deny 模型账号、放行 user，等于锁了个不存在的门。
deny `Everyone` 的代价是**锁态下操作者自己也读不了**，所以判分前必须 `unlock`。

锁态反证（2026-10-21 实测）：锁态下读 `_index/题目索引.md` → `PermissionError`；
`unlock` 后同一文件读到 4227 字符且含处置列；再 `lock` 又拒读。

**能力边界**：这把锁保证「答案文件在跑批期不可读」，不保证「模型一定不知道答案」。
后者的第一道防线是**模型侧不挂载文件读取工具**，锁是第二道。
模型若拿到管理员等价能力，可以改回 ACL —— 那已经超出文件权限能管的范围。

## 五、重建 / 审计 / 验收

> **锁态下这些命令全部跑不了**（`_builder`、`_验收` 都被 deny）——先 `plane_lock.py unlock`。

```bash
python _builder/build_sandboxes.py --dry-run     # 看计划
python _builder/build_sandboxes.py --apply       # 三箱一起重建（**整目录删掉 _answers/sbN**，先备份答卷）
python _builder/audit_leak.py                    # 七层审计，命中即 exit 1
python _builder/verify_all.py                    # 四部验收 A/B/C/D
```

审计七层：结构黑名单 / 答案指纹（含历史答卷）/ 路径泄漏 / 跨箱引用 / **答案面构建态为空** /
**题面逐字校验** / **批次卡无溯源字段**。

- 题面逐字校验最强：每个 `per_item/*.txt` 必须**恰好等于**净化后的用户原话，多一个字都判红。
- 答案面那层不再豁免任何文件（旧版曾允许 `batch-manifest.json`，等于给自己留口子：
  一张带源仓库绝对路径与题面来源分类的卡在 `_answers/` 里躺了两轮都没被发现）。

> **重建会整目录删除 `_answers/sbN/`**（不只是 run 目录）；**只重建一箱会破坏一致性**，要重建就三箱一起（脚本末尾自检清单哈希）。
>
> 完整节奏：`unlock` → 重建/审计/验收 → 跑批 → `lock` → 判分前再 `unlock`。
> 锁态是"跑批态"，不是"常驻态"。

## 六、已知限制

1. `src/` 去标识只动注释与文档串，不改代码逻辑；改动行号记在清单里。
2. `RB-20` 剥掉括号后变成“查这颗星。”——它现在考的是**指代缺失**（C 级），不再是“锥内多源”。处置级别不变，但失效原因变了，报告里要按新题面解读。
3. 题面净化后，`RB-19` 的难度实质上升（模型必须自己调 `resolve_name` 才发现 `-1000` 哨兵）。这是**正确**的考法，也是它与 r1 不可比的主因。
4. ACL 默认不启用（`--acl` 可选）：只挡误改误删，挡不住同用户读取，且会让重建多一步解封。
