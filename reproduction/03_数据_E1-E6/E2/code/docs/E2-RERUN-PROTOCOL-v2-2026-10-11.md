# E2 确认性重跑协议 v2（2026-10-11）

## 决策摘要

E2 本轮固定 **21 个场景 × 3 次 = 63 个逻辑重复**。三项覆盖缺口通过**置换现有场景**修复，不增加场景数：密集场、60,000 行分页/截断压力、NULL 与数值 ZERO 孪生对照。E2 使用冻结输入和离线真实客户端解析链路；在线探索抓取不混入确认性分析。既有 `live` 报告保留为历史在线不变量检查，不能充作本轮逐行复现结果。

本协议在代码、场景、Gold 与快照哈希冻结后才开始确认性运行。任何评分规则、场景输入、Gold 或 SUT 代码在开跑后发生变化，都必须换新 `run_id` 并重跑完整 63 次。失败、异常与额外尝试保留为独立 attempt；不覆盖、不择优挑选。

## 研究问题和可解释边界

研究问题：给定同一份带字节级清单的冻结服务响应，BEST 查询客户端能否按场景契约解析出正确行集、字段语义、分页/截断信封与错误状态？

v2 的确认性通道是**冻结快照回放**：被测对象仍走 `BestClient` 和正式 CSV/分页解析路径，传输层只从本地冻结响应提供字节。它支持 P/R、字段和分页真值逐项比对，也消除网络天气对重复性的混杂。结果不能外推为实时站点可用性；在线连通性属于独立 live gate。

合成压力夹具只支持“解析与分页实现对给定合法协议负载的行为”结论，不能声称 BEST 站点曾真实返回 60,000 行。密集场夹具必须披露来源、视场半径和源密度；如果只有合成坐标，则只能报告 synthetic dense-field stress，不能称作真实球状星团验证。

## 固定矩阵（不扩单元）

| 槽位 | 本轮覆盖 | 场景要求 | 判据重点 |
|---|---|---|---|
| 原密集场槽 | Dense field | 场景清单声明实测/合成来源、中心、半径、行数和密度；包含高近邻度/近简并匹配 | 近邻匹配、距离排序、重复/歧义、主键唯一 |
| 原超大查询槽 | 60,000 行 | 冻结 count=60,000、60 页 × 1,000 行、全量行哈希、max_rows 截断边界及末页/续页证据 | 逐页并集、无重无漏、总数/返回数/truncated 三元组 |
| 原缺失值槽 | NULL vs ZERO twins | 同字段、同类型上下文中至少有明确数值 `0.0` 与空值；保留 CSV 原始字节并提供独立 oracle | 0.0 不得转 null；NULL 不得转 0；哨兵仍单独分类 |
| 其余 18 槽 | 原有 18 个语义场景 | 维持既有 query 与场景角色；不因新数据扩大单元数 | M1–M7 可判项按 frozen lane 计分；不适用项记 N/A |

场景 manifest 必须给每个槽位唯一 `case_id`、协议版本、替换关系、输入/输出资产 SHA-256、Gold SHA-256、预期状态与所覆盖指标。确认性运行的 `n_cases` 必须等于 21，`planned_repeats` 必须等于 63；否则不得开跑或判通过。

## Gold 与评分门禁

1. Gold 由 `evals/groundtruth/gold/` 独立 oracle 生成；运行 `guard_no_src_imports.py`，不得导入 `src.*` 或被测评分器算法。
2. 每个快照核验 manifest 中的全部文件哈希，独立重算 `rows_full` 行数、每页行数、主键唯一性、页边界和 count；60,000 行场景须有 60,000 个不同主键和 60 个完整页。
3. NULL/ZERO 双生至少要在 oracle 清单中记录原始 CSV 单元格、解析后类型/值和语义标签，并用正反例证明评测器不是“全判 null”或“全判 value”。
4. Dense 场必须有预注册的密度定义和来源分级。没有可核对的外部权威/实抓目录时，不把合成夹具写成真实观测。
5. 沿用 7 指标的原权重和反证夹具；逐行 P/R 只在冻结 lane 计算。任何无证据指标记 N/A，不能补 1.0。Gold 来源与专家审核状态单独披露；自动生成不等于专家签字。

## 执行顺序和停止规则

**阶段 A：预注册冻结** — 确认 21 个场景及 3 项置换；逐一校验快照完整性；生成 Gold；核验独立性；冻结 SUT/判定器/manifest 哈希；输出预注册 JSON 和 SHA-256。任何硬性校验失败则停止，不进入 63 次运行。

**阶段 B：端到端回归** — 运行反证夹具全捕获、正向黄金路径、解析器/分页契约、Gold 独立性测试。保留 JUnit、stdout/stderr、环境、依赖锁与测试时间；此阶段不计为 63 个确认性重复。

**阶段 C：确认性 E2** — 对 manifest 排序后的 21 场景逐一执行 3 次。每一轮都新建客户端和传输会话；记录 `run_id/case_id/repeat_index/attempt_id`、查询表单（脱敏）、请求方法/本地快照路由/页号、响应状态和字节 SHA-256、规范化输出、metric 逐项结果、错误与耗时。快照响应原始字节已包含在包内，不再复制大量重复 payload。

**停止与重跑** — 本地可复现性故障、快照哈希错误、未知 Gold、未声明场景或 SUT 指纹变化时停止整批，封存已完成部分并用新 `run_id` 从头开始。离线通道不存在网络错误豁免；崩溃后不把部分批次合并成完整批。单次 SUT 判错仍保留在原批，不因结果不佳而重跑或替换。

## 报告口径

确认性结果同时给出 21 项逐场景 P/R、M1–M7 分数/分母/N/A、重复间输出哈希一致率、截断和 NULL/ZERO 逐格例证、metascore、独立 Gold 核验状态、协议/代码/数据哈希。结果解释限定为冻结 fixtures 下的客户端行为。若专家双盲复核尚未完成，论文中不得表述 Gold 已获专家验证；若 dense field 为合成，则该轴只能作为压力测试。

E5 仍按其独立协议处理：本轮不启动 E5 确认性矩阵，不把 E2 的夹具或 63 次重复计入 E5。E5 的沙箱桥接、逐格真实模型 trace、隔离和 scorer 门禁须单独通过后，才允许其原预算的 2,016 个逻辑单元。
